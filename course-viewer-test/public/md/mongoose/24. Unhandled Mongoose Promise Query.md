# Unhandled Mongoose Promise Query

## Question
What will happen if you do not handle the Promise returned by a Mongoose query?

## Answer
If you don't handle the Promise returned by a Mongoose query:

1. **The query executes** - but you can't access the results
2. **Errors are silently ignored** - no error handling occurs
3. **Unhandled Promise rejection** - Node.js will warn about unhandled rejections
4. **Application may crash** - in strict mode or future Node versions

## Examples

```javascript
// BAD - Promise not handled
User.findOne({ email: 'test@example.com' });
// Query runs but results are lost, errors ignored

// GOOD - Handle with await
const user = await User.findOne({ email: 'test@example.com' });

// GOOD - Handle with .then()
User.findOne({ email: 'test@example.com' })
  .then(user => console.log(user))
  .catch(err => console.error(err));
```

## Result
The query executes but you lose the data and can't catch errors, leading to unpredictable behavior and potential crashes.


## Thenable vs Promise - What Gets Returned?

This refers to **any thenable** (Mongoose query object), not specifically one obtained via `exec()`.

### Key Point

Mongoose queries return a **thenable** (query object with `.then()` method) by default. You don't need to call `exec()` to get a Promise-like object.

```javascript
// These are all thenables/promises:
User.findOne({ email: 'test@example.com' })        // thenable
User.findOne({ email: 'test@example.com' }).exec() // actual Promise
```

### The Difference

- **Without `exec()`**: Returns a Mongoose Query object (thenable, but not a true Promise)
- **With `exec()`**: Returns a true ES6 Promise

Both need to be handled with `await` or `.then()/.catch()` to avoid unhandled rejections.

### Why It Matters

```javascript
// Both of these are unhandled and problematic:
User.findOne({ email: 'test@example.com' });        // unhandled thenable
User.findOne({ email: 'test@example.com' }).exec(); // unhandled Promise
```

The warning applies to any Mongoose query that returns a thenable, whether or not you explicitly call `exec()`.


## Why the Question Says "Promise"

The question uses "Promise" rather than "Mongoose query object" because:

- **Common usage** - Developers typically refer to Mongoose queries as Promises
- **Practical behavior** - They're used with `await` or `.then()` like Promises
- **Accessibility** - Simpler and more intuitive for learners
- **Technical accuracy comes later** - The distinction between thenable and true Promise is explained in detail above

This approach gives learners the practical understanding first (treat it like a Promise), then provides the deeper technical nuance (it's actually a thenable until you call `exec()`).
