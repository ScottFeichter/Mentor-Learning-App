# Error Handling with Prisma

## Prisma Error Types

Prisma provides specific error codes for different scenarios.

## Common Error Codes

| Code | Meaning | HTTP Response |
|---|---|---|
| `P2002` | Unique constraint violation (duplicate email) | 400 Bad Request |
| `P2025` | Record not found | 404 Not Found |
| `P2003` | Foreign key constraint violation | 400 Bad Request |
| `P2014` | Invalid relation | 400 Bad Request |

## Important Note About P2025

The `P2025` error only occurs for the following operations:

- `update()`
- `delete()`
- `findUniqueOrThrow()`
- `findFirstOrThrow()`

For other operations:

- `findMany()` - returns an empty array if no entry is found
- `findUnique()` - returns `null` if no entry is found

## Implementing Error Handling

```javascript
const createUser = async (req, res) => {
  try {
    const user = await prisma.user.create({
      data: req.body,
    });
    res.status(201).json(user);
  } catch (error) {
    if (error.code === 'P2002') {
      return res.status(400).json({ error: 'A user with that email already exists' });
    }
    if (error.code === 'P2003') {
      return res.status(400).json({ error: 'Foreign key constraint failed' });
    }
    res.status(500).json({ error: 'Internal server error' });
  }
};

const updateUser = async (req, res) => {
  try {
    const user = await prisma.user.update({
      where: { id: parseInt(req.params.id) },
      data: req.body,
    });
    res.json(user);
  } catch (error) {
    if (error.code === 'P2025') {
      return res.status(404).json({ error: 'User not found' });
    }
    res.status(500).json({ error: 'Internal server error' });
  }
};
```

## Database Connection Errors

Prisma throws a `PrismaClientInitializationError` when it cannot connect to the database. This commonly occurs when the database server isn't running.

```javascript
const { PrismaClient } = require('@prisma/client');
const prisma = new PrismaClient();

async function connectDB() {
  try {
    await prisma.$connect();
    console.log('Connected to database');
  } catch (error) {
    if (error.name === 'PrismaClientInitializationError') {
      console.error('Cannot connect to database. Is the server running?');
    }
    process.exit(1);
  }
}
```

## Best Practices

- Always handle Prisma-specific error codes in your controllers
- Return appropriate HTTP status codes based on the error type
- Log errors for debugging but don't expose internal details to clients
- Handle connection errors at application startup
