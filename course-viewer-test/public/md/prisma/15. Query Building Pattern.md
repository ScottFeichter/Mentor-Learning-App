# Query Building Pattern

## What Is This Technique?

The query building pattern in Prisma involves constructing a query options object dynamically before passing it to a Prisma method. This allows you to conditionally add filters, sorting, and pagination based on user input.

## The Pattern

```javascript
// Step 1: Start with a base where clause
const where = { userId: req.user.id };

// Step 2: Conditionally add filters
if (req.query.status) {
  where.status = req.query.status;
}

if (req.query.search) {
  where.title = { contains: req.query.search, mode: 'insensitive' };
}

// Step 3: Execute the query with all conditions
const tasks = await prisma.task.findMany({ where });
```

## Why This Works

Unlike Mongoose where you chain methods on a query object, Prisma takes a single options object. You build that object dynamically before passing it in.

```javascript
// Prisma queries are NOT chainable like Mongoose
// ❌ This doesn't work:
// prisma.user.findMany().where({...}).sort({...})

// ✅ Instead, build the options object:
const options = {
  where: {},
  orderBy: {},
  take: 10,
  skip: 0
};
const users = await prisma.user.findMany(options);
```

## Complete Example

```javascript
const getProducts = async (req, res) => {
  const { category, search, sort, fields, page, limit } = req.query;

  // Step 1: Build where clause
  const where = {};

  if (category) {
    where.category = category;
  }

  if (search) {
    where.name = { contains: search, mode: 'insensitive' };
  }

  // Step 2: Build orderBy
  let orderBy = { createdAt: 'desc' };
  if (sort) {
    const [field, direction] = sort.startsWith('-')
      ? [sort.slice(1), 'desc']
      : [sort, 'asc'];
    orderBy = { [field]: direction };
  }

  // Step 3: Build select (if specific fields requested)
  let select = undefined;
  if (fields) {
    select = {};
    fields.split(',').forEach(f => { select[f.trim()] = true; });
  }

  // Step 4: Pagination
  const pageNum = parseInt(page) || 1;
  const limitNum = parseInt(limit) || 10;
  const skip = (pageNum - 1) * limitNum;

  // Step 5: Execute
  const products = await prisma.product.findMany({
    where,
    select,
    orderBy,
    skip,
    take: limitNum
  });

  const total = await prisma.product.count({ where });

  res.json({
    products,
    pagination: {
      page: pageNum,
      limit: limitNum,
      total,
      pages: Math.ceil(total / limitNum)
    }
  });
};
```

## Handling Date Ranges

```javascript
const where = {};

if (req.query.min_date || req.query.max_date) {
  where.createdAt = {};
  if (req.query.min_date) {
    where.createdAt.gte = new Date(req.query.min_date);
  }
  if (req.query.max_date) {
    where.createdAt.lte = new Date(req.query.max_date);
  }
}
```

## Handling OR Conditions

```javascript
const where = {};

if (req.query.search) {
  where.OR = [
    { title: { contains: req.query.search, mode: 'insensitive' } },
    { description: { contains: req.query.search, mode: 'insensitive' } }
  ];
}
```

## Helper Functions

```javascript
// Reusable sort builder
const buildOrderBy = (sortParam) => {
  if (!sortParam) return { createdAt: 'desc' };

  const validFields = ['name', 'price', 'createdAt', 'priority'];
  const field = sortParam.startsWith('-') ? sortParam.slice(1) : sortParam;
  const direction = sortParam.startsWith('-') ? 'desc' : 'asc';

  if (validFields.includes(field)) {
    return { [field]: direction };
  }
  return { createdAt: 'desc' };
};

// Reusable pagination builder
const buildPagination = (query) => {
  const page = parseInt(query.page) || 1;
  const limit = parseInt(query.limit) || 10;
  return { skip: (page - 1) * limit, take: limit, page, limit };
};
```

## Key Concepts

- Prisma queries take a **single options object** (not method chaining)
- Build the `where`, `orderBy`, `select`, `skip`, `take` properties dynamically
- Only add properties when the corresponding query parameter exists
- Always validate and whitelist sort fields to prevent errors
- Use a separate `count()` query for pagination metadata
