# Neon

## What Is Neon?

**Neon** is a serverless PostgreSQL hosting platform. It provides fully managed PostgreSQL databases with features designed for modern development workflows like branching, autoscaling, and a generous free tier.

## Key Features

- **Serverless** — scales to zero when not in use, scales up on demand
- **Branching** — create database branches (like git branches) for development/testing
- **Free tier** — generous limits for development and small projects
- **Instant provisioning** — database ready in seconds
- **Auto-suspend** — pauses after inactivity to save resources
- **Connection pooling** — built-in PgBouncer

## Setting Up Neon with Prisma

### 1. Create a Neon Account

Sign up at [neon.tech](https://neon.tech) and create a new project.

### 2. Get Your Connection String

From the Neon dashboard, copy the connection string:

```bash
DATABASE_URL="postgresql://user:pass@ep-cool-name-123456.us-east-2.aws.neon.tech/neondb?sslmode=require"
```

### 3. Configure Prisma

```prisma
// schema.prisma
datasource db {
  provider  = "postgresql"
  url       = env("DATABASE_URL")
  directUrl = env("DIRECT_URL")
}
```

```bash
# .env
DATABASE_URL="postgresql://user:pass@ep-cool-name-123456.us-east-2.aws.neon.tech/neondb?sslmode=require"
DIRECT_URL="postgresql://user:pass@ep-cool-name-123456.us-east-2.aws.neon.tech/neondb?sslmode=require"
```

### 4. Run Migrations

```bash
npx prisma migrate dev --name init
```

## Neon Branching

Create isolated database copies for development:

```bash
# In Neon dashboard or CLI:
# Create a branch from main for a feature
# Each branch has its own connection string
# Merge or delete when done
```

Use cases:
- Preview environments (one branch per PR)
- Testing migrations before applying to production
- Development without affecting shared data

## Free Tier Limits

- 0.5 GB storage
- 1 project
- 10 branches
- Compute auto-suspends after 5 minutes of inactivity
- 191 compute hours per month

## Connection Pooling with Neon

Neon provides pooled and direct connection endpoints:

```bash
# Pooled (for application queries) — port 5432
DATABASE_URL="postgresql://user:pass@ep-cool-name-123456.us-east-2.aws.neon.tech/neondb?sslmode=require"

# Direct (for migrations) — same URL works for both with Neon
DIRECT_URL="postgresql://user:pass@ep-cool-name-123456.us-east-2.aws.neon.tech/neondb?sslmode=require"
```

## When to Use Neon

- Development and prototyping (free tier)
- Serverless applications (scales to zero)
- Projects needing database branching
- When you want managed PostgreSQL without infrastructure overhead
- Small to medium production applications
