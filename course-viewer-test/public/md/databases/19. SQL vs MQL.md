# SQL vs MQL

## Overview

| Aspect | SQL | MQL |
|---|---|---|
| Full Name | Structured Query Language | MongoDB Query Language |
| Used With | Relational databases (PostgreSQL, MySQL, SQLite) | MongoDB (document database) |
| Data Model | Tables with rows and columns | Collections with documents |
| Format | Text-based statements | JavaScript method calls with JSON objects |
| Schema | Fixed schema (defined upfront) | Flexible schema (documents can vary) |

## CRUD Comparison

### Create

```sql
-- SQL
INSERT INTO users (name, email, age) VALUES ('John', 'john@example.com', 25);
```

```javascript
// MQL
db.users.insertOne({ name: "John", email: "john@example.com", age: 25 })
```

### Read

```sql
-- SQL
SELECT name, email FROM users WHERE age > 21;
```

```javascript
// MQL
db.users.find({ age: { $gt: 21 } }, { name: 1, email: 1 })
```

### Update

```sql
-- SQL
UPDATE users SET email = 'new@example.com' WHERE id = 1;
```

```javascript
// MQL
db.users.updateOne({ _id: ObjectId("...") }, { $set: { email: "new@example.com" } })
```

### Delete

```sql
-- SQL
DELETE FROM users WHERE id = 1;
```

```javascript
// MQL
db.users.deleteOne({ _id: ObjectId("...") })
```

## Filtering Comparison

| SQL | MQL |
|---|---|
| `WHERE age > 18` | `{ age: { $gt: 18 } }` |
| `WHERE age >= 18` | `{ age: { $gte: 18 } }` |
| `WHERE age < 65` | `{ age: { $lt: 65 } }` |
| `WHERE age != 25` | `{ age: { $ne: 25 } }` |
| `WHERE name = 'John'` | `{ name: "John" }` |
| `WHERE age IN (18, 21, 25)` | `{ age: { $in: [18, 21, 25] } }` |
| `WHERE name LIKE '%john%'` | `{ name: /john/i }` |
| `WHERE email IS NOT NULL` | `{ email: { $exists: true, $ne: null } }` |

## Logical Operators

| SQL | MQL |
|---|---|
| `WHERE age > 18 AND status = 'active'` | `{ age: { $gt: 18 }, status: "active" }` |
| `WHERE age < 18 OR status = 'inactive'` | `{ $or: [{ age: { $lt: 18 } }, { status: "inactive" }] }` |
| `WHERE NOT (age > 65)` | `{ age: { $not: { $gt: 65 } } }` |

## Sorting

```sql
-- SQL
SELECT * FROM users ORDER BY name ASC, age DESC;
```

```javascript
// MQL
db.users.find().sort({ name: 1, age: -1 })
```

| SQL | MQL |
|---|---|
| `ASC` | `1` |
| `DESC` | `-1` |

## Pagination

```sql
-- SQL
SELECT * FROM users ORDER BY name LIMIT 10 OFFSET 20;
```

```javascript
// MQL
db.users.find().sort({ name: 1 }).skip(20).limit(10)
```

## Aggregation

```sql
-- SQL
SELECT status, COUNT(*) as count
FROM users
GROUP BY status
HAVING count > 5
ORDER BY count DESC;
```

```javascript
// MQL
db.users.aggregate([
  { $group: { _id: "$status", count: { $sum: 1 } } },
  { $match: { count: { $gt: 5 } } },
  { $sort: { count: -1 } }
])
```

## Joins vs Lookup

```sql
-- SQL
SELECT users.name, orders.product
FROM users
JOIN orders ON users.id = orders.user_id;
```

```javascript
// MQL
db.users.aggregate([
  {
    $lookup: {
      from: "orders",
      localField: "_id",
      foreignField: "user_id",
      as: "orders"
    }
  }
])
```

## Schema Definition

```sql
-- SQL: Schema defined upfront
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(255) UNIQUE,
  age INTEGER CHECK (age >= 0)
);
```

```javascript
// MQL: Schema is optional (validation rules)
db.createCollection("users", {
  validator: {
    $jsonSchema: {
      bsonType: "object",
      required: ["name", "email"],
      properties: {
        name: { bsonType: "string" },
        email: { bsonType: "string" },
        age: { bsonType: "int", minimum: 0 }
      }
    }
  }
})
```

## Terminology Mapping

| SQL Term | MQL Term |
|---|---|
| Database | Database |
| Table | Collection |
| Row | Document |
| Column | Field |
| Primary Key | `_id` |
| Index | Index |
| JOIN | `$lookup` |
| GROUP BY | `$group` |
| WHERE | Query filter |
| HAVING | `$match` (after `$group`) |

## Key Differences

- **SQL is declarative** — you say *what* you want. **MQL is imperative** — you call methods.
- **SQL requires a fixed schema** — all rows have the same columns. **MQL is flexible** — documents in the same collection can have different fields.
- **SQL uses JOINs natively** — relationships are first-class. **MQL uses `$lookup`** — or more commonly, embeds related data in the same document.
- **SQL separates data into normalized tables**. **MQL often denormalizes** — storing related data together for faster reads.
- **SQL has a universal standard** (ANSI SQL). **MQL is MongoDB-specific** — though the concepts transfer to other document databases.
