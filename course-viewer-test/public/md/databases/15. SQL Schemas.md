# Schemas

A **schema** is a blueprint or structure that defines how data should be organized, formatted, and validated. It acts as a contract that specifies:

- What fields/properties are required or optional
- Data types for each field (string, number, boolean, etc.)
- Validation rules and constraints
- Relationships between different data elements

## Common Types

- **Database Schema**: Defines table structure, columns, and relationships
- **JSON Schema**: Validates JSON data structure and content
- **API Schema**: Describes request/response formats for web services
- **XML Schema**: Defines valid XML document structure

## Benefits

- **Data Consistency**: Ensures all data follows the same format
- **Validation**: Catches errors before data is processed or stored
- **Documentation**: Serves as clear specification for developers
- **Type Safety**: Prevents runtime errors from incorrect data types

## Example

```json
{
  "type": "object",
  "properties": {
    "name": { "type": "string", "minLength": 1 },
    "age": { "type": "integer", "minimum": 0 },
    "email": { "type": "string", "format": "email" }
  },
  "required": ["name", "email"]
}
```
