## Migration Files Are Ordered

Migrations run in sequence, typically named with timestamps:

```
20240101_001_create_users_table.js
20240102_002_add_age_to_users.js
20240115_003_create_orders_table.js
```

The database tracks which migrations have already been applied so it never runs the same one twice.

## Common Migration Operations

- Create a table
- Drop a table
- Add a column
- Remove a column
- Rename a column
- Change a column's data type
- Add an index
- Add a constraint (unique, foreign key)

## Migrations vs Seeding

- **Migrations** - change the database structure (schema)
- **Seeding** - populate the database with initial or test data

## Key Takeaway

Migrations give you a reliable, repeatable, and reversible way to evolve your database structure over time without manually running SQL commands or losing track of changes.
