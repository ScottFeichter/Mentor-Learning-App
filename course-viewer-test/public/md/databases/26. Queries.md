# Queries

## What Is a Query?

A **query** is any command or request you send to a database. While "query" often implies reading data, it broadly refers to any SQL statement - including inserts, updates, and deletes.

## Types of Queries

### Read Queries
```sql
SELECT * FROM users WHERE age > 21;
```

### Write Queries
```sql
INSERT INTO users (name, email) VALUES ('John', 'john@example.com');
UPDATE users SET name = 'Jane' WHERE id = 1;
DELETE FROM users WHERE id = 1;
```

### Structure Queries
```sql
CREATE TABLE products (id INTEGER PRIMARY KEY, name TEXT);
ALTER TABLE users ADD COLUMN phone TEXT;
DROP TABLE old_data;
```

## Query Building in Node.js

### Raw SQL
```javascript
const result = await pool.query('SELECT * FROM users WHERE id = $1', [userId]);
```

### With an ORM (Sequelize)
```javascript
const user = await User.findOne({ where: { id: userId } });
```

### With a Query Builder (Knex)
```javascript
const users = await knex('users').where('age', '>', 21).orderBy('name');
```

## Parameterized Queries (Security)

Never insert user input directly into a query string:

```javascript
// BAD - SQL injection vulnerability
const result = await pool.query(`SELECT * FROM users WHERE name = '${userInput}'`);

// GOOD - parameterized query
const result = await pool.query('SELECT * FROM users WHERE name = $1', [userInput]);
```

Parameterized queries prevent SQL injection attacks by treating user input as data, not executable code.

## Query Performance

Queries can be slow if:
- Scanning millions of rows without an index
- Joining many tables at once
- Selecting more data than needed (`SELECT *` vs specific columns)
- Missing WHERE clauses on large tables

## Key Takeaway

A query is how you communicate with a database. Writing safe, efficient queries is a core skill for backend development.
