# NoSQL Relationships

## What Are Relationships in MongoDB?

A **relationship** in MongoDB is a connection between documents, either within the same collection or across collections. Unlike SQL where relationships always use foreign keys and JOINs, MongoDB offers two primary strategies: **embedding** and **referencing**.

## Two Strategies

### Embedding (Denormalization)

Store related data **inside** the same document. No need for a separate collection or lookup.

```javascript
// User with embedded address (one-to-one)
{
  _id: ObjectId("aaa"),
  name: "John",
  address: {
    street: "123 Main St",
    city: "Springfield",
    state: "IL"
  }
}

// User with embedded orders (one-to-many)
{
  _id: ObjectId("aaa"),
  name: "John",
  orders: [
    { product: "Widget", total: 29.99 },
    { product: "Gadget", total: 49.99 }
  ]
}
```

### Referencing (Normalization)

Store related data in **separate collections** and link them with `_id` references.

```javascript
// Users collection
{ _id: ObjectId("aaa"), name: "John" }

// Orders collection
{ _id: ObjectId("bbb"), user_id: ObjectId("aaa"), product: "Widget", total: 29.99 }
{ _id: ObjectId("ccc"), user_id: ObjectId("aaa"), product: "Gadget", total: 49.99 }
```

## Types of Relationships

### One-to-One

One document relates to exactly one other piece of data.

**Embedded (preferred):**
```javascript
{
  _id: ObjectId("aaa"),
  name: "John",
  profile: { bio: "Developer", avatar: "john.png" }
}
```

**Referenced:**
```javascript
// Users collection
{ _id: ObjectId("aaa"), name: "John" }

// Profiles collection
{ _id: ObjectId("bbb"), user_id: ObjectId("aaa"), bio: "Developer" }
```

### One-to-Many

One document relates to many other documents.

**Embedded (when the "many" side is small and accessed together):**
```javascript
{
  _id: ObjectId("aaa"),
  title: "Blog Post",
  comments: [
    { author: "Sarah", text: "Great post!" },
    { author: "Mike", text: "Thanks for sharing" }
  ]
}
```

**Referenced (when the "many" side is large or accessed independently):**
```javascript
// Posts collection
{ _id: ObjectId("aaa"), title: "Blog Post" }

// Comments collection
{ _id: ObjectId("bbb"), post_id: ObjectId("aaa"), author: "Sarah", text: "Great post!" }
{ _id: ObjectId("ccc"), post_id: ObjectId("aaa"), author: "Mike", text: "Thanks for sharing" }
```

### Many-to-Many

Many documents relate to many other documents. Use **arrays of references**.

```javascript
// Students collection
{ _id: ObjectId("s1"), name: "John", course_ids: [ObjectId("c1"), ObjectId("c2")] }
{ _id: ObjectId("s2"), name: "Sarah", course_ids: [ObjectId("c1")] }

// Courses collection
{ _id: ObjectId("c1"), title: "Math", student_ids: [ObjectId("s1"), ObjectId("s2")] }
{ _id: ObjectId("c2"), title: "Science", student_ids: [ObjectId("s1")] }
```

Or use a junction collection (like SQL):
```javascript
// Enrollments collection
{ student_id: ObjectId("s1"), course_id: ObjectId("c1") }
{ student_id: ObjectId("s1"), course_id: ObjectId("c2") }
{ student_id: ObjectId("s2"), course_id: ObjectId("c1") }
```

## When to Embed vs Reference

| Embed When | Reference When |
|---|---|
| Data is always accessed together | Data is accessed independently |
| The "many" side is small (< ~100) | The "many" side is large or unbounded |
| Data doesn't change often | Data changes frequently |
| You need fast reads | You need to avoid data duplication |
| One-to-one or one-to-few | One-to-many or many-to-many |

## Querying Relationships

### Embedded — direct access:
```javascript
// Find users in Springfield
db.users.find({ "address.city": "Springfield" })
```

### Referenced — use $lookup (aggregation):
```javascript
// Get users with their orders
db.users.aggregate([
  {
    $lookup: {
      from: "orders",
      localField: "_id",
      foreignField: "user_id",
      as: "orders"
    }
  }
])
```

### Referenced — with Mongoose populate:
```javascript
const user = await User.findById(id).populate('orders')
```

## Key Differences from SQL Relationships

| SQL | MongoDB |
|---|---|
| Always uses separate tables | Can embed or reference |
| JOINs are native and fast | $lookup is available but embedding is often preferred |
| Foreign keys enforced | References not enforced by database |
| Normalized by default | Denormalized (embedded) is common |
| Junction tables for many-to-many | Arrays of references or junction collections |
