# NoSQL Keys

## What Is a Key in MongoDB?

A **key** in MongoDB is a field (or set of fields) in a document that uniquely identifies it or establishes a connection to another document.

Keys in MongoDB serve similar purposes to relational databases but work differently due to the document model.

## Types of Keys

### _id (Primary Key)

Every document automatically gets an `_id` field that **uniquely identifies it** within a collection. This is MongoDB's primary key.

- Automatically generated as an ObjectId if not provided
- Must be unique within the collection
- Cannot be changed after insertion
- Automatically indexed

```javascript
// Auto-generated _id
db.users.insertOne({ name: "John", email: "john@example.com" })
// Result: { _id: ObjectId("507f1f77bcf86cd799439011"), name: "John", ... }

// Custom _id
db.users.insertOne({ _id: "user_001", name: "John", email: "john@example.com" })
```

### ObjectId

The default type for `_id` fields. A 12-byte value containing:

- 4 bytes: timestamp (when it was created)
- 5 bytes: random value (unique to machine/process)
- 3 bytes: incrementing counter

```javascript
const id = ObjectId("507f1f77bcf86cd799439011")
id.getTimestamp()  // Returns the creation date
```

### Reference Keys (Foreign Key Equivalent)

A field that **stores the `_id` of a document in another collection**. This is how references between collections work.

```javascript
// Users collection
{ _id: ObjectId("aaa"), name: "John" }

// Orders collection - user_id references the user
{
  _id: ObjectId("bbb"),
  user_id: ObjectId("aaa"),  // Reference key
  product: "Widget",
  total: 29.99
}
```

Unlike SQL foreign keys, MongoDB does **not** enforce referential integrity — it won't prevent you from deleting a user that has orders.

### Compound Index (Composite Key Equivalent)

A unique index on **multiple fields** together, ensuring the combination is unique.

```javascript
// Ensure each student can only enroll in a course once
db.enrollments.createIndex(
  { student_id: 1, course_id: 1 },
  { unique: true }
)
```

### Unique Index (Unique Key Equivalent)

An index that enforces **unique values** on a field.

```javascript
// Ensure no duplicate emails
db.users.createIndex({ email: 1 }, { unique: true })
```

## Why Keys Matter in MongoDB

- **Identify documents** - `_id` gives each document a unique address
- **Connect collections** - reference fields link related documents
- **Enforce uniqueness** - unique indexes prevent duplicate data
- **Improve performance** - indexed fields enable fast lookups

## Key Differences from SQL Keys

| SQL | MongoDB |
|---|---|
| Primary key defined in schema | `_id` auto-generated |
| Foreign key enforced by database | References are not enforced |
| Composite primary key | Compound unique index |
| UNIQUE constraint | Unique index |
| Cascading deletes | Must handle manually |
