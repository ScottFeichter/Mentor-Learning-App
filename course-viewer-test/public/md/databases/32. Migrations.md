# Database Migrations

## What Are Migrations?

A migration is a **version-controlled change** to your database structure.

It's a file that describes how to modify the database schema (add a table, rename a column, change a data type, etc.).

Think of migrations like Git commits for your database - each one records a specific change that can be applied or undone.

## Why Migrations?

Without migrations, you'd have to manually run SQL commands to change your database structure on every machine.

Migrations solve this by:

- **Tracking changes** - a history of every structural change made to the database
- **Team collaboration** - everyone applies the same changes in the same order
- **Reproducibility** - spin up an identical database on any machine
- **Reversibility** - undo changes if something goes wrong
- **Deployment** - automate schema changes when deploying to production

## What a Migration Looks Like

Each migration has two directions:

**Up** - applies the change:
```javascript
// Migration: create_users_table
exports.up = function(knex) {
  return knex.schema.createTable('users', (table) => {
    table.increments('id');
    table.string('name');
    table.string('email').unique();
    table.timestamps(true, true);
  });
};
```

**Down** - reverses the change:
```javascript
exports.down = function(knex) {
  return knex.schema.dropTable('users');
};
```
