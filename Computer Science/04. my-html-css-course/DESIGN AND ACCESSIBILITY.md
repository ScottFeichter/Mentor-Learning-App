# DESIGN AND ACCESSIBILITY

**Design, HTML Fundamentals, and Accessibility Objectives**

GOAL: 

- Use widely accepted design principles and accessibility standards to evaluate web pages and produce HTML pages according to specifications and best practices. 

CONTENT: 

- Design  
  - Select a palette of colors that follow basic color theory  
  - Demonstrate a basic understanding of spacing and typography for readable interfaces  
  - Demonstrate familiarity with standard navigation iconography and conventions  
  - Be able to identify and label HTML elements in a low-res wireframe spec  
      
- HTML Fundamentals  
  - Appropriately structure an HTML page  
  - Identify, utilize, and distinguish common semantic HTML tags  
  - Compare and contrast similar semantic HTML tags  
    - div vs. span vs. p  
    - h1 vs. h2 vs. h3  
    - ol vs. ul  
    - br vs. hr  
    - link vs. a  
    - head vs. header  
    - head vs. body vs. footer  
        
- Accessibility  
  - Describe what web accessibility means and why it is important  
  - Identify the standards that websites are required to meet for minimum compliance  
  - Use a web-based tool to evaluate popular websites for accessibility

DEVELOPER SKILLS:

- Meeting Requirements  
  - A developer can take a product spec and produce code to address the spec.   
  - A skilled developer anticipates and tests for common use cases as well as edge/corner cases before feeling confident that the solution works.   
    - They are able to build applications that adhere to requirements defined by a third party, while also taking initiative to propose solutions in areas that may not be as well-defined by the specification.  
        
- Accessibility  
  - A software developer understands that the tools they develop are used by a diverse group of people and must be specifically designed to meet the needs of each user.   
  - This includes considering the various ways that users will engage and interact with the content, as well as considering the various devices, hardware, and browsers that the software will be implemented with.

**Design Fundamentals**

- Internet uses are everyone and therefore totally diverse

  - Styling digital components to resemble physical components.  
    - ie first iOS  
- Flat Design  
  - Uses flat colors and thin, solid outlines  
    - ie iOS 7

MODERN WEB DESIGN PRINCIPLES

- White Space  
  - Leaving empty space surrounding the text, images, and elements  
  - Increases the legibility and usability  
  - Especially important on mobile

COLORS

- Aesthetics   
  - Colors should compliment not clash  
  - Use tools to help  
    - [Adobe color wheel](https://color.adobe.com/create/color-wheel)  
    - [Google’s material design docs](https://material.io/design/color/the-color-system.html)  
        
- Accessibility  
  - Colors should be easily distinguishable even for color-blind  
  - Colors should be distinct in hue, saturation, and value  
  - To test from color blind perspective use [simulator](https://www.color-blindness.com/coblis-color-blindness-simulator/)

TYPOGRAPHY

- Choose readable fonts  
  - Serif fonts: have small strokes  
    - Times New Roman  
    - Georgia  
  - Sans serif fonts: do not have small strokes  
    - Helvetica  
    - Roboto

CONVENTIONS

  - ie sandwich menu of three stacked horizontal lines  
- Stay up with current trends  
  - visit many different websites and examine

**Intro to Web Accessibility**

WHAT IS AND WHY

- Create a better user-experience for all users, making the web a more inclusive space for users of various ages, languages, and other user characteristics.

WCAG COMPLIANCE

- Web Content Accessibility Guidelines  
  - A set of guidelines for designing accessible web content.  
  - The WCAG 2.0 Guidelines set the bar for section 508 compliance of the Rehabilitation Act.   
  - If a software company does not make the effort to provide accessible resources for users, they can be sued for violating this federal law.  
    

[WCAG FOUR PRINCIPLES](https://www.w3.org/WAI/WCAG21/quickref/) and [CHECKLIST](https://www.wuhcag.com/wcag-checklist/)

- Preceivable  
- Operable  
- Understandable  
- Robust
