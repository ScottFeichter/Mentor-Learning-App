# Memory Addressing

## What is Memory Addressing?

Memory addressing is the system computers use to locate and access data stored in addressable memory (cache, RAM, storage). Unlike CPU registers which are accessed by name, addressable memory uses numerical addresses to identify specific locations.

## Address Space Concepts

### Physical vs Virtual Addressing

#### Physical Addressing
- **Direct hardware addresses** pointing to actual memory locations
- Used by early computers and embedded systems
- Limited by physical memory size
- Security and isolation challenges

#### Virtual Addressing
- **Logical addresses** translated to physical addresses
- Each process has its own virtual address space
- Enables memory protection and isolation
- Allows programs larger than physical memory

```
Virtual Address Space (per process)
┌─────────────────────────────────────┐ 0xFFFFFFFF
│ Kernel Space                        │
├─────────────────────────────────────┤ 0xC0000000
│ Stack (grows down)                  │
│              ↓                      │
│                                     │
│              ↑                      │
│ Heap (grows up)                     │
├─────────────────────────────────────┤
│ Data Segment (.data, .bss)          │
├─────────────────────────────────────┤
│ Text Segment (.text)                │
└─────────────────────────────────────┘ 0x00000000
```

## Address Translation

### Memory Management Unit (MMU)
The MMU translates virtual addresses to physical addresses:

```
CPU → Virtual Address → MMU → Physical Address → Memory
     (0x12345678)           (0x87654321)
```

### Page Tables
Virtual memory is divided into fixed-size pages (typically 4KB):

```
Virtual Address (32-bit example)
┌──────────────┬──────────────┐
│ Page Number  │ Page Offset  │
│   (20 bits)  │  (12 bits)   │
└──────────────┴──────────────┘

Page Table Entry
┌─────────────────────────────────────┐
│ Physical Page Number │ Flags        │
│     (20 bits)        │ (12 bits)    │
└─────────────────────────────────────┘
```

## Addressing Modes

### Direct Addressing
```assembly
MOV RAX, [0x1000]    ; Load from absolute address 0x1000
```

### Indirect Addressing
```assembly
MOV RAX, [RBX]       ; Load from address stored in RBX
```

### Indexed Addressing
```assembly
MOV RAX, [RBX + 8]   ; Load from RBX + 8 offset
MOV RAX, [RBX + RCX] ; Load from RBX + RCX
```

### Base + Index + Displacement
```assembly
MOV RAX, [RBX + RCX*4 + 16]  ; Complex addressing
; Address = RBX + (RCX * 4) + 16
```

## Cache Addressing

### Cache Organization
Caches use addresses to determine where data is stored:

```
Memory Address (64-bit)
┌─────────────┬─────────────┬─────────────┐
│    Tag      │    Index    │   Offset    │
│  (52 bits)  │  (6 bits)   │  (6 bits)   │
└─────────────┴─────────────┴─────────────┘
     │             │             │
     │             │             └─ Byte within cache line
     │             └─ Which cache set
     └─ Identifies specific cache line
```

### Cache Lookup Process
1. **Extract index** from address to find cache set
2. **Compare tags** to see if data is present (cache hit/miss)
3. **Use offset** to find specific byte within cache line

### Cache Line Alignment
```
Memory Layout (64-byte cache lines)
Address:  0x1000  0x1040  0x1080  0x10C0
         ┌───────┬───────┬───────┬───────┐
         │Line 0 │Line 1 │Line 2 │Line 3 │
         └───────┴───────┴───────┴───────┘
          64 bytes each
```

## Memory Hierarchy Addressing

### L1 Cache Addressing
- **Size**: 32-64 KB
- **Associativity**: 8-way set associative
- **Line Size**: 64 bytes
- **Access**: Virtual or physical addresses

### L2/L3 Cache Addressing
- **Size**: 256 KB - 32 MB
- **Associativity**: 8-16 way set associative
- **Line Size**: 64 bytes
- **Access**: Physical addresses

### RAM Addressing
- **Address Bus**: 64-bit (supports up to 16 EB theoretical)
- **Practical Limit**: 48-bit (256 TB) on current x86-64
- **Organization**: Banks, ranks, channels for parallel access

## Address Translation Performance

### Translation Lookaside Buffer (TLB)
Cache for page table entries to speed up address translation:

```
Virtual Address → TLB Lookup → Physical Address
                     ↓
                 TLB Miss → Page Table Walk → Update TLB
```

### Address Translation Timing
| Component | Hit Time | Miss Penalty |
|-----------|----------|--------------|
| TLB | 1 cycle | 10-100 cycles |
| L1 Cache | 3-4 cycles | - |
| L2 Cache | 10-20 cycles | - |
| L3 Cache | 30-70 cycles | - |
| RAM | 200-400 cycles | - |

## Programming Language Addressing

### C/C++ Pointer Addressing
```c
int arr[100];
int *ptr = &arr[0];     // Address of first element
int value = *(ptr + 5); // Dereference address ptr + 5*sizeof(int)

// Address arithmetic
ptr++;                  // Move to next integer (ptr += 4 on 32-bit)
ptr += 10;             // Move 10 integers forward
```

### JavaScript Memory Addressing (Hidden)
```javascript
// JavaScript hides addressing, but engines use it internally
let obj = { x: 42 };    // Object allocated at some memory address
let arr = [1, 2, 3];    // Array elements at consecutive addresses

// V8 engine internally:
// - Objects have hidden classes with property offsets
// - Arrays use contiguous memory addressing
// - Garbage collector tracks object addresses
```

### 32-bit Address Space

           │ User Space (3 GB)                   │
           │ ┌─ Stack                            │
           │ │                                   │
           │ │  ↓ (grows down)                   │
           │ │                                   │
           │ │  ↑ (grows up)                     │

```

```

## Memory Protection and Addressing

### Segmentation (Legacy)
- **Code Segment**: Executable instructions
- **Data Segment**: Initialized data
- **Stack Segment**: Function calls and local variables
- **Heap Segment**: Dynamic allocation

### Page-Based Protection
Modern systems use page-level protection:
- **Read/Write/Execute permissions** per page
- **User/Kernel mode** access control
- **Copy-on-write** for memory efficiency

## Address Optimization Techniques

### Spatial Locality
```c
// Good: Sequential access (cache-friendly)
for (int i = 0; i < 1000; i++) {
    array[i] = i;  // Addresses: 0x1000, 0x1004, 0x1008...
}

// Bad: Random access (cache-unfriendly)
for (int i = 0; i < 1000; i++) {
    array[random()] = i;  // Random addresses
}
```

### Structure Padding and Alignment
```c
struct BadAlignment {
    char a;     // 1 byte
    int b;      // 4 bytes (3 bytes padding before this)
    char c;     // 1 byte (3 bytes padding after this)
};  // Total: 12 bytes

struct GoodAlignment {
    int b;      // 4 bytes
    char a;     // 1 byte
    char c;     // 1 byte (2 bytes padding after this)
};  // Total: 8 bytes
```

## Common Addressing Errors

### Segmentation Fault
```c
int *ptr = NULL;
*ptr = 42;  // Accessing address 0x0 - segmentation fault
```

### Buffer Overflow
```c
char buffer[10];
strcpy(buffer, "This string is too long");  // Writes past buffer end
```

### Use After Free
```c
int *ptr = malloc(sizeof(int));
free(ptr);
*ptr = 42;  // Accessing freed memory address
```

## Performance Implications

### Cache-Friendly Addressing Patterns
1. **Sequential access** - leverages prefetching
2. **Power-of-2 strides** - avoids cache conflicts
3. **Aligned access** - prevents crossing cache line boundaries
4. **Temporal locality** - reuse recently accessed addresses

### Address Translation Overhead
- **TLB misses** can add 10-100 cycles per memory access
- **Large pages** (2MB, 1GB) reduce TLB pressure
- **PCID** (Process Context ID) reduces TLB flushes

## Key Insights

1. **Addressing enables the memory hierarchy** - without addresses, we'd only have registers
2. **Virtual memory provides isolation** - each process has its own address space
3. **Cache performance depends on addressing patterns** - sequential beats random
4. **Address translation has overhead** - TLB and page table walks cost cycles
5. **Alignment matters** - misaligned access can span cache lines
6. **Modern addressing is complex** - multiple levels of translation and caching
