# jsonwebtoken Package

## What is jsonwebtoken?

`jsonwebtoken` is a Node.js package that implements JSON Web Tokens (JWT) for secure authentication and information exchange between parties.

JWTs are compact, URL-safe tokens that contain encoded JSON data and are digitally signed to verify authenticity.

## What Does It Do?

- **Creates JWTs**: Generates signed tokens containing user data (payload)
- **Verifies JWTs**: Validates tokens to ensure they haven't been tampered with
- **Decodes JWTs**: Extracts payload data without verification (use cautiously)
- **Manages Token Expiration**: Automatically handles token expiry times

## Important: Signing vs Password Hashing

**jsonwebtoken DOES use hashing, but NOT for passwords:**

### What JWT Hashing Does:
- When `jwt.sign()` creates a token, it uses **HMAC-SHA256** (or other algorithms) to hash the header + payload + secret
- This creates the **signature** (the third part of the token)
- The signature verifies the token hasn't been tampered with

```javascript
// JWT signing process (simplified):
signature = HMAC-SHA256(
  base64(header) + "." + base64(payload),
  secret
)
```

### What JWT Does NOT Do:
- **Does NOT hash passwords** - passwords need separate hashing
- **Does NOT encrypt the payload** - it's only base64-encoded (anyone can decode and read it)

### Password Hashing (Separate Requirement):

You must use a dedicated library for password hashing:
- `bcrypt` (recommended)
- `bcryptjs`
- `argon2`

**Complete Example:**
```javascript
const jwt = require('jsonwebtoken');
const bcrypt = require('bcrypt');

// Registration - bcrypt hashes the password
const hashedPassword = await bcrypt.hash(password, 10);
await saveUser({ email, password: hashedPassword });

// Login - bcrypt verifies password, JWT hashes token content for signature
const user = await findUser(email);
const validPassword = await bcrypt.compare(password, user.password);

if (validPassword) {
  // jwt.sign() uses HMAC-SHA256 hashing to create the signature
  const token = jwt.sign({ userId: user.id }, SECRET);
  res.json({ token });
}
```

**Key Takeaway:** JWT uses hashing to sign tokens (create signatures), but password hashing is a separate process requiring bcrypt or similar libraries.

## Most Common Methods

### 1. `jwt.sign(payload, secretOrPrivateKey, [options])`

Creates and signs a new JWT.

**Parameters:**
- `payload`: Object containing the data to encode (user ID, roles, etc.)
- `secretOrPrivateKey`: String or buffer containing the secret key
- `options`: Optional configuration object

**Common Options:**
- `expiresIn`: Token expiration time (e.g., '1h', '7d', '30m')
- `algorithm`: Signing algorithm (default: 'HS256')
- `issuer`: Token issuer
- `audience`: Token audience

**Example:**
```javascript
const jwt = require('jsonwebtoken');

const token = jwt.sign(
  { userId: 123, email: 'user@example.com' },
  'your-secret-key',
  { expiresIn: '1h' }
);
```

### 2. `jwt.verify(token, secretOrPublicKey, [options])`

Verifies a token's signature and decodes the payload.

**Parameters:**
- `token`: The JWT string to verify
- `secretOrPublicKey`: The secret key used to sign the token
- `options`: Optional configuration object

**Returns:** Decoded payload if valid

**Throws:** Error if token is invalid, expired, or tampered with

**Example:**
```javascript
try {
  const decoded = jwt.verify(token, 'your-secret-key');
  console.log(decoded); // { userId: 123, email: 'user@example.com', iat: ..., exp: ... }
} catch (error) {
  console.error('Invalid token:', error.message);
}
```

### 3. `jwt.decode(token, [options])`

Decodes a token WITHOUT verifying the signature.

**Parameters:**
- `token`: The JWT string to decode
- `options`: Optional configuration object

**Returns:** Decoded payload (unverified)

**Warning:** Use only when you don't need to verify authenticity

**Example:**
```javascript
const decoded = jwt.decode(token);
console.log(decoded); // Payload without verification
```

## Common Use Cases

### Authentication Flow

```javascript
// Login - Generate token
app.post('/login', (req, res) => {
  const user = authenticateUser(req.body);
  const token = jwt.sign(
    { userId: user.id, role: user.role },
    process.env.JWT_SECRET,
    { expiresIn: '24h' }
  );
  res.json({ token });
});

// Protected Route - Verify token
app.get('/protected', (req, res) => {
  const token = req.headers.authorization?.split(' ')[1];
  try {
    const decoded = jwt.verify(token, process.env.JWT_SECRET);
    res.json({ data: 'Protected data', user: decoded });
  } catch (error) {
    res.status(401).json({ error: 'Unauthorized' });
  }
});
```

## Token Structure

A JWT consists of three parts separated by dots:
```
header.payload.signature
```

Example:
```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ1c2VySWQiOjEyMywiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
```

## Best Practices

1. **Store secrets securely**: Use environment variables, never hardcode
2. **Set expiration times**: Always use `expiresIn` option
3. **Use HTTPS**: Transmit tokens only over secure connections
4. **Validate on server**: Always verify tokens on the backend
5. **Don't store sensitive data**: JWTs are encoded, not encrypted
6. **Implement token refresh**: Use refresh tokens for long-lived sessions

## Common Errors

- `JsonWebTokenError`: Invalid token format or signature
- `TokenExpiredError`: Token has expired
- `NotBeforeError`: Token used before `nbf` claim time
