# Hash Tables

Also known as hash maps. Perhaps the most important data structure.

- Key:value storage
- Constant O(1) time complexity for insertion, deletion, access, and search
- An array with elements indexed by a hashed key
- Key hash is run through a modulo function to convert it to an array index

## Steps to Create

1. Initialize a fixed-size array with each element set to null (elements are called **buckets**)
2. Create a hash function that converts keys (strings) to integers
3. Create a hashMod function that converts the key hash into a valid array index (using modulo)

## Steps to Insert

1. Hash and modulo the key to find the correct bucket index
2. Create key:value pair
3. Store the pair in the correct bucket: `fixedSizeArray[index] = {key: value}`

## Steps to Retrieve

1. Run `hashMod(key)` to get the index
2. Find the bucket at the index

## Performance

**Time Complexity:**
- Maintains much of the performance of the underlying array
- Hashing is technically O(n) but if key < 1000 chars it's effectively O(1)
- hashMod is O(1)
- Searching for keys is faster than searching through an array

**Space Complexity:**
- Lots of wasted space compared to an array
- Most often O(1) but proportional to values stored
- Essentially the same as an array: O(n)

## Best-Case Time Complexity

| Operation | Complexity |
|-----------|-----------|
| Reading/Getting | O(1) |
| Inserting/Setting | O(1) |
| Deleting/Removing | O(1) |
