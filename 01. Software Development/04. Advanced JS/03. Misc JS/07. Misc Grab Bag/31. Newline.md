# Newline

A newline is not a single character — it is a category of invisible characters called **Line Terminators** that signal the end of a line.

---

## Why It Matters

The lexer uses line terminators to:

- Track line numbers for error messages
- Know when a `//` comment ends
- Inform ASI (Automatic Semicolon Insertion) where a line break occurred

---

## Line Terminator Characters

| Name | Escape | Hex | Decimal | Origin |
|------|--------|-----|---------|--------|
| Line Feed | `\n` | `0x0A` | 10 | Unix, macOS, modern standard |
| Carriage Return | `\r` | `0x0D` | 13 | Old Mac systems (pre OS X) |
| CR+LF | `\r\n` | `0x0D 0x0A` | 13 + 10 | Windows |
| Line Separator | `\u2028` | `0x2028` | 8232 | Unicode — rare |
| Paragraph Separator | `\u2029` | `0x2029` | 8233 | Unicode — rare |

The JS spec recognizes all five as valid line terminators.

---

## Carriage Return vs Line Feed

These names come from typewriters:

- **Carriage Return** — physically moved the print head back to the start of the line
- **Line Feed** — physically rolled the paper up one line

On early computers both actions were separate. Over time different operating systems made different choices about which byte sequence to use for "go to the next line":

- Unix chose Line Feed only — `\n`
- Old Mac chose Carriage Return only — `\r`
- Windows chose both together — `\r\n`

Today `\n` is the universal standard. Windows still uses `\r\n` internally but most modern tools handle both.

---

## How The Lexer Sees Them

The lexer reads source code one byte at a time. When it encounters a line terminator:

1. It increments its internal line counter
2. It resets its column counter to zero
3. If it was inside a `//` comment it exits comment mode
4. It passes the line terminator information to ASI

For `\r\n` the lexer treats the two bytes as a single line terminator — it does not count them as two separate lines.

---

## CR+LF In Practice

If a file was written on Windows and opened on Unix, you may see `\r` appearing as a visible character at the end of lines — sometimes shown as `^M` in terminals. This is the leftover Carriage Return that Unix did not strip.

Most code editors and version control tools normalize line endings automatically to avoid this.

---

## Line Terminators vs Whitespace

Line terminators are related to whitespace but distinct:

- **Whitespace** — space `0x20`, tab `0x09` — skipped silently, no side effects
- **Line Terminators** — trigger line counting, end `//` comments, inform ASI

The lexer treats them differently even though both are invisible characters.
