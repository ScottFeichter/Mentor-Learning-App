# Whitespace

Whitespace is syntax the lexer recognizes and skips. It has no meaning to the parser or engine.

---

## What Whitespace Is

Whitespace is not a single thing — it is a category of invisible characters that the lexer treats the same way: see it, skip it, move on.

Multiple whitespace characters in a row are just multiple bytes of the same kind. There is no "amount" encoded — repetition is all it is.

---

## Whitespace Characters

Each whitespace character is a single byte with a fixed hex value in ASCII:

| Character | Hex | Decimal | Name |
|-----------|-----|---------|------|
| Space | `0x20` | 32 | Space |
| Tab | `0x09` | 9 | Horizontal Tab |
| `\n` | `0x0A` | 10 | Line Feed (LF) |
| `\r` | `0x0D` | 13 | Carriage Return (CR) |
| `\r\n` | `0x0D 0x0A` | 13 + 10 | CR+LF (Windows) |
| `\v` | `0x0B` | 11 | Vertical Tab (rare) |
| `\f` | `0x0C` | 12 | Form Feed (rare) |

---

## Space vs Tab

- A space is one `0x20` byte. Three spaces is three `0x20` bytes in a row.
- A tab is one `0x09` byte regardless of how wide it looks in your editor.
- The visual width of a tab (2, 4, or 8 spaces) is an editor display setting — the actual byte is always `0x09`.
- To the lexer, a space and a tab are identical — both are whitespace, both are skipped.

---

## Line Terminators

The JS spec recognizes three line terminator sequences:

- `\n` — Line Feed. Unix and macOS.
- `\r` — Carriage Return. Old Mac systems.
- `\r\n` — CR+LF. Windows. Two bytes treated as one line terminator.

The lexer uses line terminators to track line numbers. Every time it encounters one it increments its internal line counter. This is how error messages know which line a problem is on.

---

## What Hex Is

`0x` is the prefix that signals a number is written in base 16 (hexadecimal).

`0x20` = 2×16 + 0 = 32 in decimal — the ASCII code for a space character.
