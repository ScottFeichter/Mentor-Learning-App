# Identifiers

&nbsp;

An **Identifier** is what you write as a name you give something.

---

## Identifiers Are Memory Addresses

An **Identifier** is a human readable representation of a memory address in your code.

### JS Engine Allocates Memory Address

The computer doesn't use the syntax you write as an Indentifer for something.

Instead it uses a memory address that it creates and allocates when it reads your declaration.

### Identifiers Must Be Declared

JS is prompted by declaration keywords to recognize syntax as intended to be an identifer.

It must be preceeded by a declaration keyword and a space for JS to understand its purpose.

---

## Where Identifiers Live In Memory

If an identifier is the human readable representation of a memory address what kind of memory is it?

### Volatile Memory? Cache Memory?

The address is not allocated until runtime

### On The Call Stack

It lives on the **call stack**, inside the current execution context.

That memory location holds either a value directly, or an address pointing to where the value lives.

```
Stack (execution context)
─────────────────────────
volume → 5
radio  → [address: 0x001]
```

- `volume` lives on the stack and holds its value directly
- `radio` lives on the stack and holds an address (pointer)
