# Lines Of Code

&nbsp;

We've discussed all the syntax parts but lets examine what **lines of code** are.

---

## Byte Sequences

The text humans see and interact with is not what the computer uses.

### Unicode and UTF-8

Unicode is a lookup table for translating text characters to/from byte sequences.

It includes ASCII and more to cover every character in every writing system in the world.

### JavaScript Source Files

Each character in a .js file maps to a Unicode byte sequence, including whitespace.

UTF-8 is the strategy used by .js files for storing Unicode characters in differing byte sizes.

---

## Codec (Encoder Decoder)

Getting byte sequences to/from text readable by humans is a process of encoding/decoding.

### Codec In Editor

When you open a .js file in an editor it uses a built-in codec to map byte sequences to human readable text.

The codec reads bytes left to right and builds the text view character by character.

### Editing vs Running JS Files

When the file consumer needs text rather than raw bytes a codec is essential.

When running a file readable text and a codec aren't necessary and instead a lexer is used.

---

## Lexical Analyser aka Tokenizer

The Lexer converts things like Operators into meaningful tokens and discards Incidentals.

### Signals

A Lexer scans source code byte by byte from left to right.

Certain Unicode sequences signal the Lexer to recognize and discard Incidentals.

### Tokens

The bytes not discarded are tokenized to C++ objects with properties like type and value.

From there the Lexer hands the tokenized code to the parser for further processing.
