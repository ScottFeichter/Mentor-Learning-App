# this & Context

&nbsp;

Every execution context has a `this` binding.

When the JS engine creates an execution context, one of the three things it sets up is what `this` points to.

---

## Execution Context Sets this

`this` is not determined by where a function is written.

It is determined by how the function is **called**.

```js
const radio = {
  station: "101.1",
  getStation() {
    console.log(this.station)
  }
}

const fn = radio.getStation

radio.getStation() // this = radio       — method call
fn()               // this = globalThis  — regular function call
```

Same function definition.
Different call site.
Different `this`.

---

## Context vs Scope

- **Scope** is determined at write time — where the identifier is declared
- **Context (`this`)** is determined at call time — how the function is invoked

They are set up differently and serve different purposes inside the execution context.

---

## The Three Parts of Execution Context

Every execution context contains:

- **Variable Environment** — where identifiers live
- **Scope Chain** — access to outer scopes
- **`this` binding** — what object `this` refers to

`this` is the third part — separate from scope entirely.

---

## Losing Context

Context can be lost when a method is detached from its object.

```js
const radio = {
  station: "101.1",
  getStation() {
    console.log(this.station)
  }
}

const fn = radio.getStation
fn() // this is no longer radio — context is lost
```

Use `bind` to lock `this` to a specific object.

```js
const fn = radio.getStation.bind(radio)
fn() // this = radio
```
