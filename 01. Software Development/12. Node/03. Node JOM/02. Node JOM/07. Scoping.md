# Scoping

&nbsp;

**Scope** determines where a variable is accessible in your code.

When you declare a variable, scope defines which parts of the program can read or write it.

## The Scope Chain

<span class="js-yellow">JS</span> resolves variable names by looking outward through nested scopes.

If a variable isn't found in the current scope, JS looks in the parent scope, then its parent, and so on until it reaches the global scope.

If it still isn't found, a <span class="purple-bold">ReferenceError</span> is thrown.

```js
const x = 'global'

function outer() {
  const y = 'outer'

  function inner() {
    const z = 'inner'
    console.log(x) // found in global scope
    console.log(y) // found in outer scope
    console.log(z) // found in local scope
  }
}
```

## Types of Scope in JS

### Block Scope

<span class="purple-bold">let</span> and <span class="purple-bold">const</span> are block scoped.

They are only accessible within the `{}` block they are declared in.

```js
{
  let a = 1
  const b = 2
}

console.log(a) // ReferenceError
console.log(b) // ReferenceError
```

### Function Scope

<span class="purple-bold">var</span> is function scoped.

It is accessible anywhere within the function it is declared in, regardless of blocks.

```js
function example() {
  if (true) {
    var x = 'I am var'
    let y = 'I am let'
  }
  console.log(x) // 'I am var'
  console.log(y) // ReferenceError
}
```

### Module Scope

When <span class="js-yellow">JS</span> files are treated as modules, top-level declarations are scoped to that file.

They are not added to <span class="purple-bold">globalThis</span>.

```js
// module.js
const secret = 'only in this file'

// other.js
console.log(secret) // ReferenceError
```

### Global Scope

A variable declared at the top level outside any function or block has global scope.

It becomes a property of <span class="purple-bold">globalThis</span>.

```js
var greeting = 'hello'

console.log(globalThis.greeting) // 'hello'
```

## Scoping Differs Between JS, Browser, and <span class="node-green">Node</span>

The scope chain always ends at <span class="purple-bold">globalThis</span>.

But what <span class="purple-bold">globalThis</span> contains — and how top-level code is treated — differs between environments.

### Plain JS (ECMAScript)

The language spec defines scope rules but does not define a global environment.

<span class="purple-bold">globalThis</span> exists as a concept but its contents are left to the runtime.

### Browser

In the browser, top-level <span class="purple-bold">var</span> declarations and function declarations become properties of <span class="purple-bold">window</span>.

Since <span class="purple-bold">window</span> is <span class="purple-bold">globalThis</span>, they are globally accessible everywhere.

```js
// browser — classic script tag (not a module)
var name = 'Scott'
console.log(window.name) // 'Scott'
```

If the script is loaded as a module (`type="module"`), top-level declarations are module scoped and do not attach to <span class="purple-bold">window</span>.

### Node

In <span class="node-green">Node</span>, every file is treated as a module by default.

Top-level <span class="purple-bold">var</span> declarations do **not** attach to <span class="purple-bold">global</span>.

They are scoped to the file.

```js
// node
var name = 'Scott'
console.log(global.name) // undefined
console.log(name)        // 'Scott' — file scoped
```

To explicitly attach something to the <span class="node-green">Node</span> global scope you must assign it directly.

```js
global.name = 'Scott'
console.log(global.name) // 'Scott'
```

## Summary

| | Top-level var attaches to globalThis? | Default module scope? |
|---|---|---|
| Browser (script) | Yes | No |
| Browser (module) | No | Yes |
| <span class="node-green">Node</span> | No | Yes |
