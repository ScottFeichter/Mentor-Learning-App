# Environment Scope Differences

&nbsp;

The scope chain always ends at <span class="purple-bold">globalThis</span> regardless of environment.

But what <span class="purple-bold">globalThis</span> contains differs between environments.

## Scoping Differs Between JS, Browser, and Node

How top-level code is treated varies among environments due to disparity of <span class="purple-bold">globalThis</span>.

### Plain JS (ECMAScript)

The language spec defines scope rules but does not define a global environment.

<span class="purple-bold">globalThis</span> exists as a concept but its contents are left to the runtime.

### Browser

In the browser, top-level var and function declarations become properties of <span class="purple-bold">window</span>.

Since <span class="purple-bold">window</span> is <span class="purple-bold">globalThis</span>, they are globally accessible everywhere.

```js
// browser — classic script tag (not a module)
var name = 'Scott'
console.log(window.name) // 'Scott'
```

If the script is loaded as a module (`type="module"`) top-level declarations are **NOT** global.

They are module scoped and do not attach to <span class="purple-bold">window</span>.

### Node

In <span class="node-green">Node</span>, every file is treated as a module by default.

Top-level declarations do **NOT** attach to <span class="purple-bold">global</span>; they are scoped to the file.

```js
// node
var name = 'Scott'
console.log(global.name) // undefined
console.log(name)        // 'Scott' — file scoped
```

To attach something to <span class="node-green">Node</span> global scope you must assign it directly.

```js
global.name = 'Scott'
console.log(global.name) // 'Scott'
```

## Summary

| | Top-level var attaches to globalThis? | Default module scope? |
|---|---|---|
| Browser (script) | Yes | No |
| Browser (module) | No | Yes |
| <span class="node-green">Node</span> | No | Yes |
