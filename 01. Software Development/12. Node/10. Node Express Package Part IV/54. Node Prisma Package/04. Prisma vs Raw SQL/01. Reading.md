# Prisma vs Raw SQL

## Overview

Both approaches connect Node.js applications to PostgreSQL, but serve different purposes and provide different levels of abstraction.

## Raw SQL (pg driver)

**Low-level driver** that provides direct access to PostgreSQL operations.

### Characteristics
- **Direct SQL**: Write raw SQL queries
- **Minimal abstraction**: Close to the database
- **Performance**: Less overhead
- **Flexibility**: Full control over queries
- **Learning curve**: Requires SQL knowledge

### Example
```javascript
const { Pool } = require('pg');

const pool = new Pool({ connectionString: process.env.DATABASE_URL });

// Direct SQL operations
const result = await pool.query(
  'INSERT INTO users (name, email) VALUES ($1, $2) RETURNING *',
  ['John', 'john@email.com']
);
const user = result.rows[0];

const found = await pool.query('SELECT * FROM users WHERE id = $1', [1]);
```

## Prisma (ORM)

**Object-Relational Mapper** that adds structure, type safety, and schema management on top of the database.

### Characteristics
- **Schema-based**: Define structure in schema.prisma
- **Type-safe**: Auto-generated client with autocomplete
- **Migrations**: Track schema changes over time
- **Abstraction**: Work with JavaScript objects, not SQL strings
- **Relations**: Easy eager loading and nested queries

### Example
```javascript
const { PrismaClient } = require('@prisma/client');
const prisma = new PrismaClient();

// Model-based operations
const user = await prisma.user.create({
  data: { name: 'John', email: 'john@email.com' }
});

const found = await prisma.user.findUnique({ where: { id: 1 } });
```

## Key Differences

| Feature | pg (Raw SQL) | Prisma |
|---------|--------------|--------|
| **Abstraction Level** | Low-level, direct SQL | High-level, object-oriented |
| **Schema** | Managed in SQL/migrations manually | Managed in schema.prisma |
| **Type Safety** | None (strings) | Full TypeScript support |
| **Performance** | Faster (less overhead) | Slightly slower (more features) |
| **Learning Curve** | Need SQL knowledge | Need Prisma syntax |
| **Migrations** | Manual SQL files | Auto-generated |
| **Relations** | Manual JOINs | include/select |
| **Validation** | Manual | Schema-level constraints |

## Code Comparison

### Connection
```javascript
// pg
const { Pool } = require('pg');
const pool = new Pool({ connectionString: process.env.DATABASE_URL });

// Prisma
const { PrismaClient } = require('@prisma/client');
const prisma = new PrismaClient();
```

### Create
```javascript
// pg
await pool.query('INSERT INTO users (name, email) VALUES ($1, $2)', ['John', 'john@email.com']);

// Prisma
await prisma.user.create({ data: { name: 'John', email: 'john@email.com' } });
```

### Read with Filter
```javascript
// pg
const result = await pool.query('SELECT * FROM users WHERE age > $1 ORDER BY name LIMIT $2', [18, 10]);

// Prisma
const users = await prisma.user.findMany({
  where: { age: { gt: 18 } },
  orderBy: { name: 'asc' },
  take: 10
});
```

### Join/Relations
```javascript
// pg
const result = await pool.query(`
  SELECT u.name, t.title FROM users u
  JOIN tasks t ON u.id = t.user_id
  WHERE u.id = $1
`, [1]);

// Prisma
const user = await prisma.user.findUnique({
  where: { id: 1 },
  include: { tasks: true }
});
```

## When to Use Which

### Use Raw SQL (pg) When:
- Performance is critical
- Complex queries that Prisma can't express
- You already know SQL well
- Minimal dependencies preferred
- One-off scripts or simple projects

### Use Prisma When:
- Rapid development needed
- Type safety is important
- Team collaboration (schema as code)
- Complex relations and eager loading
- You want auto-generated migrations
- Building REST APIs with CRUD operations

## Relationship

Prisma **generates SQL** internally — it translates your Prisma method calls into optimized SQL queries. You can even use `$queryRaw` to write raw SQL when Prisma's query builder isn't enough.
