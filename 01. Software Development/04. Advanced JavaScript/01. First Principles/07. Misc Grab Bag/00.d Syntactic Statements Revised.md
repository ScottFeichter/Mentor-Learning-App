# Syntactic Statements Revised

A statement consists of Lexicals, Expressions, or both. It must direct the engine to do something — even if that something is nothing (ghost).

---

## The Syntax Lens

The categories below are defined by what the programmer **writes**, not what the engine does implicitly. This is the syntax lens.

- A **Lexical Statement** contains only keywords and/or punctuators. No operator written, no operand written — even if the engine fills in implicit behavior.
- An **Expression Statement** contains an operator and operands written by the programmer. Divided by whether the result is usable elsewhere.

---

## The Taxonomy

```
Statements
├── Lexical Statements
│   ├── Declaration    (let x, const x, var x)
│   ├── Import/Export  (import x from ..., export default x)
│   └── Ghost          (;)
└── Expression Statements
    ├── Operable
    │   ├── Function calls        (foo())
    │   ├── Arithmetic            (x + y)
    │   ├── Logical               (x && y)
    │   ├── Comparison            (x === y)
    │   ├── Ternary               (x ? y : z)
    │   └── Literals/Identifiers  (42, "hello", x, "use strict")
    └── Inoperable
        ├── Initialization        (let x = 5)
        └── Assignment            (x = 5)
```

---

## Key Deliberations

### Why Declaration is a Lexical Statement
`let x` has no operator and no operand written by the programmer. The engine implicitly binds `x` to `undefined`, but that behavior is invisible in the syntax. Through the syntax lens, it is keyword-only — a Lexical Statement.

### Why Initialization is an Expression Statement
`let x = 5` contains a keyword *and* an operator *and* operands. The `=` operator is written by the programmer. In another language `y = (let x = 5)` might be valid — JS forbids it, but that is a JS-specific restriction, not a syntactic property. The expression is there, JS just walls it off. So initialization is an Inoperable Expression Statement.

### Why Assignment is Inoperable
`x = 5` produces a value — the value of the right-hand side. JS restricts where that value can be used as an operand. The restriction is JS-specific. The expression itself is valid and produces a value, it just can't be used freely as an operand in JS.

### Why Ghost is a Lexical Statement
`;` is a lone punctuator. No expression, no operator, no operand. The engine executes it by doing nothing. It still qualifies as a statement because a statement must consist of Lexicals and/or Expressions — and `;` is a Lexical.

### Why "use strict" is an Operable Expression Statement
`"use strict"` is a string literal. Syntactically, a literal produces a value — `"use strict"` produces the string `"use strict"`. The engine intercepts it and treats it as a directive, ignoring the produced value. But that is runtime behavior layered on top. Through the syntax lens it is a string literal expression — Operable, the engine just happens to consume the value before it goes anywhere.

### The Category Rule
The category (Lexical vs Expression) is determined by what initiates and drives the statement in the syntax:
- If only keywords and/or punctuators appear — Lexical Statement.
- If an operator and operands appear — Expression Statement.
- A statement can contain both (e.g. `let x = 5`) — the presence of an operator is what makes it an Expression Statement.
