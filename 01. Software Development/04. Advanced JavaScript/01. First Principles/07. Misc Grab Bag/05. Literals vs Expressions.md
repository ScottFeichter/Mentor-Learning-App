# Literals vs Expressions

&nbsp;

A **literal** is one specific kind of expression.

The natural comparison for a literal is not a primitive or a reference — it is any **expression that produces a value at runtime**.

---

## The Distinction

- **Literal** — a value written directly in code, always the same
- **Expression** — any code that produces a value, possibly computed at runtime

```js
"101.1"          // literal — written directly, always "101.1"
getStation()     // expression — produced at runtime, could be anything
"101." + "1"     // expression — computed from two literals
```

---

## All Literals Are Expressions

A literal is a value written directly in code.

That makes it an expression — it evaluates to a value.

But not all expressions are literals.

```js
42               // literal expression
volume * 2       // expression — not a literal
new Date()       // expression — not a literal
```

---

## Are All Literals Part Of a Statement?

Yes — everything in JS is part of a statement at some level.

A literal is an expression, and expressions live inside statements.

```js
"101.1"                  // floating alone — an expression statement, useless
let x = "101.1"         // literal inside a declaration statement
console.log("101.1")    // literal as an argument inside an expression statement
```

The hierarchy is:

```
Statement
  └── Expression
        └── Literal (one kind of expression)
```

---

## The Three Comparisons

These concepts each live on a different axis:

```
Syntax  →  Literals vs Expressions
Syntax  →  Expressions vs Statements
Memory  →  Primitives vs References
```

- **Literals vs Expressions** — how a value enters the code
- **Expressions vs Statements** — the fundamental syntax split in JS
- **Primitives vs References** — how values are stored and copied in memory

Mixing these axes is what makes the concepts feel confusing.

They are answering completely different questions.
