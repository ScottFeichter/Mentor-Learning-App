# Literals

&nbsp;

A **literal** is a value written directly in code.

## What Is A Literal

It is not a variable, not a function call, not an expression.

It is the value itself, typed out explicitly.

---

## What Literals Look Like

<span style="color: var(--heading-h3-color); font-weight: bold;">String literal</span>
  - characters wrapped in quotes
    - `"101.1"`, `'hello'`, `` `world` ``

<span style="color: var(--heading-h3-color); font-weight: bold;">Number literal</span>
  - a number typed directly
    - `42`, `3.14`, `-7`

<span style="color: var(--heading-h3-color); font-weight: bold;">Boolean literal</span>
  - one of two reserved words
    - `true`, `false`

<span style="color: var(--heading-h3-color); font-weight: bold;">Null literal</span>
  - the intentional absence of a value
    - `null`

<span style="color: var(--heading-h3-color); font-weight: bold;">Undefined literal</span>
  - the absence of an assigned value
    - `undefined`

<span style="color: var(--heading-h3-color); font-weight: bold;">BigInt literal</span>
  - a large integer with an `n` suffix
    - `42n`, `9007199254740991n`

<span style="color: var(--heading-h3-color); font-weight: bold;">Object literal</span>
  - key-value pairs wrapped in curly braces
    - `{ station: "101.1", volume: 5 }`

<span style="color: var(--heading-h3-color); font-weight: bold;">Array literal</span>
  - values wrapped in square brackets
    - `["101.1", "98.7"]`

<span style="color: var(--heading-h3-color); font-weight: bold;">Function literal</span>
  - a function expression written inline
    - `function() {}`, `() => {}`

<span style="color: var(--heading-h3-color); font-weight: bold;">Regular expression literal</span>
  - a pattern wrapped in forward slashes
    - `/[a-z]+/i`

<span style="color: var(--heading-h3-color); font-weight: bold;">Template literal</span>
  - a string with embedded expressions using backticks
    - `` `Station: ${station}` ``

---

## Literals Are Not Identifiers

A literal is the value itself — not a name that points to a value.

```js
"101.1"         // literal — the value itself
station         // identifier — a name that holds a value
```

---

## Literals Are Not Always Primitives

Primitive literals — `"hello"`, `42`, `true` — produce primitive values.

But object and array literals produce objects:

```js
{ station: "101.1" }  // object literal — produces an object
["101.1", "98.7"]     // array literal — produces an array
```

A literal is about **syntax** — how a value is written.

A primitive is about **type** — what kind of value it is.


---

## Where Literals Fit

A literal always lives inside an expression statement or inside the expression part of a non-expression statement.

```js
let x = "101.1"       // non-expression statement — "101.1" is a literal expression inside it
if (x === "101.1")    // non-expression statement — "101.1" is a literal expression inside it
console.log("101.1")  // expression statement — "101.1" is a literal expression inside it
```

---

## The Precise Chain

- A literal is always an expression
- That expression is always part of a statement
- That statement is either an expression statement or a non-expression statement


---

## Where Literals Fit

A literal is one of the smaller building blocks.

It is an expression — a piece of a statement that produces a value.

It is never a complete instruction on its own.

```js
"101.1"                 // not a complete instruction — just an expression
let x = "101.1"        // complete instruction — "101.1" is a building block inside it
console.log("101.1")   // complete instruction — "101.1" is a building block inside it
