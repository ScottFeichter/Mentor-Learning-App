# Examples In JS

&nbsp;

The JavaScript ecosystem is replete with both **Terms Of Art** and **Semantic Drift**.

---

## JavaScript Terms Of Art

In JS, words like `scope`, `context`, `binding`, and `hoisting` are **terms of art**.

When a **term of art** gets used loosely or interchangeably with other terms, **semantic drift** occurs.

---

## Semantic Drift In JS Terms Of Art

JS has several terms of art that have experienced semantic drift.

- <span style="color: var(--heading-h3-color); font-weight: bold;">context</span>
  - the full environment the JS engine creates to run a piece of code
  - used loosely to mean either execution context or `this`
- <span style="color: var(--heading-h3-color); font-weight: bold;">scope</span>
  - where an identifier is accessible, determined at write time
  - sometimes conflated with context or execution environment
- <span style="color: var(--heading-h3-color); font-weight: bold;">this</span>
  - a keyword automatically bound by the engine to an object at call time
  - shares its name with the English demonstrative pronoun, making it hard to discuss in conversation
- <span style="color: var(--heading-h3-color); font-weight: bold;">binding</span>
  - the connection between an identifier and its value
  - used loosely to mean what `this` is bound to, or what `bind()` does
- <span style="color: var(--heading-h3-color); font-weight: bold;">hoisting</span>
  - declarations are processed at parse time before execution begins
  - described as variables "moving to the top" — nothing physically moves
- <span style="color: var(--heading-h3-color); font-weight: bold;">closure</span>
  - a function that retains access to its outer scope's variable environment after that scope has returned
  - vaguely described as a function "remembering" its scope, which obscures the precise mechanism
- <span style="color: var(--heading-h3-color); font-weight: bold;">reference</span>
  - a pointer to a location in memory where a value is stored
  - used loosely to mean a variable, a pointer, or a value depending on who is talking
- <span style="color: var(--heading-h3-color); font-weight: bold;">variable</span>
  - an identifier declared with `var` or `let` that can be reassigned
  - used as a catch-all for any identifier, even constants and function names
- <span style="color: var(--heading-h3-color); font-weight: bold;">object</span>
  - a collection of key-value pairs stored in the heap
  - everything in JS is loosely called an object, but primitives are not objects
- <span style="color: var(--heading-h3-color); font-weight: bold;">class</span>
  - syntactic sugar over JS prototype-based inheritance
  - treated as traditional OOP classes from languages like Java or Python
- <span style="color: var(--heading-h3-color); font-weight: bold;">prototype</span>
  - an object that another object delegates property lookups to
  - conflated with class-based inheritance from other languages
- <span style="color: var(--heading-h3-color); font-weight: bold;">asynchronous</span>
  - code whose completion is deferred and handled via the event loop
  - conflated with non-blocking, parallel, or concurrent — which are related but distinct concepts
- <span style="color: var(--heading-h3-color); font-weight: bold;">callback</span>
  - a function passed as an argument and invoked by the receiving function
  - used to mean any function passed as an argument, regardless of when or if it is invoked
- <span style="color: var(--heading-h3-color); font-weight: bold;">promise</span>
  - an object representing the eventual completion or failure of an async operation
  - the word implies a future value but the object is created synchronously — the resolution is what is deferred
- <span style="color: var(--heading-h3-color); font-weight: bold;">event loop</span>
  - the mechanism that picks tasks off the queue and pushes them onto the call stack when it is empty
  - often described imprecisely, leading to confusion about when callbacks actually run
- <span style="color: var(--heading-h3-color); font-weight: bold;">immutable</span>
  - a value that cannot be changed after it is created
    - true of primitives
  - `const` is described as making a value immutable
    - it only fixes the binding
    - the value can still be mutated
