# Literals vs Keywords

&nbsp;

**Literals** and **Keywords** (**aka Reserved Words**) are different things.

---

## Reserved Words

**Reserved words** are words the engine claims for its own syntax.

You cannot use them as identifiers.

```js
const let = 5 // SyntaxError — let is a reserved word
```

- `const`, `let`, `var`
- `function`, `class`, `return`
- `if`, `else`, `for`, `while`

---

## Literals

**Literals** are values written directly in code.

They are not words the engine reserves for syntax.
They are representations of values.

```js
42          // number literal
"hello"     // string literal
[]          // array literal
{}          // object literal
```

---

## Where They Overlap

`true`, `false`, and `null` are both reserved words **and** literals.

They are reserved — you cannot use them as identifiers.
They are also literals — they represent values directly.

```js
true   // reserved word + boolean literal
false  // reserved word + boolean literal
null   // reserved word + null literal
```

---

## The Odd One Out — `undefined`

`undefined` looks like a reserved word but is not technically one.

It is a property of `globalThis`.

In practice it behaves like a reserved word — but the engine does not formally reserve it.

```js
undefined  // global property, used as a literal value
```

---

## Summary

| | Reserved Word | Literal |
|---|---|---|
| `const`, `let`, `return` | yes | no |
| `42`, `"hello"`, `[]`, `{}` | no | yes |
| `true`, `false`, `null` | yes | yes |
| `undefined` | no (global property) | yes |
