# Invoke vs Call

&nbsp;

**Call** and **invoke** are used interchangeably in the JS community.

There is no established distinction between them.

---

## Origins

### Call

Plain English.

Also the actual JS method name — `Function.prototype.call`.

The call stack is named after the act of calling a function — every time you call a function, a frame gets pushed onto the stack.

### Invoke

From Latin *invocare* — to call upon.

Used in formal and technical writing.

"Invoke a function" sounds more precise and academic.

---

## Soft Distinction In Practice

There is no defined rule — but there is a stylistic drift:

- **call** tends to appear in runtime and mechanical contexts
  - "the function gets called"
  - "the call stack"
  - "called at call time"

- **invoke** tends to appear in formal or descriptive contexts
  - "invoking a callback"
  - "the function is invoked with these arguments"

This is stylistic, not a defined rule.

---

## What They Do Not Mean

They do not distinguish between:

- code as written vs code as executed
- stack behavior vs source code appearance

Both words refer to the same thing — causing a function to execute.

---

## Key Idea

The precision is not in the word choice between call and invoke.

The precision is in understanding *when* and *how* a function executes — which is what the call stack and execution context describe.
