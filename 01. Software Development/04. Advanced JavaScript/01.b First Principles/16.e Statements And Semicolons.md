# Statements And Semicolons

&nbsp;

Statements end with semicolons — but not all statements use one.

---

## The Rule

Statements that end with a **block** `{}` do not get a semicolon.

Statements that end with an **expression** or **declaration** do.

```js
let x = 5;            // ends with expression — semicolon
x + 1;                // expression statement — semicolon
if (x > 0) {}         // ends with block — no semicolon
function greet() {}   // ends with block — no semicolon
for (let i = 0) {}    // ends with block — no semicolon
```

---

## Automatic Semicolon Insertion

JS has **Automatic Semicolon Insertion (ASI)**.

The engine inserts semicolons for you in most cases.

In practice the language often does not care whether you write them or not.

---

## When ASI Gets It Wrong

ASI has edge cases where it inserts a semicolon in the wrong place — or fails to insert one at all.

```js
const fn = () => {}
(function() {})()     // ASI does NOT insert a semicolon after the first line
                      // engine reads it as fn()(function(){})() — TypeError
```

The engine saw two lines that could be read as one expression and did not insert a semicolon between them.

---

## Semicolons Are Not About Readability

Semicolons are syntactically meaningful — not decorative.

They mark the end of a complete instruction.

They are often optional because of ASI — but occasionally critical when ASI would insert one in the wrong place or not at all.

---

## Community Split

The JS community is divided on semicolons.

- some style guides require them everywhere — explicit and safe
- others omit them and rely on ASI — cleaner but requires knowing the edge cases

Both approaches work if applied consistently.
