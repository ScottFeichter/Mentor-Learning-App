# Primitives vs Literals

&nbsp;

These two terms are often used interchangeably — they are not the same thing.

---

## The Core Distinction

- **Primitive** — a category of *value type*
- **Literal** — a category of *syntax*

A primitive describes *what kind of value* something is.

A literal describes *how a value is written in code*.

---

## Where They Overlap

Every primitive can be written as a literal.

```js
"101.1"   // string literal — produces a string primitive
42        // number literal — produces a number primitive
true      // boolean literal — produces a boolean primitive
null      // null literal — produces a null primitive
undefined // undefined literal — produces an undefined primitive
42n       // bigint literal — produces a bigint primitive
```

In these cases, the literal *is* the primitive.

The syntax and the type happen to match.

---

## Where They Diverge

Not all literals produce primitives.

```js
{ station: "101.1" }   // object literal — produces an object, not a primitive
["101.1", "98.7"]      // array literal — produces an array, not a primitive
() => {}               // function literal — produces a function, not a primitive
/[a-z]+/i              // regex literal — produces a RegExp object, not a primitive
```

And not all primitives come from literals.

```js
Symbol()               // produces a symbol primitive — but Symbol() is a function call, not a literal
String(42)             // produces a string primitive — but String() is a function call, not a literal
```

---

## Summary

|  | Primitive | Literal |
|---|---|---|
| What it describes | A value type | A syntax form |
| Can be an object | No | Yes |
| Always written directly in code | No | Yes |
| Overlap | Primitive literals | Primitive literals |

---

## Key Idea

A **literal** is about how you write something.

A **primitive** is about what type of value it is.

They overlap when you write a primitive value directly in code — but they are describing different things.
