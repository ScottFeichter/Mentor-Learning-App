# References & Pointers

&nbsp;

A JS **reference** and a C **pointer** are closely related — but not the same thing.

---

## Short Answer

A JS **reference** *is* a **pointer** under the hood.

- The engine stores a memory address.

But the term **reference** is used because you never interact with that address directly.

- It is an abstraction over the **pointer** concept.

---

## What They Share

Both are a level of indirection.

- Instead of holding a value directly, they hold a way to reach it.

- Both point to something stored elsewhere in memory.

---

## How They Differ

### Pointer (C / C++)

A **pointer** is explicit and manual.

- You can see and manipulate the memory address directly
- You can do pointer arithmetic — `ptr + 1` moves to the next memory slot
- You can have a pointer to a pointer
- You control allocation and deallocation

### Reference (JS)

A **reference** is implicit and managed.

- You never see the memory address — the engine handles it
- No arithmetic, no dereferencing syntax like `*ptr`
- The garbage collector handles deallocation
- You cannot have a reference to a reference

---

## The Practical Overlap

```js
const a = { name: "Ada" }
const b = a
```

Both `a` and `b` hold the same internal address to the same object on the heap.

- That is **pointer**-like behavior.

- JS just calls it a **reference** and hides the machinery.
