# Reference Types

&nbsp;

A **reference type** is any value that is stored on the heap and accessed through a reference.

The identifier does not hold the value directly.
It holds a memory address that points to where the value lives.

---

## The Reference Types In JS

- <span style="color: var(--heading-h3-color); font-weight: bold;">Object</span>
  - a collection of key-value pairs
    - `{ station: "101.1", volume: 5 }`
- <span style="color: var(--heading-h3-color); font-weight: bold;">Array</span>
  - an ordered collection of values
    - `["101.1", "98.7"]`
- <span style="color: var(--heading-h3-color); font-weight: bold;">Function</span>
  - a callable object — functions are objects under the hood
    - `function greet() {}`, `() => {}`
- <span style="color: var(--heading-h3-color); font-weight: bold;">Class instance</span>
  - an object created with `new`
    - `new Radio("101.1")`, `new Date()`
- <span style="color: var(--heading-h3-color); font-weight: bold;">Built-in objects</span>
  - objects provided by the JS engine
    - `Map`, `Set`, `WeakMap`, `WeakRef`
    - `Promise`, `RegExp`, `Error`

---

## How References Work

When you assign a reference type to an identifier, the identifier holds the memory address — not the value itself.

```
Stack                    Heap
─────────────────────    ──────────────────────────
radio  → [0x001]    →    { station: "101.1" }
```

When you copy a reference type, you copy the address — not the object.

```js
const radio = { station: "101.1" }
const copy = radio

copy.station = "98.7"

console.log(radio.station) // "98.7" — same object
console.log(copy.station)  // "98.7" — same object
```

Both identifiers point to the same object in memory.

---

## Reference Types Are Mutable

Unlike primitives, reference types can be changed after they are created.

```js
const radio = { station: "101.1" }
radio.station = "98.7"   // allowed — mutating the object
radio.volume = 5         // allowed — adding a new property
```

`const` locks the binding — not the value.

`radio` cannot be pointed at a new object.
But the object it points to can still be changed.

---

## Reference Types And Equality

Two reference types are only equal if they point to the same object in memory.

```js
const a = { station: "101.1" }
const b = { station: "101.1" }

console.log(a === b) // false — different objects in memory

const c = a
console.log(a === c) // true — same reference
```

---

## Primitives vs Reference Types

| | Primitive | Reference Type |
|---|---|---|
| Stored | directly in the binding | on the heap |
| Copied | by value — independent copy | by reference — same object |
| Mutable | no | yes |
| Equality | compares value | compares memory address |
