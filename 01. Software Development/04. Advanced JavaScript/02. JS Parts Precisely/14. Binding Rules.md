# Binding Rules

&nbsp;

A **binding** is the connection between an identifier and its value.

---

Each keyword defines different rules for how that binding can change.

## The Rules

### const
- `const` — the binding is **fixed**
  - cannot be rebound to a new value
  - cannot be redeclared in the same scope

### let
- `let` — the binding is **flexible**
  - can be rebound (reassigned)
  - cannot be redeclared in the same scope

### var
- `var` — the binding is **loose**
  - can be rebound (reassigned)
  - can be redeclared in the same scope

### function
- `function` — binds the function name in the current scope
  - can be rebound and redeclared (behaves like `var`)
  - hoisted to the top of its scope

### class
- `class` — binds the class name in the current scope
  - cannot be rebound or redeclared (behaves like `let`)
  - not hoisted

### function parameters
- function parameters — each parameter is a binding local to that function
  - can be rebound inside the function
  - scoped to the function body

### new
- `new` — creates a binding to a new object instance
  - `this` inside the constructor is bound to the new object
  - the identifier that receives it follows whatever keyword declared it (`const`, `let`, `var`)

### import
- `import` — creates a **read-only** binding
  - cannot be rebound or redeclared
  - similar to `const` but the binding is live — it reflects updates from the exporting module
  - ESM only
- `require()` — the CJS equivalent of `import`
  - not a keyword — it is a function call
  - the binding rules of the receiving identifier apply (`const`, `let`, `var`)
  - can be rebound or redeclared depending on which keyword is used

## Loops

The binding keyword used in a loop affects how the binding behaves across iterations.

### var in a loop

One binding is shared across all iterations.

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0)
}
// 3, 3, 3
```

By the time the callbacks run, `i` has already incremented to `3`.

This is the classic closure bug.

### let in a loop

A fresh binding is created for each iteration.

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0)
}
// 0, 1, 2
```

Each callback closes over its own `i`.

### const in a loop

Works in `for...of` and `for...in` — a new binding is created each iteration.

```js
for (const station of ["101.1", "98.7", "92.3"]) {
  console.log(station)
}
// 101.1, 98.7, 92.3
```

Does not work in a standard `for` loop — the binding cannot be reassigned.

```js
for (const i = 0; i < 3; i++) {} // TypeError
```
