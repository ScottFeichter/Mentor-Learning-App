# Changing Value

&nbsp;

There are several distinct ways a value or binding can change in JS.

---

## Declaring

Introducing the identifier into scope.

No value is assigned — it holds `undefined`.

```js
let station
```

---

## Assigning

Giving the identifier its first value after declaring.

```js
let station
station = "101.1"
```

---

## Initializing

Declaring and assigning in the same statement.

```js
let station = "101.1"
```

`const` requires initialization — it cannot be declared without a value.

---

## Reassigning

Any subsequent value change after the first assignment.

```js
let station = "101.1"
station = "98.7"
```

The identifier stays the same. The value it points to changes.

---

## Rebinding

Pointing an identifier at a completely different value.

Reassigning and rebinding mean the same thing.

The term **rebinding** emphasizes that the connection between the identifier and the value is what changed.

---

## Redeclaring

Declaring an identifier that already exists in the same scope.

```js
var x = 1
var x = 2 // allowed with var

let y = 1
let y = 2 // SyntaxError
```

---

## Mutating

Changing the contents of a value without changing the binding.

The identifier still points to the same object or array in memory.

```js
const radio = { station: "101.1" }
radio.station = "98.7" // mutating — rebinding a property key
radio.volume = 5       // mutating — adding a new property key binding
radio = {}             // TypeError — cannot rebind a const identifier
```

Array indices work the same way.

```js
const stations = ["101.1", "98.7"]
stations[0] = "92.3"  // mutating — rebinding index 0
stations.push("88.1") // mutating — adding a new index binding
stations = []         // TypeError — cannot rebind a const identifier
```

---

## Summary

| Term | What Changes |
| :--- | :--- |
| Declaring | introduces the identifier into scope, value is `undefined` |
| Assigning | gives the identifier its first value |
| Initializing | declares and assigns in the same statement |
| Reassigning | any subsequent value change after the first assignment |
| Rebinding | same as reassigning — emphasizes the binding |
| Redeclaring | re-introduces the identifier in the same scope |
| Mutating | changes the contents of the value, not the binding |
