# Linked Lists

- Take up more space than arrays and are slower in almost every way
- Ordered sequence of nodes
- They can be out of order in memory but the pointers give them order
  - Not required to be in contiguous blocks of memory
  - Take up more memory than an array
  - To visit any node you need to come from the previous node
  - To visit the nth node, you must traverse through all prior nodes — O(n)

## Structure

- Each node consists of a **data value** and a **pointer** to the next node
- The linked list itself is just a pointer to the first node (the **head node**)
- The list continues until it reaches a **null** node pointer (the **tail node**)
- If the head pointer is itself null, the linked list is empty

## Pointers

- Pointers are hidden in JavaScript
- Allow for storage of complex, multi-dimensional data in linear memory
- Enable: multi-type arrays, pass-by-reference, graph traversal, and more

## Time Complexity

| Operation | Complexity |
|-----------|-----------|
| addToHead() | O(1) |
| addToTail() | O(n) — can be O(1) with a tail pointer |
| removeFromHead() | O(1) |
| removeFromTail() | O(n) |
| traversal | O(n) |
| search | O(1) to O(n) |

Space complexity: O(n)

## Optimization

- Adding a **tail pointer** makes addToTail() O(1) — trades space for time
- Removing from tail is still O(n) in a singly linked list because you can't traverse backwards
