# Encapsulation Strategies

&nbsp;

**Encapsulation** is controlling access to data — deciding what is exposed and what is hidden.

---

## Strategies In JS

JS encapsulation is limited compared to other languages. These are the main approaches:

### Closure

The most idiomatic JS approach. Variables declared inside a function are inaccessible from outside — you expose only what you return.

```js
function makeCounter() {
  let count = 0;
  return {
    increment() { count++; },
    getCount()  { return count; }
  };
}

const counter = makeCounter();
counter.increment();
console.log(counter.getCount()); // 1
console.log(counter.count);      // undefined — count is hidden
```

### Private Class Fields `#`

Introduced in ES2022. Properties prefixed with `#` are truly private to the class and throw an error if accessed from outside.

```js
class BankAccount {
  #balance = 0;

  deposit(amount) { this.#balance += amount; }
  getBalance()    { return this.#balance; }
}

const account = new BankAccount();
account.deposit(100);
console.log(account.getBalance()); // 100
console.log(account.#balance);     // SyntaxError — truly private
```

### Underscore Convention `_`

Prefixing a property with `_` signals "treat this as private" but does not enforce anything. Still widely seen in older codebases.

```js
class Person {
  constructor(name) {
    this._name = name; // convention only — still accessible
  }
}

const p = new Person('Alice');
console.log(p._name); // 'Alice' — nothing is actually hidden
```

### WeakMap

An older pattern where private data is stored in a WeakMap keyed by the instance, keeping it out of the object itself.

```js
const _balance = new WeakMap();

class BankAccount {
  constructor() { _balance.set(this, 0); }
  deposit(amount) { _balance.set(this, _balance.get(this) + amount); }
  getBalance()    { return _balance.get(this); }
}

const account = new BankAccount();
account.deposit(50);
console.log(account.getBalance()); // 50
console.log(account.balance);      // undefined — not on the object
```

---

## Summary

| Strategy | Actually Private | Modern |
|---|---|---|
| Closure | yes | yes |
| `#` private fields | yes | yes |
| `_` convention | no | no |
| WeakMap | yes | no |

Closure and `#` private fields are the two that actually enforce access restriction. Most modern code uses `#` for class-based encapsulation and closure for functional encapsulation.

---

## Encapsulation and OOP

Closure-based encapsulation is **functional** encapsulation, not OOP encapsulation. OOP encapsulation specifically refers to an object controlling access to its own state — which in JS means `#` private fields on a class.

Closure achieves the same outcome (hidden data) but through a different mechanism and philosophy — it's a function scope thing, not an object/class thing. The module pattern and factory functions use closure this way, and those are considered functional or procedural patterns, not OOP.

- `#` private fields = OOP encapsulation
- closure = functional encapsulation

Same goal, different paradigm.
