# JavaScript Identifiers and References

## Are All Identifiers References?

No, not all identifiers in JavaScript are references. It depends on the **data type**:

## Primitive Identifiers (Store Values)
```javascript
let name = "John";     // name stores the actual string value
let age = 25;          // age stores the actual number value
let isActive = true;   // isActive stores the actual boolean value
```

## Reference Identifiers (Store References)
```javascript
let person = { name: "John" };  // person stores a reference to the object
let numbers = [1, 2, 3];        // numbers stores a reference to the array
let myFunc = function() {};     // myFunc stores a reference to the function
```

## The Key Difference

**Primitives (string, number, boolean, null, undefined, symbol, bigint):**
- Identifier stores the actual value
- Assignment creates a copy

**Objects (objects, arrays, functions, dates, etc.):**
- Identifier stores a reference (memory address)
- Assignment copies the reference, not the object

## Example
```javascript
// Primitive - value stored
let a = 5;
let b = a;  // b gets copy of value
a = 10;
console.log(b); // Still 5

// Object - reference stored  
let obj1 = { x: 5 };
let obj2 = obj1;  // obj2 gets copy of reference
obj1.x = 10;
console.log(obj2.x); // Now 10 - same object
```

## What is a Reference?

A **reference** is a pointer to where data is stored in memory, rather than the actual data itself.

**Function References:**
```javascript
function sayHello() {
  return "Hello!";
}

let myFunc = sayHello;  // myFunc now references the same function
myFunc();               // Calls the function: "Hello!"
```

## Summary

Identifiers either store **values** (primitives) or **references** (objects), depending on what type of data they hold. This distinction is crucial for understanding how data is passed and modified in JavaScript.
