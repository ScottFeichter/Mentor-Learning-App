# Scope Review

&nbsp;

**Scope** determines where a <span class="subheading-highlight">declared identifier</span> is accessible in your code.

An identifier can be a variable, constant, function, class, or object.

Which parts of the program can read or write an identifier is defined by **scope**.

## Identifiers Live In Scopes

Every identifier **lives in** the scope of the construct that declared it.

That construct might be a block, a function, a module, or the global environment.

## Constructs That Create Scope

Not everything in JS creates its own scope.

These constructs **do** create scope:

- `{}` blocks — for `let` and `const`
- Functions — for `var`, and all identifiers declared inside
- Modules — top-level declarations stay file-scoped
- Classes — class body has its own scope

These constructs **do not** create scope:

- Object literals `{}`
- Plain expressions
- `if`, `for`, `while` blocks only affect `var` — not `let`/`const`

## The Scope Chain

<span class="js-yellow">JS</span> resolves identifiers by looking outward through nested **scopes**.

If an identifier isn't found in the current **scope**, <span class="js-yellow">JS</span> looks in the parent **scope**.

If still not found then its parent, and so on until it reaches the global **scope**.

If it still isn't found, a <span class="red-bold">ReferenceError</span> is thrown.

The scope chain always ends at <span class="purple-bold">globalThis</span>.

```js
const x = 'global'

function outer() {
  const y = 'outer'

  function inner() {
    const z = 'inner'
    console.log(x) // found in global scope
    console.log(y) // found in outer scope
    console.log(z) // found in local scope
  }
}
```
