# Scope Chain

&nbsp;

When the JS engine looks up an identifier, it does not just check the current scope.

It walks **outward** through a chain of scopes until it finds the identifier or runs out of scopes.

This chain is called the **scope chain**.

---

## How It Works

1. The engine checks the current scope first
2. If not found, it moves to the parent scope
3. It keeps moving outward until it reaches the global scope
4. If still not found, a `ReferenceError` is thrown

```js
const x = 'global'

function outer() {
  const y = 'outer'

  function inner() {
    const z = 'inner'
    console.log(z) // found in current scope
    console.log(y) // found in outer scope
    console.log(x) // found in global scope
  }

  inner()
}

outer()
```

---

## The Chain Is Set at Write Time

The scope chain is determined by where functions are **written** in the code, not where they are called.

This is called **lexical scoping**.

```js
const station = "101.1"

function getStation() {
  console.log(station) // looks up the chain — finds station in global scope
}

function run() {
  const station = "98.7"
  getStation() // does NOT use run's station — getStation's chain was set where it was written
}

run() // logs "101.1"
```

---

## The Chain Always Ends at globalThis

Every scope chain ends at the global scope.

The global scope lives on `globalThis`.

If an identifier is not found anywhere in the chain, a `ReferenceError` is thrown.

```js
console.log(missing) // ReferenceError: missing is not defined
```

---

## Inner Scopes Cannot Be Seen From Outer Scopes

The chain only goes outward — never inward.

```js
function outer() {
  function inner() {
    const secret = 'hidden'
  }
  console.log(secret) // ReferenceError — outer cannot see inner's scope
}
```
