# Why API Is Confusing

&nbsp;

**API** is an overloaded term but it always refers to the same thing:

- <span class="subheading-highlight">An interface to call already written code</span>.

- <span class="subheading-highlight">Without needing to know how the code works internally</span>.

## Why Confusion?

This concept applies at every level of programming.

From a single function to an entire web service.

### API Describes:
- <span class="olive-bold">Tiny Things</span> <span class="muted">(a single function)</span>
- <span class="olive-bold">Big Things</span> <span class="muted">(entire web services)</span>
- <span class="olive-bold">Local Things</span> <span class="muted">(library functions)</span>
- <span class="olive-bold">Remote Things</span> <span class="muted">(HTTP endpoints)</span>

But they're all the same concept: <span class="subheading-highlight">a way to call pre written code</span>.

### Simple Rule:

Whenever you see **API**, replace it with <span class="purple-bold">functions I can call:</span>

- <span class="olive-bold">Node</span> **API** = <span class="purple-bold">Node functions I can call</span>
- <span class="olive-bold">DOM</span> **API** = <span class="purple-bold">DOM functions I can call</span>
- <span class="olive-bold">React</span> **API** = <span class="purple-bold">React functions I can call</span>
- <span class="olive-bold">Browser</span> **API** = <span class="purple-bold">Browser functions I can call</span>
