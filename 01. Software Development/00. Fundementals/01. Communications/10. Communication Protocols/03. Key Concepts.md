# Key Concepts

&nbsp;

A few core concepts appear across all communication protocols and are worth understanding before diving into specific ones.

## Handshake

A handshake is an initial exchange between two parties to establish a connection and agree on parameters before data is transmitted.

TCP uses a three-way handshake. TLS uses its own handshake on top of that.

## Request and Response

Many protocols follow a request-response pattern — one party sends a request and the other sends a response.

HTTP is the most familiar example of this pattern.

## Stateless vs Stateful

- <span class="olive-bold">Stateless</span> — each request is independent, the server retains no memory of previous requests <span class="muted">(HTTP is stateless)</span>
- <span class="olive-bold">Stateful</span> — the connection maintains context across multiple exchanges <span class="muted">(TCP is stateful)</span>

## Connection-Oriented vs Connectionless

- <span class="olive-bold">Connection-oriented</span> — a connection is established before data is sent and torn down after <span class="muted">(TCP)</span>
- <span class="olive-bold">Connectionless</span> — data is sent without establishing a connection first <span class="muted">(UDP)</span>

## Ports

Protocols are associated with port numbers that identify which service on a machine should receive incoming data.

HTTP uses port 80, HTTPS uses 443, SSH uses 22.

## RFC

A Request for Comments (RFC) is the document format used to define internet standards.

Most protocols are formally specified in one or more RFCs published by the IETF.
