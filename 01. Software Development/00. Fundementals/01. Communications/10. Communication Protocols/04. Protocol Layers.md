# Protocol Layers

&nbsp;

Protocols are organized into layers — each layer handles a specific aspect of communication and relies on the layer below it.

Layering allows protocols to be developed, replaced, and combined independently.

## The OSI Model

The OSI (Open Systems Interconnection) model defines 7 layers:

| Layer | Name | Responsibility |
|---|---|---|
| 7 | Application | User-facing protocols — HTTP, DNS, SMTP |
| 6 | Presentation | Data formatting, encryption, compression |
| 5 | Session | Managing sessions between applications |
| 4 | Transport | End-to-end delivery — TCP, UDP |
| 3 | Network | Addressing and routing — IP |
| 2 | Data Link | Node to node transfer — Ethernet, MAC |
| 1 | Physical | Raw bit transmission — cables, signals |

## The TCP/IP Model

The TCP/IP model is the practical model the internet actually uses — it collapses the OSI layers into four:

| Layer | Covers |
|---|---|
| Application | OSI layers 5, 6, 7 |
| Transport | OSI layer 4 |
| Internet | OSI layer 3 |
| Network Access | OSI layers 1, 2 |

## Why Layers Matter

Each layer communicates with the layer directly above and below it.

A web developer works at the Application layer — HTTP — without needing to know how TCP handles reliability or how IP handles routing.

Each layer abstracts the complexity of the layers beneath it.
