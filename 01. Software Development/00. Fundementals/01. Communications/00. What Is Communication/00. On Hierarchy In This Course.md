# On Hierarchy In This Course

&nbsp;

There is no perfect hierarchy for organizing these topics.

## Why Hierarchy Breaks Down

Many of these fields are self-referencing.

Computer Science uses communication to transmit code.

Communications uses computers to transmit signals.

Telecommunications depends on software built with Computer Science.

Information Technology manages the systems that all of the above run on.

Each field contains concepts that belong to another field.

Any hierarchy you draw will have exceptions.

## The Hierarchy We Use

This course organizes topics in the following order:

- <span class="olive-bold">Communications</span> — the broadest context
- <span class="olive-bold">Networks</span> — the infrastructure that connects systems
- <span class="olive-bold">Computer Science</span> — the technical branch we focus on
- <span class="olive-bold">Information Technology</span> — the applied layer within that branch

This was chosen not because it is objectively correct, but because it is the most useful sequence for learning.

You need to understand how information moves before you can understand how devices are connected.

You need to understand how devices are connected before you can understand how computers process and exchange data.

You need to understand how computers work before you can understand how to deploy and manage them.

## The Takeaway

Treat the hierarchy as a learning path, not a definitive map of reality.

The goal is to build understanding progressively — each layer giving you the context needed to make sense of the next.
