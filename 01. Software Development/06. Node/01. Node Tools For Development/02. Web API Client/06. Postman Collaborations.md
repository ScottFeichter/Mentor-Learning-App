# Postman Collaborations

&nbsp;

**Postman** has built-in tools for sharing and collaborating on API work with a team.

## Workspaces

<div class="indent">

### What They Are

A workspace is a shared environment where a team can access the same collections, environments, and history.

### Types

- **Personal** — only visible to you
- **Team** — shared with members of your **Postman** team
- **Public** — visible to anyone with the link

### How To Use

Create a team workspace and invite collaborators by email.

All shared collections and environments live inside the workspace.

</div>

## Sharing Collections

<div class="indent">

### Via Workspace

Move a collection into a team workspace to make it accessible to all members.

Changes sync automatically for everyone in the workspace.

### Via Export

Export a collection as a `.json` file and share it directly.

Teammates import it into their own **Postman** using **File → Import**.

### Via Link

Generate a public link to a collection from the collection's share menu.

Anyone with the link can view and fork the collection.

</div>

## Environments

<div class="indent">

### What They Are

Environments are sets of variables that can be swapped out without changing requests.

### Sharing Environments

Export an environment as a `.json` file and share it alongside a collection.

This ensures teammates use the same variable values when running requests.

</div>

## Forking

<div class="indent">

### What It Is

Forking creates a personal copy of a collection from a shared workspace.

### Why Use It

It lets you make changes without affecting the original shared collection.

You can submit a **pull request** to merge your changes back into the source collection.

</div>
