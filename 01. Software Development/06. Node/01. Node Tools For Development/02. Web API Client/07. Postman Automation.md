# Postman Automation

&nbsp;

**Postman** supports scripting and automation to reduce manual testing work.

## Pre-Request Scripts

<div class="indent">

### What They Are

Pre-request scripts run JavaScript before a request is sent.

### Common Uses

- Generating a timestamp to include in a request header
- Setting a variable dynamically before the request fires
- Refreshing an auth token before it expires

### Example

```js
pm.environment.set("timestamp", Date.now());
```

</div>

## Tests

<div class="indent">

### What They Are

Test scripts run JavaScript after a response is received.

They let you assert that the response matches what you expect.

### Common Assertions

```js
pm.test("Status is 200", () => {
  pm.response.to.have.status(200);
});

pm.test("Response has user id", () => {
  const body = pm.response.json();
  pm.expect(body.id).to.be.a("number");
});
```

### Why Use Them

Tests turn **Postman** from a manual tool into an automated API verification tool.

They run every time the request is sent, catching regressions immediately.

</div>

## Variables In Automation

<div class="indent">

### Setting Variables From Responses

You can extract values from a response and store them as variables for use in later requests.

```js
const body = pm.response.json();
pm.environment.set("userId", body.id);
```

### Chaining Requests

This lets you chain requests — for example, create a user, capture the returned `id`, then use it in a follow-up request to fetch that user.

</div>

## Newman

<div class="indent">

### What It Is

**Newman** is **Postman**'s command-line collection runner.

### Why Use It

It lets you run **Postman** collections outside the UI — in a terminal or as part of a CI/CD pipeline.

### Basic Usage

```bash
newman run collection.json --environment env.json
```

### Use Cases

- Running API tests automatically on every code push
- Integrating **Postman** tests into GitHub Actions or other CI tools

</div>
