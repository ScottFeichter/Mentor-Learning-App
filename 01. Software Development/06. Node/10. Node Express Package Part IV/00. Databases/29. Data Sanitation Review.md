# Data Sanitization

**Data sanitization** cleans and transforms input data to remove or neutralize potentially harmful content.

### Purpose
- **Prevent security attacks** (XSS, SQL injection)
- **Normalize data format** for consistency
- **Remove unwanted characters** or content
- **Prepare data for safe storage/display**

### Common Sanitization Techniques

#### HTML/XSS Prevention
```javascript
const DOMPurify = require('dompurify');

// Remove dangerous HTML tags and attributes
const cleanHTML = DOMPurify.sanitize(userInput);

// Escape HTML entities
function escapeHtml(text) {
  return text
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;');
}
```

#### Input Cleaning
```javascript
// Trim whitespace and normalize
function sanitizeString(input) {
  return input.trim().toLowerCase();
}

// Remove special characters
function sanitizeAlphanumeric(input) {
  return input.replace(/[^a-zA-Z0-9]/g, '');
}

// Sanitize phone number
function sanitizePhone(phone) {
  return phone.replace(/\D/g, ''); // Keep only digits
}
```

## Validation vs Sanitization

| Aspect | Validation | Sanitization |
|--------|------------|--------------|
| **Purpose** | Check if data is acceptable | Clean/transform data |
| **Action** | Accept or reject | Modify input |
| **Timing** | Before processing | Before validation/storage |
| **Result** | Pass/fail with errors | Modified data |
| **Example** | "Email format invalid" | Convert "JOHN@EMAIL.COM" to "john@email.com" |

## Best Practices

### Validation Best Practices
- **Validate at all three layers** — client, server, and database (defense in depth)
- **Never trust client-side only** — it can be bypassed entirely
- **Fail fast** - validate early in the process
- **Provide clear error messages** to users
- **Use whitelist approach** - define what's allowed, not what's forbidden

### Sanitization Best Practices
- **Sanitize before validation** to ensure consistent format
- **Context-aware sanitization** - different rules for different uses
- **Preserve user intent** when possible
- **Log sanitization actions** for security monitoring

## Implementation Example

```javascript
// Combined validation and sanitization
function processUserInput(data) {
  // 1. Sanitize first
  const sanitized = {
    name: data.name?.trim(),
    email: data.email?.toLowerCase().trim(),
    age: parseInt(data.age)
  };

  // 2. Then validate

  return { sanitized, errors };
}
```

## Security Considerations

- **Never rely on client-side validation alone**
- **Sanitize data based on output context** (HTML, SQL, etc.)
- **Use parameterized queries** to prevent injection attacks
- **Implement rate limiting** to prevent abuse
- **Log validation failures** for security monitoring

Both validation and sanitization are essential for building secure, reliable applications that handle user input safely.
