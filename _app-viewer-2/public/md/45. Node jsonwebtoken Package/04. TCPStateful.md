# TCP Stateful Connection

## What is TCP?

TCP (Transmission Control Protocol) is a **stateful** connection-oriented protocol that ensures reliable data transmission between two computers.

## What Does "Stateful" Mean?

**Stateful** means TCP maintains information about the connection throughout its lifetime.

### TCP Tracks:
- Connection state (established, closing, closed)
- Sequence numbers (order of packets)
- Acknowledgments (which packets were received)
- Window size (flow control)
- Retransmission timers

## TCP Three-Way Handshake

Before any data is sent, TCP establishes a connection:

```
Client                          Server
  |                               |
  |-------- SYN (seq=100) ------->|  1. Client: "Let's connect"
  |                               |
  |<--- SYN-ACK (seq=300, ack=101)|  2. Server: "OK, I'm ready"
  |                               |
  |-------- ACK (ack=301) ------->|  3. Client: "Confirmed"
  |                               |
  |<====== Connection Ready =====>|
  |                               |
  |<====== Data Transfer ========>|
```

### Why This Makes TCP Stateful:
- Both sides remember the connection exists
- Both track sequence numbers
- Both maintain buffers for data
- Connection persists until explicitly closed

## TCP Connection Lifecycle

```
1. CLOSED → No connection
2. SYN_SENT → Client sent connection request
3. SYN_RECEIVED → Server received request
4. ESTABLISHED → Connection active (data transfer)
5. FIN_WAIT → Closing connection
6. CLOSED → Connection terminated
```

Each side maintains this state information.

## How HTTP Sits on Top of TCP

HTTP is an **application layer** protocol that uses TCP for transport.

### The Protocol Stack

```
┌─────────────────────────────┐
│   Application Layer         │
│   HTTP (Stateless)          │  ← Your web request/response
├─────────────────────────────┤
│   Transport Layer           │
│   TCP (Stateful)            │  ← Reliable connection
├─────────────────────────────┤
│   Network Layer             │
│   IP                        │  ← Routing
├─────────────────────────────┤
│   Link Layer                │
│   Ethernet/WiFi             │  ← Physical transmission
└─────────────────────────────┘
```

### HTTP Request Flow

```
1. Browser makes HTTP request
   ↓
2. TCP connection established (if not already open)
   ↓
3. HTTP request sent over TCP connection
   ↓
4. Server receives request via TCP
   ↓
5. Server sends HTTP response over TCP
   ↓
6. Browser receives response via TCP
   ↓
7. TCP connection closed (or kept alive)
```

## Example: HTTP Request Over TCP

### Step 1: TCP Connection
```
Client                          Server
  |                               |
  |-------- TCP Handshake ------->|
  |<------ Connection Ready ------|
```

### Step 2: HTTP Request (Sent Over TCP)
```javascript
// HTTP request (application layer)
GET /api/users HTTP/1.1
Host: example.com
Connection: keep-alive

// This is broken into TCP segments and sent
```

### Step 3: TCP Ensures Delivery
```
Client                          Server
  |                               |
  |--- Segment 1 (seq=100) ------>|
  |<------ ACK (ack=101) ---------|
  |                               |
  |--- Segment 2 (seq=101) ------>|
  |<------ ACK (ack=102) ---------|
```

### Step 4: HTTP Response (Received Over TCP)
```javascript
// HTTP response (application layer)
HTTP/1.1 200 OK
Content-Type: application/json

{"users": [...]}

// Received via TCP segments
```

## Key Differences: TCP vs HTTP

| Feature | TCP | HTTP |
|---------|-----|------|
| Layer | Transport | Application |
| State | Stateful | Stateless |
| Purpose | Reliable delivery | Request/response |
| Connection | Persistent | Per request* |
| Tracks | Packets, order | Nothing between requests |

*HTTP/1.1 can reuse TCP connections with `Connection: keep-alive`

## HTTP is Stateless, TCP is Stateful

### TCP (Stateful)
```javascript
// TCP maintains connection state
const net = require('net');

const client = net.connect({ port: 80, host: 'example.com' }, () => {
  console.log('Connected to server'); // TCP knows connection exists
  client.write('GET / HTTP/1.1\r\nHost: example.com\r\n\r\n');
});

client.on('data', (data) => {
  console.log(data.toString());
});

// TCP tracks this connection until closed
```

### HTTP (Stateless)
```javascript
// HTTP doesn't remember previous requests
const http = require('http');

// Request 1
http.get('http://example.com/page1', (res) => {
  console.log('Got page 1');
});

// Request 2 - HTTP has no memory of Request 1
http.get('http://example.com/page2', (res) => {
  console.log('Got page 2'); // Doesn't know about page 1
});

// Each HTTP request is independent
// (Even if they use the same TCP connection)
```

## Real-World Example

### Visiting a Website

```
1. Browser: "I want to visit example.com"
   ↓
2. TCP: Establishes connection to example.com:443
   - Three-way handshake
   - Connection state: ESTABLISHED
   ↓
3. HTTP: Sends GET request over TCP connection
   GET / HTTP/1.1
   Host: example.com
   ↓
4. TCP: Breaks request into segments, sends, tracks delivery
   ↓
5. Server: Receives request via TCP
   ↓
6. HTTP: Server processes request (stateless)
   ↓
7. TCP: Sends response segments back
   ↓
8. Browser: Receives response via TCP
   ↓
9. TCP: Connection kept alive or closed
```

## Why This Matters

### For Developers:
```javascript
// You write HTTP code (stateless)
app.get('/api/users', (req, res) => {
  res.json({ users: [] });
  // You don't manage TCP connection
});

// TCP handles:
// - Connection establishment
// - Packet ordering
// - Retransmission if packets lost
// - Connection teardown
```

### For Understanding Performance:
- **TCP handshake adds latency** (3 round trips)
- **HTTP/1.1 keep-alive** reuses TCP connections
- **HTTP/2** multiplexes multiple requests over one TCP connection
- **HTTPS** adds TLS handshake on top of TCP

## Summary

**TCP (Stateful)**:
- Maintains connection state
- Tracks packet delivery
- Ensures reliable transmission
- Connection-oriented

**HTTP (Stateless)**:
- Sits on top of TCP
- Each request is independent
- Doesn't remember previous requests
- Uses TCP for reliable delivery

**Relationship**:
- HTTP relies on TCP for transport
- TCP provides the "pipe" for HTTP messages
- HTTP doesn't manage connections, TCP does
- One TCP connection can carry multiple HTTP requests (keep-alive)
