# JWT Signature

## What is it?

The JWT Signature is the third and final part of a JSON Web Token.

It ensures the token hasn't been tampered with and verifies the sender's identity.

The signature is created by encoding the header and payload, then signing them with a secret key or private key.

## How it's Created

```
HMACSHA256(
  base64UrlEncode(header) + "." + base64UrlEncode(payload),
  secret
)
```

The complete JWT format:
```
[Base64URL(Header)].[Base64URL(Payload)].[Base64URL(Signature)]
```

Example:
```

```

## Signature Algorithms

### Symmetric Algorithms (HMAC)

Uses the same secret key for signing and verification.

**HS256 (HMAC-SHA256):**
```javascript
const signature = HMACSHA256(
  base64UrlEncode(header) + "." + base64UrlEncode(payload),
  "your-256-bit-secret"
);
```

**Pros:**
- Fast and simple
- Less computational overhead

**Cons:**
- Same key for signing and verifying
- Key must be shared between parties
- Not ideal for distributed systems

### Asymmetric Algorithms (RSA/ECDSA)

Uses a private key to sign and a public key to verify.

**RS256 (RSA-SHA256):**
```javascript
const signature = RSA_SHA256(
  base64UrlEncode(header) + "." + base64UrlEncode(payload),
  privateKey
);

// Verification uses publicKey
```

**ES256 (ECDSA-SHA256):**
```javascript
const signature = ECDSA_SHA256(
  base64UrlEncode(header) + "." + base64UrlEncode(payload),
  privateKey
);
```

**Pros:**
- More secure for distributed systems
- Public key can be shared freely
- Private key stays with issuer only

**Cons:**
- Slower than symmetric algorithms
- More complex key management

## Verification Process

1. Split the JWT into three parts (header, payload, signature)
2. Decode the header to determine the algorithm
3. Recreate the signature using the header, payload, and secret/public key
4. Compare the recreated signature with the provided signature
5. If they match, the token is valid and hasn't been tampered with

```javascript
// Pseudocode
function verifyToken(token, secret) {
  const [header, payload, signature] = token.split('.');

  const expectedSignature = createSignature(
    header + '.' + payload,
    secret
  );

  return signature === expectedSignature;
}
```

## Security Considerations

### Key Management

**Symmetric (HMAC):**
- Keep secret key secure and private
- Rotate keys regularly
- Use strong, random keys (at least 256 bits)
- Never commit keys to version control

**Asymmetric (RSA/ECDSA):**
- Keep private key extremely secure
- Public key can be shared openly
- Use key rotation strategies
- Consider using key management services (AWS KMS, Azure Key Vault)

### Common Vulnerabilities

**Algorithm Confusion Attack:**
- Attacker changes `alg` from RS256 to HS256
- Server uses public key as HMAC secret
- Prevention: Always verify the algorithm matches expected value

**None Algorithm:**
- Setting `alg` to `none` removes signature requirement
- Prevention: Never accept `none` algorithm in production

**Weak Secrets:**
- Short or predictable secrets can be brute-forced
- Prevention: Use cryptographically strong random keys

## Best Practices

1. **Use strong algorithms**: Prefer RS256 or ES256 for production
2. **Validate algorithm**: Always check the `alg` header matches expected value
3. **Secure key storage**: Use environment variables or key management services
4. **Key rotation**: Implement regular key rotation policies
5. **Verify signature**: Always verify signature before trusting token contents
6. **Use HTTPS**: Always transmit JWTs over secure connections
7. **Short expiration**: Combine with short token lifetimes for better security

## Example Implementation

**Node.js with jsonwebtoken library:**

```javascript
const jwt = require('jsonwebtoken');

// Signing (HMAC)
const token = jwt.sign(
  { userId: '123', role: 'admin' },
  process.env.JWT_SECRET,
  { algorithm: 'HS256', expiresIn: '1h' }
);

// Verifying
try {
  const decoded = jwt.verify(token, process.env.JWT_SECRET, {
    algorithms: ['HS256']
  });
  console.log(decoded);
} catch (err) {
  console.error('Invalid token');
}
```

**With RSA:**

```javascript
// Signing with private key
const token = jwt.sign(
  { userId: '123', role: 'admin' },
  privateKey,
  { algorithm: 'RS256', expiresIn: '1h' }
);

// Verifying with public key
const decoded = jwt.verify(token, publicKey, {
  algorithms: ['RS256']
});
```
