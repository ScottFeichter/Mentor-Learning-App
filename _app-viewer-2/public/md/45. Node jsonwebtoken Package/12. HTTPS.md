# HTTPS (HTTP Secure)

## What is HTTPS?

HTTPS is **HTTP with encryption**.

It's the secure version of HTTP that encrypts data between the browser and server using TLS/SSL.

```
HTTP  = Hypertext Transfer Protocol
HTTPS = HTTP + TLS/SSL (encryption layer)
```

## Key Differences: HTTP vs HTTPS

| Feature | HTTP | HTTPS |
|---------|------|-------|
| Port | 80 | 443 |
| Encryption | ❌ None | ✅ TLS/SSL |
| Data visible? | ✅ Yes (plaintext) | ❌ No (encrypted) |
| Certificate | ❌ Not needed | ✅ Required |
| Security | ❌ Vulnerable | ✅ Secure |
| Speed | Slightly faster | Slightly slower (encryption overhead) |
| SEO | Lower ranking | Higher ranking |

## How HTTP Works (Insecure)

```
Browser                         Server
  |                               |
  |--- GET /login HTTP/1.1 ------>|
  |    username: alice            |  ← Anyone can read this!
  |    password: secret123        |  ← Password in plaintext!
  |                               |
  |<------ 200 OK ----------------|
  |    Set-Cookie: session=abc    |  ← Cookie visible!
```

**Problem**: Anyone on the network (WiFi, ISP, hackers) can see everything.

## How HTTPS Works (Secure)

```
Browser                         Server
  |                               |
  |--- TLS Handshake ------------->|  1. Establish encryption
  |<-- Server Certificate ---------|
  |--- Encrypted Key ------------->|
  |                               |
  |=== Encrypted Connection ======|  2. All data encrypted
  |                               |
  |--- [Encrypted Request] ------->|  ← Unreadable to others
  |    [encrypted data]           |
  |                               |
  |<-- [Encrypted Response] -------|
  |    [encrypted data]           |
```

**Benefit**: Data is encrypted, only browser and server can read it.

## HTTPS Handshake Process

### Step 1: Client Hello
```
Browser → Server
"Hello! I support these encryption methods: [list]"
```

### Step 2: Server Hello + Certificate
```
Server → Browser
"Hello! Let's use AES-256. Here's my certificate (proves I'm the real server)"
```

### Step 3: Certificate Verification
```
Browser checks:
- Is certificate signed by trusted authority?
- Is it for the correct domain?
- Is it still valid (not expired)?
```

### Step 4: Key Exchange
```
Browser → Server
"Here's an encrypted session key (encrypted with server's public key)"
```

### Step 5: Encrypted Communication
```
Browser ⟷ Server
All data encrypted with session key
```

## What HTTPS Protects

### ✅ Protects Against:
1. **Eavesdropping** - Can't read data in transit
2. **Man-in-the-middle attacks** - Certificate verification prevents impersonation
3. **Data tampering** - Encryption detects modifications

### ❌ Does NOT Protect Against:
1. **Server-side breaches** - If server is hacked, data is exposed
2. **Malware on your device** - Can steal data before encryption
3. **Phishing** - HTTPS doesn't verify if site is legitimate (just encrypted)

## SSL/TLS Certificates

### What is a Certificate?

A digital document that proves a server's identity, issued by a trusted Certificate Authority (CA).

```javascript
// Certificate contains:
{
  domain: "example.com",
  owner: "Example Inc.",
  publicKey: "...",
  issuer: "Let's Encrypt",
  validFrom: "2024-01-01",
  validUntil: "2025-01-01",
  signature: "..." // Signed by CA
}
```

### Certificate Authorities (CAs)
- Let's Encrypt (free)
- DigiCert
- GlobalSign
- Comodo

Browsers trust these CAs and verify certificates against them.

## Setting Up HTTPS

### Development (Self-Signed Certificate)
```javascript
const https = require('https');
const fs = require('fs');

const options = {
  key: fs.readFileSync('server-key.pem'),
  cert: fs.readFileSync('server-cert.pem')
};

https.createServer(options, (req, res) => {
  res.writeHead(200);
  res.end('Secure connection!');
}).listen(443);
```

### Production (Let's Encrypt)
```bash
# Install Certbot
sudo apt-get install certbot

# Get certificate
sudo certbot certonly --standalone -d example.com

# Certificate files created:
# /etc/letsencrypt/live/example.com/fullchain.pem
# /etc/letsencrypt/live/example.com/privkey.pem
```

### Express.js with HTTPS
```javascript
const express = require('express');
const https = require('https');
const fs = require('fs');

const app = express();

const options = {
  key: fs.readFileSync('/path/to/privkey.pem'),
  cert: fs.readFileSync('/path/to/fullchain.pem')
};

app.get('/', (req, res) => {
  res.send('Secure!');
});

https.createServer(options, app).listen(443, () => {
  console.log('HTTPS server running on port 443');
});
```

## Redirecting HTTP to HTTPS

```javascript
const express = require('express');
const http = require('http');
const https = require('https');

const app = express();

// Redirect HTTP to HTTPS
app.use((req, res, next) => {
  if (req.secure) {
    next();
  } else {
    res.redirect('https://' + req.headers.host + req.url);
  }
});

// Or use middleware
app.use((req, res, next) => {
  if (!req.secure && req.get('x-forwarded-proto') !== 'https') {
    return res.redirect('https://' + req.get('host') + req.url);
  }
  next();
});
```

## Performance Impact

### HTTPS Overhead:
1. **TLS Handshake** - Extra round trips (adds ~100-200ms)
2. **Encryption/Decryption** - CPU overhead (minimal on modern hardware)

### Optimizations:
1. **TLS Session Resumption** - Reuse previous handshake
2. **HTTP/2** - Multiplexing over single connection
3. **OCSP Stapling** - Faster certificate validation

```javascript
// Enable HTTP/2 with HTTPS
const http2 = require('http2');
const fs = require('fs');

const server = http2.createSecureServer({
  key: fs.readFileSync('privkey.pem'),
  cert: fs.readFileSync('fullchain.pem')
});

server.on('stream', (stream, headers) => {
  stream.respond({ ':status': 200 });
  stream.end('Hello HTTP/2!');
});

server.listen(443);
```

## Common Misconceptions

### ❌ "HTTPS makes my site 100% secure"
No. HTTPS only encrypts data in transit. You still need:
- Secure server configuration
- Input validation
- Authentication/authorization
- Regular security updates

### ❌ "HTTPS is only for e-commerce sites"
No. ALL websites should use HTTPS:
- Protects user privacy
- Prevents data tampering
- Required for modern web features (geolocation, service workers)
- Better SEO ranking

### ❌ "HTTPS is expensive"
No. Let's Encrypt provides free certificates.

### ❌ "HTTPS is slow"
No. Modern hardware makes encryption overhead negligible. HTTP/2 (requires HTTPS) is actually faster than HTTP/1.1.

## Why HTTPS Matters

### 1. Privacy
```
HTTP:  ISP can see you're visiting example.com/private-page
HTTPS: ISP only sees you're visiting example.com (not which page)
```

### 2. Integrity
```
HTTP:  Attacker can modify response (inject ads, malware)
HTTPS: Any modification breaks encryption, detected immediately
```

### 3. Authentication
```
HTTP:  No proof you're talking to the real server
HTTPS: Certificate proves server identity
```
