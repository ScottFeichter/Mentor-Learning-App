# http-status-codes Module

## What is http-status-codes?

`http-status-codes` is an npm package that provides named constants for HTTP status codes. Instead of using magic numbers like `200`, `404`, or `500`, you can use descriptive constant names like `OK`, `NOT_FOUND`, or `INTERNAL_SERVER_ERROR`.

## What Does It Do?

- **Provides readable constants** for all standard HTTP status codes
- **Improves code readability** by replacing numeric codes with meaningful names
- **Reduces errors** from typos in status code numbers
- **Includes helper functions** to check status code types

## Installation

```bash
npm install http-status-codes
```

## Basic Usage

### Without http-status-codes (Magic Numbers):
```javascript
app.get('/user', (req, res) => {
  if (!user) {
    return res.status(404).json({ error: 'Not found' });
  }
  res.status(200).json(user);
});
```

### With http-status-codes (Readable Constants):
```javascript
const { StatusCodes } = require('http-status-codes');

app.get('/user', (req, res) => {
  if (!user) {
    return res.status(StatusCodes.NOT_FOUND).json({ error: 'Not found' });
  }
  res.status(StatusCodes.OK).json(user);
});
```

## Most Common Status Codes

### Success (2xx)
```javascript
const { StatusCodes } = require('http-status-codes');

StatusCodes.OK                    // 200 - Request succeeded
StatusCodes.CREATED               // 201 - Resource created
StatusCodes.ACCEPTED              // 202 - Request accepted
StatusCodes.NO_CONTENT            // 204 - Success, no content to return
```

### Client Errors (4xx)
```javascript
StatusCodes.BAD_REQUEST           // 400 - Invalid request
StatusCodes.UNAUTHORIZED          // 401 - Authentication required
StatusCodes.FORBIDDEN             // 403 - Access denied
StatusCodes.NOT_FOUND             // 404 - Resource not found
StatusCodes.CONFLICT              // 409 - Conflict (e.g., duplicate email)
StatusCodes.UNPROCESSABLE_ENTITY  // 422 - Validation error
```

### Server Errors (5xx)
```javascript
StatusCodes.INTERNAL_SERVER_ERROR // 500 - Server error
StatusCodes.NOT_IMPLEMENTED       // 501 - Not implemented
StatusCodes.BAD_GATEWAY           // 502 - Bad gateway
StatusCodes.SERVICE_UNAVAILABLE   // 503 - Service unavailable
```

## Practical Examples

### REST API with Named Status Codes
```javascript
const { StatusCodes } = require('http-status-codes');

// Create user
app.post('/users', async (req, res) => {
  try {
    const user = await createUser(req.body);
    res.status(StatusCodes.CREATED).json(user);
  } catch (error) {
    res.status(StatusCodes.BAD_REQUEST).json({ error: error.message });
  }
});

// Get user
app.get('/users/:id', async (req, res) => {
  const user = await findUser(req.params.id);
  if (!user) {
    return res.status(StatusCodes.NOT_FOUND).json({ error: 'User not found' });
  }
  res.status(StatusCodes.OK).json(user);
});

// Update user
app.put('/users/:id', async (req, res) => {
  const user = await updateUser(req.params.id, req.body);
  res.status(StatusCodes.OK).json(user);
});

// Delete user
app.delete('/users/:id', async (req, res) => {
  await deleteUser(req.params.id);
  res.status(StatusCodes.NO_CONTENT).send();
});
```

### Authentication Example
```javascript
const { StatusCodes } = require('http-status-codes');

app.post('/login', async (req, res) => {
  const user = await findUser(req.body.email);
  
  if (!user) {
    return res.status(StatusCodes.UNAUTHORIZED)
      .json({ error: 'Invalid credentials' });
  }
  
  const isValid = await bcrypt.compare(req.body.password, user.password);
  
  if (!isValid) {
    return res.status(StatusCodes.UNAUTHORIZED)
      .json({ error: 'Invalid credentials' });
  }
  
  const token = jwt.sign({ userId: user.id }, SECRET);
  res.status(StatusCodes.OK).json({ token });
});

// Protected route
app.get('/protected', (req, res) => {
  const token = req.headers.authorization?.split(' ')[1];
  
  if (!token) {
    return res.status(StatusCodes.UNAUTHORIZED)
      .json({ error: 'No token provided' });
  }
  
  try {
    const decoded = jwt.verify(token, SECRET);
    res.status(StatusCodes.OK).json({ data: 'Protected data' });
  } catch (error) {
    res.status(StatusCodes.FORBIDDEN)
      .json({ error: 'Invalid token' });
  }
});
```

### Error Handling Middleware
```javascript
const { StatusCodes } = require('http-status-codes');

app.use((err, req, res, next) => {
  console.error(err.stack);
  
  if (err.name === 'ValidationError') {
    return res.status(StatusCodes.UNPROCESSABLE_ENTITY)
      .json({ error: err.message });
  }
  
  if (err.name === 'UnauthorizedError') {
    return res.status(StatusCodes.UNAUTHORIZED)
      .json({ error: 'Invalid token' });
  }
  
  res.status(StatusCodes.INTERNAL_SERVER_ERROR)
    .json({ error: 'Something went wrong' });
});
```

## Additional Features

### ReasonPhrases (Status Messages)
```javascript
const { StatusCodes, ReasonPhrases } = require('http-status-codes');

res.status(StatusCodes.NOT_FOUND).json({
  error: ReasonPhrases.NOT_FOUND  // "Not Found"
});
```

### getReasonPhrase Function
```javascript
const { getReasonPhrase } = require('http-status-codes');

console.log(getReasonPhrase(200));  // "OK"
console.log(getReasonPhrase(404));  // "Not Found"
```

### getStatusCode Function
```javascript
const { getStatusCode } = require('http-status-codes');

console.log(getStatusCode('OK'));        // 200
console.log(getStatusCode('NOT_FOUND')); // 404
```

## Benefits

1. **Readability**: `StatusCodes.NOT_FOUND` is clearer than `404`
2. **Maintainability**: Easier to understand code intent
3. **Type Safety**: Reduces typos in status codes
4. **Consistency**: Standardized naming across your application
5. **Documentation**: Self-documenting code
