# Cookies and Browser Storage

## Types of Cookies

### Session Cookies
- **Lifespan:** Temporary - deleted when the browser is closed
- **Storage:** No `Expires` or `Max-Age` attribute set
- **Use case:** Temporary session data, shopping carts, login sessions
- **Example:**
  ```
  Set-Cookie: sessionId=abc123; Path=/; HttpOnly
  ```

### Persistent Cookies
- **Lifespan:** Stored until expiration date or manually deleted
- **Storage:** Has `Expires` or `Max-Age` attribute
- **Use case:** "Remember me" functionality, user preferences, tracking
- **Example:**
  ```
  Set-Cookie: userId=12345; Expires=Wed, 31 Dec 2025 23:59:59 GMT; Path=/
  ```

### HttpOnly Cookies
- **Access:** Cannot be accessed via JavaScript (document.cookie)
- **Security:** Protects against XSS (Cross-Site Scripting) attacks
- **Use case:** Authentication tokens, sensitive session data
- **Example:**
  ```
  Set-Cookie: authToken=xyz789; HttpOnly; Secure; Path=/
  ```

### Secure Cookies
- **Transmission:** Only sent over HTTPS connections
- **Security:** Prevents interception over unsecured networks
- **Example:**
  ```
  Set-Cookie: token=abc123; Secure; HttpOnly
  ```

### SameSite Cookies
- **Protection:** Prevents CSRF (Cross-Site Request Forgery) attacks
- **Values:**
  - `Strict` - Cookie only sent to same-site requests
  - `Lax` - Cookie sent on top-level navigation (default in modern browsers)
  - `None` - Cookie sent on cross-site requests (requires `Secure`)
- **Example:**
  ```
  Set-Cookie: data=value; SameSite=Strict; Secure
  ```

## Cookie Attributes Summary

| Attribute | Purpose |
|-----------|---------|
| `Domain` | Specifies which hosts can receive the cookie |
| `Path` | URL path that must exist in the request |
| `Expires` | Absolute expiration date |
| `Max-Age` | Relative expiration time in seconds |
| `Secure` | Only sent over HTTPS |
| `HttpOnly` | Not accessible via JavaScript |
| `SameSite` | Controls cross-site request behavior |

## Cookies vs Other Browser Storage

### Cookies
- **Size limit:** ~4KB per cookie
- **Sent with requests:** Automatically included in HTTP headers
- **Access:** Server and client (unless HttpOnly)
- **Expiration:** Can be session or persistent
- **Use case:** Authentication, session management, tracking

### LocalStorage
- **Size limit:** ~5-10MB (varies by browser)
- **Sent with requests:** No - stays in browser only
- **Access:** Client-side JavaScript only
- **Expiration:** Never expires (persists until manually cleared)
- **Use case:** Caching data, user preferences, offline data
- **Example:**
  ```javascript
  localStorage.setItem('theme', 'dark');
  localStorage.getItem('theme');
  ```

### SessionStorage
- **Size limit:** ~5-10MB (varies by browser)
- **Sent with requests:** No - stays in browser only
- **Access:** Client-side JavaScript only
- **Expiration:** Cleared when tab/window is closed
- **Scope:** Per-tab (not shared between tabs)
- **Use case:** Form data, temporary UI state
- **Example:**
  ```javascript
  sessionStorage.setItem('formData', JSON.stringify(data));
  sessionStorage.getItem('formData');
  ```

### IndexedDB
- **Size limit:** Much larger (50MB+ depending on browser and available disk space)
- **Sent with requests:** No - stays in browser only
- **Access:** Client-side JavaScript only (async API)
- **Expiration:** Never expires (persists until manually cleared)
- **Use case:** Large datasets, offline applications, complex data structures
- **Example:**
  ```javascript
  const request = indexedDB.open('MyDatabase', 1);
  ```

## Comparison Table

| Feature | Cookies | LocalStorage | SessionStorage | IndexedDB |
|---------|---------|--------------|----------------|-----------|
| Capacity | ~4KB | ~5-10MB | ~5-10MB | 50MB+ |
| Sent to Server | Yes | No | No | No |
| Accessible from | Client & Server | Client only | Client only | Client only |
| Expiration | Configurable | Never | Tab close | Never |
| Storage Type | String | String | String | Structured data |
| API | document.cookie | localStorage API | sessionStorage API | IndexedDB API |

## Security Best Practices

### For Cookies:
1. **Always use `HttpOnly`** for authentication tokens to prevent XSS attacks
2. **Always use `Secure`** to ensure transmission over HTTPS only
3. **Use `SameSite=Strict` or `Lax`** to prevent CSRF attacks
4. **Set appropriate `Domain` and `Path`** to limit cookie scope
5. **Use short expiration times** for sensitive data
6. **Never store sensitive data** in plain text

### For LocalStorage/SessionStorage:
1. **Never store sensitive data** (tokens, passwords, PII)
2. **Validate and sanitize** data before storing
3. **Be aware of XSS vulnerabilities** - any script can access storage
4. **Consider encryption** for sensitive but non-critical data

## Common Use Cases

### Authentication Flow with Cookies:
```
1. User logs in
2. Server creates session and sends HttpOnly cookie
   Set-Cookie: sessionId=abc123; HttpOnly; Secure; SameSite=Strict; Path=/
3. Browser automatically sends cookie with each request
4. Server validates session on each request
5. Cookie expires or user logs out
```

### Token Storage Options:
- **HttpOnly Cookie:** Most secure for authentication tokens (prevents XSS)
- **LocalStorage:** Accessible to JavaScript (vulnerable to XSS, but useful for SPAs)
- **SessionStorage:** Similar to LocalStorage but cleared on tab close
- **Memory only:** Most secure but lost on page refresh

## Important Notes

- **Third-party cookies** are being phased out by browsers for privacy reasons
- **Cookie consent** is required in many jurisdictions (GDPR, CCPA)
- **Storage events** can be used to sync data across tabs (LocalStorage only)
- **Private/Incognito mode** affects storage behavior
- **Storage quotas** can be exceeded - always handle errors
