# CPU Registers

## What Are CPU Registers?

CPU registers are the fastest memory storage locations inside the CPU chip. Unlike other memory types, registers are accessed by name rather than memory addresses, making them fundamentally different from the memory hierarchy.

## Key Characteristics

- **Location**: Inside the CPU chip
- **Size**: 64-256 bytes total
- **Speed**: 1 cycle (0.3-1 nanoseconds)
- **Cost**: ~$1000 per byte
- **Access Method**: Direct naming (no addressing)
- **Volatility**: Volatile (lost when power off)

## Register Types and Organization

### General Purpose Registers (x86-64)
```
64-bit: RAX, RBX, RCX, RDX, RSI, RDI, RBP, RSP, R8-R15
32-bit: EAX, EBX, ECX, EDX, ESI, EDI, EBP, ESP, R8D-R15D
16-bit: AX,  BX,  CX,  DX,  SI,  DI,  BP,  SP,  R8W-R15W
8-bit:  AL,  BL,  CL,  DL,  SIL, DIL, BPL, SPL, R8B-R15B
```

### Special Purpose Registers
- **RIP**: Instruction Pointer (program counter)
- **RFLAGS**: Status flags (zero, carry, overflow, etc.)
- **Segment Registers**: CS, DS, ES, FS, GS, SS
- **Control Registers**: CR0, CR1, CR2, CR3, CR4

## Register File Organization

Registers are organized in a flat structure, not a hierarchical tree:

```
Register File (Physical Implementation)
┌─────────────────────────────────────┐
│ RAX [63:0] ┌─EAX[31:0]─┬─AX[15:0]─┐ │
│            │           ├─AH[15:8]─┤ │
│            │           └─AL[7:0]──┘ │
├─────────────────────────────────────┤
│ RBX [63:0] ┌─EBX[31:0]─┬─BX[15:0]─┐ │
│            │           ├─BH[15:8]─┤ │
│            │           └─BL[7:0]──┘ │
├─────────────────────────────────────┤
│ RCX, RDX, RSI, RDI... (similar)    │
└─────────────────────────────────────┘
```

## How Register Access Works

### Direct Naming (No Addressing)
```assembly
; Direct register naming (no address calculation)
MOV RAX, 1234h      ; RAX = 1234h
MOV RBX, RAX        ; RBX = RAX (register to register)
MOV [RBX], RAX      ; Memory[RBX] = RAX (register as address)
MOV RAX, [RBX+8]    ; RAX = Memory[RBX+8] (register + offset)
```

### Register Access vs Memory Access
```assembly
; Register access (1 cycle)
MOV RAX, 1234h

; Memory access for comparison (100+ cycles)
MOV RAX, [0x1000]  ; Requires:
                   ; - Address calculation
                   ; - Cache lookup
                   ; - Possible cache miss
                   ; - 100+ cycles if RAM access
```

## Register Renaming (Modern CPUs)

Modern processors use register renaming for performance optimization:

```
Logical Registers (what programmer sees)
    RAX, RBX, RCX, RDX...
         ↓
Physical Register File (what CPU uses)
    P0, P1, P2, P3, P4, P5... (128+ registers)
```

**Benefits:**
- Eliminates false dependencies
- Enables out-of-order execution
- Increases instruction-level parallelism

## Register Usage Patterns

### Function Call Convention (x86-64 System V ABI)
```assembly
; Parameter passing
RDI - 1st argument
RSI - 2nd argument  
RDX - 3rd argument
RCX - 4th argument
R8  - 5th argument
R9  - 6th argument

; Return values
RAX - Primary return value
RDX - Secondary return value (for 128-bit returns)

; Preserved across calls
RBX, RBP, R12-R15 - Callee-saved
RAX, RCX, RDX, RSI, RDI, R8-R11 - Caller-saved
```

### Register Allocation Priority
```
High Priority → Low Priority
┌─────────────┬─────────────┬─────────────┐
│ Frequently  │ Loop        │ Temporary   │
│ used vars   │ counters    │ calculations│
│ (registers) │ (registers) │ (memory)    │
└─────────────┴─────────────┴─────────────┘
```

## Register Operations

### Basic Operations
```assembly
; Load immediate value
MOV RAX, 42

; Register to register
MOV RBX, RAX

; Arithmetic
ADD RAX, RBX
SUB RAX, 10
MUL RCX
DIV RDX

; Bitwise operations
AND RAX, 0xFF
OR  RAX, 0x100
XOR RAX, RAX    ; Common way to zero a register
SHL RAX, 2      ; Shift left (multiply by 4)
```

### Advanced Operations
```assembly
; Conditional moves
CMP RAX, RBX
CMOVG RAX, RCX  ; Move RCX to RAX if RAX > RBX

; Exchange
XCHG RAX, RBX   ; Swap RAX and RBX

; Compare and exchange (atomic)
CMPXCHG [memory], RBX
```

## Register Constraints and Limitations

### Fixed Purposes
- **RSP**: Stack pointer (should not be used for general computation)
- **RBP**: Base pointer (frame pointer in some calling conventions)
- **RIP**: Instruction pointer (cannot be directly modified)

### Size Limitations
- Limited number of registers (16 general purpose in x86-64)
- Register pressure forces spilling to memory
- Compiler optimization crucial for efficient usage

## Programming Language Integration

### High-Level Language Mapping
```c
// C code
int a = 5;
int b = 10;
int c = a + b;

// Possible assembly (optimized)
MOV EAX, 5      ; a in EAX
MOV EBX, 10     ; b in EBX  
ADD EAX, EBX    ; c = a + b, result in EAX
```

### JavaScript Engine Usage
Modern JavaScript engines (V8, SpiderMonkey) use registers for:
- Temporary calculations during JIT compilation
- Function parameters and return values
- Loop counters and array indices
- Object property access optimization

## Performance Impact

### Register vs Memory Speed Comparison
| Operation | Cycles | Time (3GHz CPU) |
|-----------|--------|-----------------|
| Register access | 1 | 0.33 ns |
| L1 cache access | 3-4 | 1-1.3 ns |
| L2 cache access | 10-20 | 3-7 ns |
| RAM access | 200-400 | 67-133 ns |

### Optimization Strategies
1. **Keep frequently used variables in registers**
2. **Minimize register spilling to memory**
3. **Use appropriate data types to fit in registers**
4. **Leverage compiler optimizations for register allocation**

## Key Insights

1. **Registers are not addressable memory** - they're accessed by name
2. **Fastest storage available** - direct CPU access in 1 cycle
3. **Limited quantity** - scarcity makes them precious
4. **Compiler managed** - high-level languages abstract register usage
5. **Architecture specific** - different CPUs have different register sets
6. **Performance critical** - efficient register usage dramatically affects speed
