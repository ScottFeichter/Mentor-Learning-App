# Computer Memory

## Memory Hierarchy Overview

Computer memory is organized in a hierarchy based on speed, size, and cost. Faster memory is more expensive and smaller, while slower memory is cheaper and larger.

## Types of Memory (Fastest to Slowest)

### 1. CPU Registers
**Location**: Inside the CPU chip
**Size**: 64-256 bytes total
**Speed**: 1 cycle (0.3-1 nanoseconds)
**Cost**: ~$1000 per byte
**Access Method**: Direct naming (no addressing)

- Fastest memory available
- Accessed by name rather than memory addresses
- Store immediate operands, addresses, and temporary results
- Limited quantity makes them precious for performance

*For detailed information about registers, see [14. CPU Registers.md](14.%20CPU%20Registers.md)*

### 2. CPU Cache
**Levels**: L1, L2, L3 (closest to farthest from CPU)

#### L1 Cache
- **Size**: 32-64 KB per core
- **Speed**: 2-4 cycles (1-2 nanoseconds)
- **Cost**: ~$100 per byte
- Split into instruction cache (I-cache) and data cache (D-cache)

#### L2 Cache
- **Size**: 256 KB - 1 MB per core
- **Speed**: 10-20 cycles (3-7 nanoseconds)
- **Cost**: ~$10 per byte
- Unified cache for both instructions and data

#### L3 Cache
- **Size**: 8-32 MB shared across cores
- **Speed**: 30-70 cycles (10-25 nanoseconds)
- **Cost**: ~$1 per byte
- Shared between all CPU cores

### 3. Main Memory (RAM)
**Types**: DDR4, DDR5, LPDDR

- **Size**: 4-128 GB typical
- **Speed**: 200-400 cycles (60-120 nanoseconds)
- **Cost**: ~$0.000001 per byte
- Volatile (loses data when power off)
- Random access - any location accessible in same time

**Memory Access Pattern:**
```
CPU Request → L1 Cache (hit/miss) → L2 Cache (hit/miss) → L3 Cache (hit/miss) → RAM
```

### 4. Storage Memory
**Types**: SSD, HDD, NVMe

#### NVMe SSD
- **Speed**: 50,000-100,000 nanoseconds
- **Cost**: ~$0.0000001 per byte
- Non-volatile (retains data without power)

#### SATA SSD
- **Speed**: 100,000-500,000 nanoseconds
- **Cost**: ~$0.00000005 per byte

#### Hard Disk Drive (HDD)
- **Speed**: 5,000,000-15,000,000 nanoseconds
- **Cost**: ~$0.00000002 per byte
- Mechanical moving parts

## Memory Access Methods

### 1. Register Access
- Direct naming (no addressing)
- Fastest method (1 cycle)
- See [14. CPU Registers.md](14.%20CPU%20Registers.md) for details

### 2. Addressable Memory Access
- Uses numerical addresses to locate data
- Includes cache, RAM, and storage
- See [15. Memory Addressing.md](15.%20Memory%20Addressing.md) for details

### 3. Cache-Line Access
- Memory loaded in chunks (cache lines)
- Typical cache line: 64 bytes
- Improves spatial locality

## Memory Hierarchy Principles

### 1. Locality of Reference
- **Temporal Locality**: Recently accessed data likely to be accessed again
- **Spatial Locality**: Nearby data likely to be accessed soon

### 2. Caching Strategy
- Keep frequently used data in faster memory
- Automatically managed by hardware and OS
- Cache hits = fast access, cache misses = slower access

### 3. Memory Management
- **Virtual Memory**: OS creates illusion of large address space
- **Paging**: Memory divided into fixed-size pages
- **Swapping**: Move inactive pages to storage

## JavaScript Memory Context

### Heap Memory
- Objects and dynamic data stored in RAM
- Managed by garbage collector
- Accessed through references/pointers

### Stack Memory
- Function calls and local variables
- Faster access than heap
- Automatically managed (LIFO)

### Example Memory Access Pattern:
```javascript
// This creates objects in heap memory
let obj = { name: "Hello" };  // Heap allocation
let arr = [1, 2, 3, 4, 5];    // Heap allocation

// Function calls use stack memory
function process(data) {      // Stack frame created
    let temp = data.length;   // Stack variable
    return temp * 2;          // Stack operations
}                             // Stack frame destroyed
```

## Key Insights

1. **Speed vs Size Trade-off**: Faster memory is smaller and more expensive
2. **Automatic Management**: Hardware and OS handle most memory hierarchy decisions
3. **Performance Impact**: Cache hits/misses significantly affect program speed
4. **Programming Implications**: Data locality affects performance in all languages
5. **Memory Bandwidth**: Not just latency - how much data can be transferred per second matters

The memory hierarchy is designed to give the illusion of large, fast memory while keeping costs reasonable.
