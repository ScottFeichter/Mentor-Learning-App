# Setters and Getters

## What Are They?

**Getters** and **setters** are special methods that let you define how a property is accessed (get) or modified (set). They look like regular properties from the outside, but run a function under the hood.

- **Getter**: Runs when you *read* a property
- **Setter**: Runs when you *assign* a value to a property

They're useful for:
- Computed/derived values
- Validation before setting a value
- Encapsulation (hiding internal data)
- Logging or side effects on access/mutation

## Object Literal Syntax

```javascript
const user = {
  firstName: 'John',
  lastName: 'Doe',

  get fullName() {
    return `${this.firstName} ${this.lastName}`;
  },

  set fullName(value) {
    const parts = value.split(' ');
    this.firstName = parts[0];
    this.lastName = parts[1];
  }
};

console.log(user.fullName);    // "John Doe" — calls the getter
user.fullName = 'Jane Smith';  // calls the setter
console.log(user.firstName);   // "Jane"
console.log(user.lastName);    // "Smith"
```

Notice you access `fullName` like a property, not a method call — no parentheses.

## Class Syntax

```javascript
class Circle {
  constructor(radius) {
    this._radius = radius; // convention: underscore = "private"
  }

  get radius() {
    return this._radius;
  }

  set radius(value) {
    if (value <= 0) throw new Error('Radius must be positive');
    this._radius = value;
  }

  get area() {
    return Math.PI * this._radius ** 2;
  }

  get diameter() {
    return this._radius * 2;
  }
}

const c = new Circle(5);
console.log(c.radius);    // 5
console.log(c.area);      // 78.539...
console.log(c.diameter);  // 10

c.radius = 10;            // calls setter, validates
console.log(c.area);      // 314.159...

c.radius = -1;            // Error: Radius must be positive
```

## Getter Only (Read-Only Property)

```javascript
class Temperature {
  constructor(celsius) {
    this._celsius = celsius;
  }

  get fahrenheit() {
    return this._celsius * 9 / 5 + 32;
  }

  get celsius() {
    return this._celsius;
  }

  set celsius(value) {
    this._celsius = value;
  }
}

const temp = new Temperature(100);
console.log(temp.fahrenheit); // 212
temp.fahrenheit = 50;         // silently ignored (no setter defined)
console.log(temp.fahrenheit); // still 212
```

## Validation with Setters

```javascript
class User {
  constructor(name, age) {
    this.name = name; // calls the setter
    this.age = age;   // calls the setter
  }

  get name() {
    return this._name;
  }

  set name(value) {
    if (!value || value.trim().length === 0) {
      throw new Error('Name cannot be empty');
    }
    this._name = value.trim();
  }

  get age() {
    return this._age;
  }

  set age(value) {
    if (typeof value !== 'number' || value < 0 || value > 150) {
      throw new Error('Age must be a number between 0 and 150');
    }
    this._age = value;
  }
}

const u = new User('Alice', 30); // works
const bad = new User('', 25);    // Error: Name cannot be empty
```

## Using Object.defineProperty

You can also add getters/setters to existing objects:

```javascript
const obj = { _count: 0 };

Object.defineProperty(obj, 'count', {
  get() {
    return this._count;
  },
  set(value) {
    if (value < 0) throw new Error('Count cannot be negative');
    this._count = value;
  }
});

obj.count = 5;
console.log(obj.count); // 5
obj.count = -1;         // Error: Count cannot be negative
```

## Lazy Computation with Getters

Getters are great for values that are expensive to compute — you only calculate when accessed:

```javascript
class DataSet {
  constructor(numbers) {
    this._numbers = numbers;
  }

  get average() {
    const sum = this._numbers.reduce((a, b) => a + b, 0);
    return sum / this._numbers.length;
  }

  get max() {
    return Math.max(...this._numbers);
  }

  get min() {
    return Math.min(...this._numbers);
  }
}

const data = new DataSet([4, 8, 15, 16, 23, 42]);
console.log(data.average); // 18
console.log(data.max);     // 42
console.log(data.min);     // 4
```

## Key Points

- Getters/setters are accessed like properties, not called like methods
- Use `get` keyword to define a getter, `set` keyword for a setter
- The underscore prefix (`_name`) is a convention to indicate the backing property — it's not truly private
- A getter without a setter makes a read-only property
- A setter without a getter makes a write-only property (rare)
- Setters are ideal for validation logic
- Getters are ideal for computed/derived values
- In classes, the constructor can trigger setters if you assign to `this.propertyName`
