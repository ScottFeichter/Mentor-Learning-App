# Promise Executor Timing

## The Callback (Executor) is NOT Invoked in the Argument List

```javascript
new Promise(function executor(resolve, reject) {
  // This function is passed as a callback, not called here
});
```

The executor function is passed as a callback to the Promise constructor - it's not invoked in the argument list.

## Executor As Argument To The Constructor

The executor function is passed as a callback argument to the Promise constructor.

It is very important that we pass this as a callback rather than a function call.

UNLESS WE ARE DEFINING IT IN THE CONSTRUCTOR,

WE MUST NOT USE PARENTHESIS ON THE EXECUTOR!!!

```javascript
                      // THIS IS BAD!!!
let myPromise = new Promise(executor());
// IT WILL NOT WORK BECAUSE THIS IS NOT A CALLBACK!!!
```


## The Promise Constructor Calls It Immediately

**What happens inside the Promise constructor:**
```javascript
class Promise {
  constructor(executor) {
    // executor received as callback
    const resolve = (value) => { /* ... */ };
    const reject = (reason) => { /* ... */ };

    // Promise constructor calls the executor immediately
    executor(resolve, reject);
  }
}
```

## The Key Point:

1. **You pass** the executor as a callback (not invoked in argument list)
2. **Promise constructor receives** the executor function
3. **Promise constructor immediately calls** the executor in its body

## Why "Runs Immediately"?

Unlike other callbacks that might be called later (like event handlers), the Promise constructor is designed to call the executor right away to set up the async operation.

**So both statements are true:**
- Callback not invoked in argument list ✓
- Executor runs immediately ✓

The "immediately" refers to when the Promise constructor calls it, not when you pass it.
