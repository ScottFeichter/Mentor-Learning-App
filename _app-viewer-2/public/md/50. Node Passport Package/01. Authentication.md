# Authentication in Web Development

Authentication is the process of verifying the identity of a user, device, or system.

It answers the question: "Who are you?"

## Core Concepts

**Authentication vs Authorization**
- **Authentication** - Verifying identity (login)
- **Authorization** - Verifying permissions (access control)

## Common Authentication Methods

### 1. Session-Based Authentication
- User logs in with credentials
- Server creates a session and stores session ID in a cookie
- Cookie sent with each request to identify the user
- Session data stored on server

```javascript
// Login creates session
app.post('/login', (req, res) => {
  // Verify credentials
  req.session.userId = user.id; // Store in session
  res.send('Logged in');
});

// Session cookie automatically sent with requests
app.get('/profile', (req, res) => {
  if (!req.session.userId) return res.status(401).send('Unauthorized');
  res.send('Profile data');
});
```

### 2. Token-Based Authentication (JWT)
- User logs in with credentials
- Server generates a token (JWT)
- Client stores token (localStorage, cookie)
- Token sent with each request in Authorization header
- Stateless - no server-side session storage

```javascript
// Login returns token
app.post('/login', (req, res) => {
  const token = jwt.sign({ userId: user.id }, SECRET);
  res.json({ token });
});

// Client sends token in header
app.get('/profile', authenticateToken, (req, res) => {
  res.json(req.user);
});

function authenticateToken(req, res, next) {
  const token = req.headers['authorization']?.split(' ')[1];
  if (!token) return res.status(401).send('Unauthorized');
  jwt.verify(token, SECRET, (err, user) => {
    if (err) return res.status(403).send('Forbidden');
    req.user = user;
    next();
  });
}
```

### 3. OAuth / Social Login
- User authenticates through third-party provider (Google, GitHub, Facebook)
- Provider verifies identity and returns user data
- Your app receives authorization to access user info

### 4. Multi-Factor Authentication (MFA)
- Requires multiple verification methods
- Something you know (password)
- Something you have (phone, security key)
- Something you are (biometrics)

## Key Security Practices

1. **Hash passwords** - Never store plain text passwords (use bcrypt, argon2)
2. **Use HTTPS** - Encrypt data in transit
3. **Secure sessions** - Use httpOnly, secure, sameSite cookie flags
4. **Implement rate limiting** - Prevent brute force attacks
5. **Validate input** - Prevent injection attacks
6. **Use strong secrets** - For signing tokens and sessions

## Authentication Flow Example

```
1. User submits username/password
2. Server validates credentials against database
3. Server creates session/token
4. Client stores session cookie/token
5. Client includes cookie/token with subsequent requests
6. Server verifies cookie/token
7. Server grants access to protected resources
```

## When to Use What

- **Session-based** - Traditional web apps, server-rendered pages
- **Token-based (JWT)** - APIs, mobile apps, SPAs, microservices
- **OAuth** - Third-party integrations, social login
