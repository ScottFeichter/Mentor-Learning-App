# Testing

## Testing Pyramid

- **End-to-End Tests** — aka E2E, test the whole application
- **Integration Tests** — test the interactions between pieces of the application
- **Unit Tests** — test the smallest pieces of the application in isolation

## Test Driven Development (TDD)

- Ensures code written works
- Reduces unnecessary functionality
- Helps enforce code modularity
- Makes expectations of code clearer
- Code is guaranteed to be testable
- Makes for easier collaboration
- Basically a form of Polya's problem-solving method

The process:
1. Write failing tests first
2. Write minimal code to pass
3. Refactor code

## Mocha and Chai

- **Mocha** is a testing framework
- **Chai** is an assertion library
- Tests live in a `test` folder with `calculator-spec.js` naming convention

### Important Functions

```javascript
describe('Calculator', function () {
  it('should add two numbers', function () {
    assert.equal(add(1, 2), 3);
  });
});
```

Key functions for specs:
- `describe()` — groups related tests
- `it()` — defines a single test case
- `assert()` — checks expected outcomes

Helpful helpers:
- `expect()` — BDD-style assertion
- `before()` — runs once before all tests
- `after()` — runs once after all tests
- `context()` — alias for describe

### Setup

- `package.json` — summary of data and dependencies
- `npm install` — installs all listed dependencies into `node_modules`
- `package-lock.json` — exact versions of dependencies

## Common Test Cases

### Edge Cases (extremes)

- Not of desired type
- Empty, null, undefined, falsey value
- Maximum/minimum value
- Maximum/minimum input
- Very large/very small input

### Unintuitive Cases (other possible errors)

- Same length inputs
- Boundary conditions
- Unexpected input combinations
