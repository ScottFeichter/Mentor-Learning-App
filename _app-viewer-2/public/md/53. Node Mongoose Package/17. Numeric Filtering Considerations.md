# Numeric Query Filtering Considerations

## Overview
Filtering queries with numeric values presents unique challenges that require special handling beyond simple string matching.

## Key Challenges

### 1. Type Conversion
Query parameters arrive as strings but need numeric comparison:

```javascript
// URL: /api/products?price>=100
// req.query.price = "100" (string)
// Need: price >= 100 (number)

const numericValue = Number(queryParam);
// or
const numericValue = parseInt(queryParam, 10);
```

### 2. Operator Parsing
Extract and interpret comparison operators from filter strings:

```javascript
// Input: "price>=100"
// Need to separate: field="price", operator=">=", value=100

const match = filter.match(/(\w+)(>=|<=|>|<|=)(\d+)/);
const [, field, operator, value] = match;
```

### 3. Database Query Translation
Convert parsed filters into database-specific syntax:

```javascript
// MongoDB example
const mongoOperators = {
  '>=': '$gte',
  '<=': '$lte', 
  '>': '$gt',
  '<': '$lt',
  '=': '$eq'
};

// "price>=100" becomes: { price: { $gte: 100 } }
```

### 4. Validation Concerns
- **Invalid numbers**: `"abc"` → `NaN`
- **Floating point precision**: `0.1 + 0.2 !== 0.3`
- **Range limits**: Ensure values are within acceptable bounds
- **Injection prevention**: Sanitize operator strings

### 5. Multiple Filters
Handle combinations of numeric conditions:

```javascript
// URL: /api/products?price>=100&price<=500&rating>4
// Result: price between 100-500 AND rating > 4
```

## Common Solutions

### Preprocessing Pipeline
```javascript
function parseNumericFilters(queryString) {
  return queryString
    .split('&')
    .map(parseFilter)
    .filter(isValidNumeric)
    .map(convertToDbQuery);
}
```

### Type Safety
```javascript
function safeNumericConversion(value) {
  const num = Number(value);
  if (isNaN(num)) throw new Error('Invalid numeric value');
  return num;
}
```

## Why Extra Consideration Matters
- **Data integrity**: Prevents incorrect comparisons (`"10" > "2"` is false, but `10 > 2` is true)
- **Performance**: Proper indexing requires correct data types
- **Security**: Prevents injection attacks through operator manipulation
- **User experience**: Provides meaningful error messages for invalid inputs
