# SQLite

## What Is SQLite?

**SQLite** is a self-contained, serverless, zero-configuration relational database engine. Unlike PostgreSQL or MySQL, SQLite doesn't run as a separate server process — it reads and writes directly to a single file on disk. It's the most widely deployed database in the world, embedded in phones, browsers, operating systems, and countless applications.

## History

- **2000**: Created by D. Richard Hipp while working on a US Navy project
- **2000**: First release — designed to need no administration
- **2004**: Adopted by many embedded systems and mobile platforms
- **2007**: Apple adopted SQLite for iPhone (iOS)
- **2008**: Google adopted SQLite for Android
- **Today**: Estimated to be running on billions of devices (every smartphone, every browser, many desktop apps)

## Key Features

- **Serverless** — no separate process, no configuration
- **Zero-configuration** — no setup, no admin
- **Single file** — entire database is one `.db` file
- **Cross-platform** — the file works on any OS
- **Self-contained** — no external dependencies
- **ACID compliant** — full transaction support
- **Small footprint** — library is ~600KB
- **Fast** — faster than client-server databases for many use cases
- **Public domain** — no license restrictions whatsoever

## Running Locally (sqlite3 Shell)

### Open/Create a Database

```bash
# Open (or create) a database file
sqlite3 myapp.db

# Open in-memory database (temporary)
sqlite3 :memory:
```

### Basic Shell Commands

```sql
-- List all tables
.tables

-- Show schema for a table
.schema users

-- Show all databases attached
.databases

-- Toggle column headers
.headers on

-- Set output mode
.mode column

-- Quit
.quit

-- Import CSV
.import data.csv tablename

-- Export to CSV
.mode csv
.output results.csv
SELECT * FROM users;
.output stdout
```

### Basic SQL Operations

```sql
-- Create a table
CREATE TABLE users (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  email TEXT UNIQUE NOT NULL,
  age INTEGER CHECK (age >= 0),
  created_at TEXT DEFAULT (datetime('now'))
);

-- Insert data
INSERT INTO users (name, email, age) VALUES ('John', 'john@example.com', 30);

-- Query data
SELECT * FROM users WHERE age > 21 ORDER BY name;

-- Update data
UPDATE users SET age = 31 WHERE email = 'john@example.com';

-- Delete data
DELETE FROM users WHERE id = 1;

-- Drop a table
DROP TABLE users;
```

### SQLite-Specific Notes

```sql
-- SQLite uses dynamic typing (type affinity)
-- These all work:
INSERT INTO users (name) VALUES (123);    -- stored as text affinity
INSERT INTO users (age) VALUES ('thirty'); -- stored but not enforced as integer

-- No ALTER TABLE DROP COLUMN (before 3.35.0)
-- No RIGHT JOIN or FULL OUTER JOIN
-- No GRANT/REVOKE (no user system)
```

## Running Remotely

SQLite is primarily a local/embedded database. However, there are ways to use it in production:

### Hosted/Remote SQLite Options

| Service | Notes |
|---------|-------|
| **Turso** | Distributed SQLite at the edge (libSQL) |
| **LiteFS (Fly.io)** | Replicated SQLite for distributed apps |
| **Cloudflare D1** | SQLite at the edge (Workers) |
| **Litestream** | Stream SQLite backups to S3/cloud storage |

### Connecting from Node.js

```javascript
// Using better-sqlite3 (synchronous, fast)
const Database = require('better-sqlite3');
const db = new Database('myapp.db');

const users = db.prepare('SELECT * FROM users WHERE age > ?').all(21);

// Using sqlite3 (async, callback-based)
const sqlite3 = require('sqlite3');
const db = new sqlite3.Database('myapp.db');

db.all('SELECT * FROM users', (err, rows) => {
  console.log(rows);
});
```

## Default Port

**None** — SQLite is serverless (file-based, no network port)

## When to Use SQLite

- Prototyping and development
- Mobile applications (iOS, Android)
- Desktop applications (Electron, etc.)
- Embedded systems and IoT
- Testing (in-memory databases)
- Small to medium websites
- Single-server applications
- When you don't want to manage a database server

## When NOT to Use SQLite

- High-concurrency write workloads (single writer at a time)
- Multiple servers needing the same database
- Very large datasets (>1TB)
- When you need user/role-based access control
