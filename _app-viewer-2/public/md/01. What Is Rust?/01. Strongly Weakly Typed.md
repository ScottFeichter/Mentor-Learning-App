# Strongly Typed vs Weakly Typed Languages

## Overview
Type systems determine how strictly a language enforces type rules and when type checking occurs.

## Strongly Typed (Rust)
Types are enforced at compile time. Type mismatches cause compilation errors.

### Examples

**Variable Declaration:**
```rust
let age: i32 = 25;
let name: String = String::from("Alice");

// This won't compile - type mismatch
// let age: i32 = "25"; // Error: expected integer, found string
```

**Function Parameters:**
```rust
fn add_numbers(a: i32, b: i32) -> i32 {
    a + b
}

// This won't compile
// add_numbers(5, "10"); // Error: expected i32, found &str
```

**Type Conversion (Explicit):**
```rust
let num_str = "42";
let num: i32 = num_str.parse().unwrap(); // Must explicitly convert
```

## Weakly Typed (JavaScript)
Types are flexible and automatically converted. Type coercion happens at runtime.

### Examples

**Variable Declaration:**
```javascript
let age = 25;        // number
age = "twenty-five"; // now string - no error
```

**Automatic Type Coercion:**
```javascript
console.log(5 + "10");    // "510" (number + string = string)
console.log("5" * 2);     // 10 (string * number = number)
console.log(true + 1);    // 2 (boolean + number = number)
```

**Function Parameters:**
```javascript
function addNumbers(a, b) {
    return a + b;
}

addNumbers(5, 10);    // 15
addNumbers(5, "10");  // "510" (concatenation, not addition)
addNumbers("5", "10"); // "510"
```

## Key Differences

| Aspect | Strongly Typed (Rust) | Weakly Typed (JavaScript) |
|--------|----------------------|---------------------------|
| **Type Checking** | Compile time | Runtime |
| **Type Conversion** | Explicit only | Automatic coercion |
| **Error Detection** | Before code runs | During execution |
| **Performance** | Faster (no runtime checks) | Slower (runtime conversions) |
| **Safety** | Prevents type errors | Runtime type errors possible |

## Advantages

### Strongly Typed (Rust)
- **Early error detection** - bugs caught before deployment
- **Better performance** - no runtime type checking overhead
- **Code clarity** - explicit types document intent
- **Refactoring safety** - type system catches breaking changes

### Weakly Typed (JavaScript)
- **Flexibility** - rapid prototyping and dynamic behavior
- **Less verbose** - no need to declare types everywhere
- **Duck typing** - "if it walks like a duck, it's a duck"
- **Runtime adaptability** - can handle unexpected data gracefully

## Example: Same Logic, Different Approaches

**Rust (Strongly Typed):**
```rust
fn calculate_total(price: f64, tax_rate: f64) -> f64 {
    price * (1.0 + tax_rate)
}

// Must pass correct types
let total = calculate_total(100.0, 0.08);
```

**JavaScript (Weakly Typed):**
```javascript
function calculateTotal(price, taxRate) {
    return price * (1 + taxRate);
}

// Works with various inputs due to coercion
let total1 = calculateTotal(100, 0.08);      // numbers
let total2 = calculateTotal("100", "0.08");  // strings (coerced to numbers)
```
