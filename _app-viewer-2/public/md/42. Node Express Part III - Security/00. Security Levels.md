# Security Levels

Security concerns exist at every layer of the network stack. As web developers, we interact with most of these layers whether we realize it or not.

## Network / Transport Layer

- **Man-in-the-middle attacks** — intercepting data in transit
- **Mitigation:** HTTPS/TLS encrypts traffic between client and server

## Application Layer (HTTP)

- **Cross-Site Scripting (XSS)** — injecting malicious scripts into pages
- **Cross-Site Request Forgery (CSRF)** — tricking users into making unintended requests
- **SQL/NoSQL Injection** — manipulating queries through unsanitized input
- **Mitigation:** input validation, sanitization, CSRF tokens, security headers

## Authentication & Session Layer

- **Credential theft** — stolen passwords, session hijacking
- **Brute force attacks** — automated login attempts
- **Mitigation:** hashing (bcrypt), secure cookies, rate limiting, multi-factor auth

## Server / Infrastructure Layer

- **DDoS attacks** — overwhelming the server with traffic
- **Misconfigured servers** — exposed ports, default credentials, verbose error messages
- **Mitigation:** firewalls, load balancers, environment variables, minimal error exposure in production

## Database Layer

- **Unauthorized access** — direct DB exposure or privilege escalation
- **Data leaks** — storing sensitive data in plaintext
- **Mitigation:** least-privilege access, encryption at rest, parameterized queries

## Client Layer (Browser)

- **Malicious third-party scripts** — compromised CDNs or dependencies
- **Data exposure** — sensitive info stored in localStorage or cookies
- **Mitigation:** Content Security Policy (CSP), Subresource Integrity (SRI), HttpOnly/Secure cookie flags

---

As web developers, the **application layer** is where we have the most direct control — but awareness of every layer helps us build more secure apps end to end.
