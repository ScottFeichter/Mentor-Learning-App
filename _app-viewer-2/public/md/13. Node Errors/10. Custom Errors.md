

## Creating Custom Errors

```javascript
class ValidationError extends Error {
  constructor(message) {
    super(message);
    this.name = 'ValidationError';
  }
}

throw new ValidationError('Invalid email format');
```

## Error Object in Node.js

In Node.js, errors often include additional properties:

```javascript
const fs = require('fs');

fs.readFile('nonexistent.txt', (err, data) => {
  if (err) {
    console.log(err.message); // Error message
    console.log(err.code);    // 'ENOENT' (error code)
    console.log(err.path);    // 'nonexistent.txt'
  }
});
```

## Best Practices

**1. Always provide descriptive messages:**
```javascript
throw new Error('User ID must be a positive number');
// Better than: throw new Error('Invalid input');
```

**2. Use specific error types:**
```javascript
throw new TypeError('Expected string, got number');
// Better than: throw new Error('Wrong type');
```

**3. Catch errors appropriately:**
```javascript
try {
  riskyOperation();
} catch (error) {
  if (error instanceof ValidationError) {
    // Handle validation errors
  } else {
    // Handle other errors
    throw error; // Re-throw if you can't handle it
  }
}
```

## Summary

- Error objects represent runtime errors
- They have `message`, `name`, and `stack` properties
- Use `throw` to create errors, `try...catch` to handle them
- JavaScript has built-in error types (TypeError, ReferenceError, etc.)
- You can create custom error types by extending Error
