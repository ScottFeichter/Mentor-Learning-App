# Try Catch Finally

**Try** - code for the program to try to run.

**Catch** — code to handle a thrown error so it doesn't crash the program.

**Finally** - code to run regardless of the outcome of try.

## Catching Errors

Use a try catch in attempt to keep the program running when an error occurs.

```javascript
try {
  console.log("we are about to try to divide 10 by 0");

  let myVariable = 10/0;      // code for the program to try
                              // you don't have to throw the error here
                              // because this code will throw a built in JS error

} catch (error) {             // the arg is optional
                              // the arg is whatever was thrown
                              // is bananable
                              // can be anything
                              // most commonly an error object

  console.log(error.message); // 'Cannot divide by zero'
  console.log(error.name);    // 'Error'


} finally {                   // The finally block is optional

  console.log("I run regardless of the outcome of try");

}
```

## When would I use a Try Catch Finally block?

When you have code you suspect could fail for reasons outside your control.

Common scenarios:

- **Parsing data** — `JSON.parse(someInput)` will throw if the input isn't valid JSON. You don't control what the user or an API sends you.

- **Network requests** — `await fetch(url)` can fail if the server is down, the network drops, etc. You can't guarantee the outside world cooperates.

- **Database operations** — querying, inserting, updating. The DB could be down, the connection could timeout, a unique constraint could be violated.

- **File system operations** — reading/writing files. The file might not exist, you might not have permissions.

- **Accessing external APIs/services** — anything that leaves your process is unreliable by nature.

- **User input** — anytime you're processing something a user gave you and it could be malformed.
