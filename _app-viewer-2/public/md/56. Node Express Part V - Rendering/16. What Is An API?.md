# What Is An API?

## The Confusion

"API" is used for so many different things that it becomes confusing. You know it stands for Application Programming Interface, but what does that actually mean?

## What API Actually Means

**Application Programming Interface** = A way for code to talk to other code.

That's it. It's just an **interface** - a set of functions/methods you can call.

## Why It's Confusing: Different Contexts

### 1. Web APIs (HTTP/REST APIs)
```javascript
fetch('https://api.github.com/users/scottfeichter')
```
- Server exposes endpoints you can call over the internet
- Returns JSON data
- This is what most people think of as "an API"

### 2. Browser APIs (Web APIs)
```javascript
document.getElementById('button')  // DOM API
localStorage.setItem('key', 'value')  // Storage API
navigator.geolocation.getCurrentPosition()  // Geolocation API
```
- Functions the browser provides to JavaScript
- Let you interact with browser features

### 3. Operating System APIs
```c
// C code calling OS API
FILE* file = fopen("data.txt", "r");
```
- Functions the OS provides to programs
- Let you access files, network, hardware

### 4. Library/Framework APIs
```javascript
// React API
const [count, setCount] = useState(0);

// Node.js API
const fs = require('fs');
fs.readFile('file.txt', callback);
```
- Functions a library provides
- Let you use the library's features

### 5. Language APIs
```javascript
// JavaScript built-in API
const arr = [1, 2, 3];
arr.push(4);  // Array API
Math.random()  // Math API
```
- Built-in functions the language provides

## The Pattern

In every case, an API is:
1. **A set of functions/methods** someone else wrote
2. **That you can call** to do something
3. **Without knowing how it works internally**

## Why The Same Word?

Because they're all the same concept:
- **Interface**: The "what" you can do (function names, parameters)
- **Implementation**: The "how" it works (hidden from you)

```
You call → API (interface) → Hidden implementation does the work → Returns result
```

## Examples From Our Conversation

**"JavaScript APIs"** (Browser APIs):
```javascript
document.querySelector()  // DOM API
button.addEventListener()  // Event API
```

**"Wasm needs JavaScript APIs"**:
- Wasm can't directly access browser features
- Must call JavaScript functions (the API) to do so

**"Native apps call rendering APIs"**:
```swift
button.setBackgroundColor(.blue)  // iOS UIKit API
```

**"WASI provides APIs"**:
- Standard functions for file I/O, networking, etc.
- Wasm code calls these functions (the API)

## The Confusion

The word "API" is used for:
- Tiny things (a single function)
- Big things (entire web services)
- Local things (library functions)
- Remote things (HTTP endpoints)

But they're all the same concept: **a way to call code you didn't write**.

## Simple Rule

Whenever you see "API", replace it with **"functions I can call"**:
- "Browser API" = "Browser functions I can call"
- "REST API" = "Server functions I can call over HTTP"
- "React API" = "React functions I can call"
- "DOM API" = "DOM functions I can call"
- "Node API" = "Node functions I can call"

## The Bottom Line

API is an overloaded term, but it always means the same thing: **an interface to call code someone else wrote, without needing to know how it works internally**.

The confusion comes from the fact that this concept applies at every level of programming - from a single function to an entire web service.
