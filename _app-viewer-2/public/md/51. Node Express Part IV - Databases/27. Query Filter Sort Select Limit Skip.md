# Query, Filter, Sort, Select, Limit, Skip

Generic Database Concepts

## What is a Query?

A **query** is a request to retrieve data from a database. It's the overall operation that asks the database to find and return records or documents that match certain criteria. Every database interaction that reads data starts with a query.

In SQL databases, queries use the `SELECT` statement. In document databases like MongoDB, queries use methods like `find()`. Regardless of the database type, the concept is the same: you're asking the database to give you data.

### How ORMs/ODMs Express Queries

| Tool | Syntax |
|------|--------|
| Raw SQL | `SELECT * FROM users` |
| Prisma | `prisma.user.findMany()` |
| Sequelize | `User.findAll()` |
| Mongoose | `User.find()` |

## What is a Filter?

A **filter** is the criteria or conditions that determine which records to include in the query results. It narrows down the full dataset to only the records you care about. In SQL, this is the `WHERE` clause.

Without filters, a query returns every record in the table/collection. Filters are essential for:
- Finding specific records (e.g., a user by email)
- Narrowing results by conditions (e.g., active users over age 18)
- Reducing the amount of data processed and returned

### How ORMs/ODMs Express Filters

| Tool | Syntax |
|------|--------|
| Raw SQL | `WHERE age > 18 AND status = 'active'` |
| Prisma | `{ where: { age: { gt: 18 }, status: 'active' } }` |
| Sequelize | `{ where: { age: { [Op.gt]: 18 }, status: 'active' } }` |
| Mongoose | `{ age: { $gt: 18 }, status: 'active' }` |

### Common Filter Operations

| Operation | SQL | Description |
|-----------|-----|-------------|
| Equal | `= value` | Exact match |
| Not Equal | `!= value` | Not matching |
| Greater Than | `> value` | Above a threshold |
| Less Than | `< value` | Below a threshold |
| Greater/Equal | `>= value` | At or above |
| Less/Equal | `<= value` | At or below |
| IN | `IN (a, b, c)` | Matches any in list |
| LIKE | `LIKE '%text%'` | Pattern matching |
| IS NULL | `IS NULL` | Field has no value |
| BETWEEN | `BETWEEN a AND b` | Within a range |

### Logical Operators

- **AND**: All conditions must be true (implicit when listing multiple conditions)
- **OR**: At least one condition must be true
- **NOT**: Negates a condition

## What is Sorting?

**Sorting** (also called ordering) determines the sequence in which filtered results are returned. It doesn't change *which* records are returned, only their *order*. In SQL, this is the `ORDER BY` clause.

Sorting is important for:
- Displaying data in a meaningful order (alphabetical, newest first, etc.)
- Ensuring consistent, predictable results
- Supporting user-facing features like "sort by price"

### Sort Directions

- **Ascending (ASC)**: A→Z, 0→9, oldest→newest
- **Descending (DESC)**: Z→A, 9→0, newest→oldest

### How ORMs/ODMs Express Sorting

| Tool | Syntax |
|------|--------|
| Raw SQL | `ORDER BY name ASC, createdAt DESC` |
| Prisma | `{ orderBy: [{ name: 'asc' }, { createdAt: 'desc' }] }` |
| Sequelize | `{ order: [['name', 'ASC'], ['createdAt', 'DESC']] }` |
| Mongoose | `{ sort: { name: 1, createdAt: -1 } }` |

### Multi-Field Sorting

You can sort by multiple fields. The database sorts by the first field, then uses subsequent fields to break ties. For example, sorting by `category ASC, price DESC` groups items by category alphabetically, then within each category, shows the most expensive items first.

## What is Select?

**Select** (also called projection or field selection) determines which fields/columns are included in the returned data. It controls what data is sent back, rather than which records are returned.

Select is important for:
- **Security**: Excluding sensitive fields like passwords
- **Performance**: Less data transferred over the network
- **Efficiency**: Database only reads requested columns from disk
- **Bandwidth**: Smaller response payloads

### How ORMs/ODMs Express Select

| Tool | Syntax |
|------|--------|
| Raw SQL | `SELECT name, email FROM users` |
| Prisma | `{ select: { name: true, email: true } }` |
| Sequelize | `{ attributes: ['name', 'email'] }` |
| Mongoose | `.select('name email')` |

### Include vs Exclude

Some tools let you specify fields to include, others let you exclude fields, and some support both:

- **Include**: "Only give me these fields" — you list what you want
- **Exclude**: "Give me everything except these fields" — you list what to hide

## What is Limit?

**Limit** restricts the maximum number of records returned by a query. Even if 10,000 records match your filter, a limit of 10 means only 10 are returned. In SQL, this is the `LIMIT` clause.

Limit is essential for:
- **Pagination**: Showing results page by page
- **Performance**: Preventing massive result sets
- **User Experience**: Faster page loads
- **Resource Protection**: Preventing memory exhaustion

### How ORMs/ODMs Express Limit

| Tool | Syntax |
|------|--------|
| Raw SQL | `LIMIT 10` |
| Prisma | `{ take: 10 }` |
| Sequelize | `{ limit: 10 }` |
| Mongoose | `.limit(10)` |

## What is Skip?

**Skip** (also called offset) bypasses a specified number of records before returning results. Combined with limit, it enables pagination — showing different "pages" of results.

In SQL, this is the `OFFSET` clause.

### How ORMs/ODMs Express Skip

| Tool | Syntax |
|------|--------|
| Raw SQL | `OFFSET 20` |
| Prisma | `{ skip: 20 }` |
| Sequelize | `{ offset: 20 }` |
| Mongoose | `.skip(20)` |

## How They All Work Together

These six concepts form a pipeline for data retrieval:

```
Query → Filter → Sort → Skip → Limit → Select
```

1. **Query**: Identifies the table/collection to read from
2. **Filter**: Narrows down to matching records
3. **Sort**: Orders the matching records
4. **Skip**: Skips past records already seen (pagination)
5. **Limit**: Caps the number of records returned
6. **Select**: Picks which fields to include in the response

### SQL Example (All Together)

```sql
SELECT name, email, age       -- Select (projection)
FROM users                    -- Query (which table)
WHERE age >= 18               -- Filter (conditions)
  AND status = 'active'
ORDER BY name ASC             -- Sort (ordering)
LIMIT 10                      -- Limit (max records)
OFFSET 20;                    -- Skip (pagination offset)
```

## Pagination

Pagination is the most common use case for combining skip and limit. It allows you to show results in pages rather than all at once.

### The Pagination Formula

```
skip = (page - 1) * limit
```

| Page | Skip | Limit | Records Returned |
|------|------|-------|-----------------|
| 1 | 0 | 10 | Records 1-10 |
| 2 | 10 | 10 | Records 11-20 |
| 3 | 20 | 10 | Records 21-30 |

### Pagination Metadata

A good API returns pagination metadata alongside the data:

```json
{
  "data": [...],
  "pagination": {
    "page": 2,
    "limit": 10,
    "total": 95,
    "pages": 10,
    "hasNext": true,
    "hasPrev": true
  }
}
```

To calculate `total`, you run a separate count query with the same filter but without skip/limit.

## How They Relate to Each Other

| Concept | Affects | Depends On |
|---------|---------|------------|
| Query | Which table/collection | Nothing |
| Filter | Which records match | Query |
| Sort | Order of results | Filter (sorts only matching records) |
| Skip | Which records to bypass | Sort (skip is position-based, so order matters) |
| Limit | How many to return | Skip (limit applies after skip) |
| Select | Which fields to show | All above (applies to final result set) |

### Important Relationships

- **Filter before Sort**: You sort only the records that passed the filter
- **Sort before Skip/Limit**: Skip and limit are positional, so the order must be established first
- **Skip before Limit**: Skip removes records from the front, then limit caps the remainder
- **Select is independent**: It doesn't affect which records are returned or their order, only what fields are visible

## Performance Considerations

- **Filters** should use indexed columns for fast lookups
- **Sorting** on indexed columns is much faster than non-indexed
- **Select** reduces I/O and network transfer
- **Limit** prevents runaway queries from consuming resources
- **Skip** with large offsets can be slow (the database still reads skipped records)

## Key Takeaways

- These six operations are universal across all databases and ORMs
- They combine to give you precise control over data retrieval
- The syntax differs between tools, but the concepts are identical
- Proper use of these operations is critical for application performance
- Pagination (skip + limit) is essential for any production application
