# Transactions

## What Is a Transaction?

A **transaction** is a group of database operations that must either ALL succeed or ALL fail together. There is no partial completion.

Think of it like transferring money between bank accounts - you need to subtract from one account AND add to another. If only one happens, the data is corrupted.

## ACID Properties

Transactions follow four rules known as **ACID**:

| Property | Meaning |
|---|---|
| **A**tomicity | All operations succeed or none do |
| **C**onsistency | Database moves from one valid state to another |
| **I**solation | Concurrent transactions don't interfere with each other |
| **D**urability | Once committed, data survives crashes |

## Basic Syntax

```sql
BEGIN;  -- Start transaction

UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;

COMMIT;  -- All succeeded, save changes
```

If something fails:
```sql
BEGIN;

UPDATE accounts SET balance = balance - 100 WHERE id = 1;
-- Something goes wrong here...

ROLLBACK;  -- Undo everything, database unchanged
```

## In Node.js (PostgreSQL Example)

```javascript
const client = await pool.connect();

try {
  await client.query('BEGIN');
  await client.query('UPDATE accounts SET balance = balance - 100 WHERE id = $1', [1]);
  await client.query('UPDATE accounts SET balance = balance + 100 WHERE id = $1', [2]);
  await client.query('COMMIT');
} catch (error) {
  await client.query('ROLLBACK');
  throw error;
} finally {
  client.release();
}
```

## When to Use Transactions

- Transferring money between accounts
- Creating related records that depend on each other
- Any operation where partial completion would leave bad data
- Batch updates that must all succeed or all fail

## Key Takeaway

Transactions guarantee that your database never ends up in a broken or inconsistent state, even if errors occur or the system crashes mid-operation.
