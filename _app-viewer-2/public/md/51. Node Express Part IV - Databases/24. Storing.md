# Storing Data

## What Is Storing?

**Storing** is the act of writing data to a database so it persists. In SQL, this is done with the `INSERT` statement.

## Basic Insert

```sql
INSERT INTO users (name, email, age) VALUES ('John', 'john@example.com', 25);
```

## Inserting Multiple Rows

```sql
INSERT INTO users (name, email, age) VALUES
  ('John', 'john@example.com', 25),
  ('Sarah', 'sarah@example.com', 30),
  ('Mike', 'mike@example.com', 22);
```

## In Node.js

```javascript
// Single insert
const result = await pool.query(
  'INSERT INTO users (name, email, age) VALUES ($1, $2, $3) RETURNING *',
  ['John', 'john@example.com', 25]
);

// The new row
console.log(result.rows[0]);
```

## What Happens When You Store Data

1. Database checks constraints (NOT NULL, UNIQUE, FOREIGN KEY, etc.)
2. If constraints pass, data is written to disk
3. Any indexes on the table are updated
4. The new row is available for queries

## If Constraints Fail

```sql
-- If email has a UNIQUE constraint:
INSERT INTO users (email) VALUES ('john@example.com');  -- Works
INSERT INTO users (email) VALUES ('john@example.com');  -- ERROR: duplicate
```

The database rejects the insert and the data is not stored.

## Key Takeaway

Storing data is straightforward, but the database enforces all constraints and rules before allowing data in. This is why proper schema design matters - it protects your data at the storage level.
