# Data Constraints

## What Are Constraints?

**Constraints** are rules enforced at the database level that control what data can be stored. They are the last line of defense for data integrity - even if your application code has a bug, constraints prevent bad data from entering the database.

## Common Constraints

### NOT NULL

Prevents a column from having empty (null) values.

```sql
CREATE TABLE users (
  name TEXT NOT NULL  -- name is required
);

INSERT INTO users (name) VALUES (NULL);  -- ERROR
```

### UNIQUE

Prevents duplicate values in a column.

```sql
CREATE TABLE users (
  email TEXT UNIQUE  -- no two users can have the same email
);

INSERT INTO users (email) VALUES ('john@example.com');
INSERT INTO users (email) VALUES ('john@example.com');  -- ERROR
```

### PRIMARY KEY

Combines NOT NULL and UNIQUE. Identifies each row uniquely.

```sql
CREATE TABLE users (
  id INTEGER PRIMARY KEY
);
```

### FOREIGN KEY

Ensures a value in one table exists in another table.

```sql
CREATE TABLE orders (
  user_id INTEGER,
  FOREIGN KEY (user_id) REFERENCES users(id)
);

-- Cannot insert an order for a user that doesn't exist
INSERT INTO orders (user_id) VALUES (999);  -- ERROR if user 999 doesn't exist
```

### CHECK

Enforces a custom condition on values.

```sql
CREATE TABLE users (
  age INTEGER CHECK (age >= 0 AND age <= 150)
);

INSERT INTO users (age) VALUES (-5);  -- ERROR
```

### DEFAULT

Provides a value when none is specified.

```sql
CREATE TABLE users (
  role TEXT DEFAULT 'user',
  created_at TIMESTAMP DEFAULT NOW()
);

INSERT INTO users (name) VALUES ('John');  -- role automatically set to 'user'
```

## Why Constraints Matter

- **Data integrity** - bad data can never enter the database
- **Application-independent** - protects data even if app code has bugs
- **Documentation** - constraints describe the rules of your data
- **Performance** - the database can optimize based on constraints

## Constraints vs Application Validation

| | Application Validation | Database Constraints |
|---|---|---|
| **Where** | Server code | Database level |
| **Can be bypassed?** | Yes (bugs, direct DB access) | No |
| **Error messages** | User-friendly | Technical |
| **Speed** | Catches errors early | Last line of defense |

**Best practice:** Use both. Validate in your application for user-friendly errors, and use constraints as a safety net.
