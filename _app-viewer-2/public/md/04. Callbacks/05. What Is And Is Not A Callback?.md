### Function Definition by Reference (No Parentheses!!!)

- This **IS** a callback.
- Passing a reference identifier passes the function definition itself as a value:

```javascript
function sayHello() {
  return "Hello!";
}

console.log(sayHello);    // Logs: [Function: sayHello]
```

### Function Call (With Parentheses)

- This is **NOT** a callback.
- Executes the function immediately and logs the result:

```javascript
console.log(sayHello());  // Logs: "Hello!"
```

## Function Defined inline in Argument list is still a Reference

- This **IS** a callback.
- Even when you define a function directly in the argument, it's still a function reference.
- The paramter is the identifier used to invoke the callback in the receiving function body:

```javascript
function receiveCallback(theCallbackParam) {
  console.log("About to call callback");
  theCallbackParam();
  console.log("Callback finished");
}
```

- In this case the pointer/reference/identifier is theCallbackParam.
- This is the function parameter as defined in the recieving function.
- Passing a function definition in the arg list assigns it to the identifer.

```javascript
// Function defined inline - this is STILL a function reference
receiveCallback(function theCallbackArg() {
  console.log("I'm the callback!");
});

// Output:
// "About to call callback"
// "I'm the callback!"
// "Callback finished"
```

- Therefore when we define the function inline (in the argument):
- The pointer/reference/identifier is the parameter in the recieving function definition.
- The callback is the argument which is a callback function definition.

The function `function theCallbackArg() { console.log("I'm the callback!"); }` is passed as a reference, not executed immediately. The `receiveCallback` function decides when to call it.
