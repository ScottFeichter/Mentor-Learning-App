# Big O Notation

## What is "Better"?

When comparing algorithms, "better" can mean:
- Faster?
- More readable?
- Less memory?
- Better at scale?

Rather than using a timer (which may or may not be a good indicator), we count the number of simple operations.

## Asymptotic Notation

- **Big O** — Upper Bound (Worst Case)
- **Big Ω (Omega)** — Lower Bound (Best Case)
- **Big Θ (Theta)** — Tight Bound (Average Case)

## Big O Classes

| Notation | Name | Description |
|----------|------|-------------|
| O(1) | Constant | Operations remain constant regardless of input size N |
| O(log n) | Logarithmic | Grows very slowly — nearly flat |
| O(n) | Linear | Operations grow in proportion to input size N |
| O(n log n) | Linear-logarithmic | The best possible sort complexity |
| O(n²) | Quadratic | Often an O(n) operation inside an O(n) operation |
| O(2ⁿ) | Exponential | Doubles with each additional input |
| O(n!) | Factorial | Grows astronomically fast |

## Logarithms

The **logarithm** of a number roughly measures the number of times you can divide that number by 2 before you get a value ≤ 1. This is the inverse of exponentiation.

**When we reference log in Big O notation, it is always log₂.**

We use base 2 in computers because computers use binary.

**N is always expressed as 1** (i.e., we don't write O(1n), just O(n)).
