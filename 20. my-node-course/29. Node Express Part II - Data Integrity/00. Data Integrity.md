# Data Integrity

## What Is It?

Data integrity means that the data in your system is **accurate**, **consistent**, and **trustworthy** throughout its entire lifecycle — from the moment it's created to when it's read, updated, or deleted.

## Why It Matters

- **Bad data = bad decisions.** If a user's email is stored incorrectly, password resets break. If an order total is wrong, you lose money or trust.
- **Corrupted or inconsistent data** can cascade through your app and cause bugs that are extremely hard to track down.
- **Users expect reliability.** If they submit a form, they expect the data to be saved exactly as intended.

## How It Relates to Web Development

In a web app (like one built with Node/Express), data flows through many layers — client, server, database. Integrity can break at any point:

- **Client side:** A user submits an empty required field or a string where a number is expected.
- **Server side:** Your route handler trusts the incoming data without checking it.
- **Database level:** The DB accepts a duplicate email or a null value where one shouldn't exist.

To protect data integrity we use techniques like:

- **Validation** — checking that data meets expected rules before saving it
- **Sanitization** — cleaning input to remove unwanted or dangerous content
- **Constraints** — enforcing rules at the database level (unique, not null, foreign keys)
- **Error handling** — catching and responding to problems gracefully instead of silently failing
