# Oracle Database

## What Is Oracle Database?

**Oracle Database** is a proprietary, enterprise-grade relational database management system developed by Oracle Corporation. It's one of the oldest and most powerful commercial databases, dominant in large enterprises, financial institutions, and government systems.

## History

- **1977**: Larry Ellison, Bob Miner, and Ed Oates founded Software Development Laboratories (later Oracle)
- **1979**: Oracle V2 released — first commercially available SQL-based RDBMS
- **1983**: Oracle V3 — rewritten in C for portability
- **1992**: Oracle 7 — stored procedures, triggers, PL/SQL matured
- **2001**: Oracle 9i — "i" for internet, RAC (Real Application Clusters)
- **2013**: Oracle 12c — "c" for cloud, multitenant architecture
- **2018**: Oracle 18c — autonomous database features
- **Today**: Oracle remains dominant in banking, telecom, healthcare, and government

## Key Features

- PL/SQL — Oracle's procedural SQL extension
- Real Application Clusters (RAC) — multi-node clustering
- Data Guard — disaster recovery and high availability
- Multitenant architecture — pluggable databases
- Advanced partitioning
- In-memory column store
- Advanced security (encryption, auditing, data masking)
- Flashback technology (point-in-time recovery)
- Materialized views with automatic refresh
- Advanced analytics and machine learning built-in
- JSON and XML native support

## Installation (macOS/Linux via Docker)

Oracle doesn't run natively on macOS. Use Docker with Oracle XE:

```bash
# Pull Oracle XE image
docker pull gvenzl/oracle-xe:21-slim

# Run the container
docker run -d --name oracle-xe \
  -p 1521:1521 \
  -e ORACLE_PASSWORD=mypassword \
  gvenzl/oracle-xe:21-slim

# Wait for startup (takes 1-2 minutes)
docker logs -f oracle-xe
```

## Running Locally (SQL*Plus Shell)

### Connect to Oracle

```bash
# Connect via Docker
docker exec -it oracle-xe sqlplus system/mypassword@//localhost:1521/XEPDB1

# Or if installed locally
sqlplus username/password@//localhost:1521/servicename
```

### Basic Shell Commands

```sql
-- List all tables (current user)
SELECT table_name FROM user_tables;

-- Describe a table
DESCRIBE users;

-- Show current user
SELECT USER FROM dual;

-- Show all users
SELECT username FROM all_users;

-- Quit
EXIT;

-- Run a SQL file
@/path/to/file.sql
```

### Basic SQL Operations

```sql
-- Create a table
CREATE TABLE users (
  id NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name VARCHAR2(100) NOT NULL,
  email VARCHAR2(255) UNIQUE NOT NULL,
  age NUMBER CHECK (age >= 0),
  created_at TIMESTAMP DEFAULT SYSTIMESTAMP
);

-- Insert data
INSERT INTO users (name, email, age) VALUES ('John', 'john@example.com', 30);
COMMIT;

-- Query data
SELECT * FROM users WHERE age > 21 ORDER BY name;

-- Pagination (Oracle style)
SELECT * FROM users OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY;

-- Update data
UPDATE users SET age = 31 WHERE email = 'john@example.com';
COMMIT;

-- Delete data
DELETE FROM users WHERE id = 1;
COMMIT;
```

### Oracle-Specific Notes

```sql
-- Oracle requires COMMIT after DML (INSERT/UPDATE/DELETE)
-- No BOOLEAN type (use NUMBER(1) with 0/1)
-- VARCHAR2 instead of VARCHAR (Oracle recommends VARCHAR2)
-- DUAL table for selecting expressions: SELECT SYSDATE FROM dual;
-- Sequences for auto-increment (or IDENTITY in 12c+)
-- NVL() instead of COALESCE() (though COALESCE works too)
-- ROWNUM for limiting (legacy): SELECT * FROM users WHERE ROWNUM <= 10;
```

## Running Remotely

### Connection String Format (TNS)

```
(DESCRIPTION=(ADDRESS=(PROTOCOL=TCP)(HOST=host)(PORT=1521))(CONNECT_DATA=(SERVICE_NAME=myservice)))
```

```
username/password@host:port/service_name
```

### Connecting from Node.js

```javascript
// Using oracledb
const oracledb = require('oracledb');

const connection = await oracledb.getConnection({
  user: 'myuser',
  password: 'mypassword',
  connectString: 'localhost:1521/XEPDB1'
});

const result = await connection.execute('SELECT * FROM users');
console.log(result.rows);
await connection.close();
```

## Default Port

**1521**

## When to Use Oracle

- Large enterprise applications
- Financial systems requiring maximum reliability
- Government and healthcare (compliance requirements)
- When you need RAC for horizontal scaling
- Legacy systems already on Oracle
- When budget is not a constraint
- Complex data warehousing and analytics

## When NOT to Use Oracle

- Startups or small projects (cost prohibitive)
- Simple web applications
- When open-source is preferred
- When you want to avoid vendor lock-in
