# Security Headers

## Headers in General

HTTP headers are **key-value pairs** sent along with every request and response. They carry metadata about the communication — not the body content itself.

In Express, you can access request headers via `req.headers`:

```js
app.get('/', (req, res) => {
  console.log(req.headers);
  // {
  //   host: 'localhost:3000',
  //   'user-agent': 'Mozilla/5.0 ...',
  //   accept: 'text/html',
  //   'content-type': 'application/json',
  //   authorization: 'Bearer <token>',
  //   cookie: 'sessionId=abc123',
  //   ...
  // }
});
```

Common header categories:

- **Request headers** — sent by the client (e.g. `Accept`, `Authorization`, `Content-Type`, `Cookie`)
- **Response headers** — sent by the server (e.g. `Set-Cookie`, `Content-Type`, `Cache-Control`)
- **Security headers** — a subset of response headers that tell the browser how to behave securely

## Security Headers

Security headers are **response headers** set by the server to instruct the browser on how to handle content, connections, and permissions. The browser enforces them.

### Key Security Headers

| Header | What It Does |
|---|---|
| `Content-Security-Policy` (CSP) | Restricts where scripts, styles, images, etc. can be loaded from. Prevents XSS by blocking inline scripts and unauthorized sources. |
| `Strict-Transport-Security` (HSTS) | Forces the browser to only use HTTPS for future requests to your domain. Prevents downgrade attacks. |
| `X-Content-Type-Options` | Set to `nosniff` — prevents the browser from guessing (MIME sniffing) the content type. Forces it to trust the declared `Content-Type`. |
| `X-Frame-Options` | Controls whether your site can be embedded in an `<iframe>`. Prevents clickjacking attacks. Values: `DENY` or `SAMEORIGIN`. |
| `X-XSS-Protection` | Legacy header that enabled the browser's built-in XSS filter. Mostly deprecated in favor of CSP, but still set for older browsers. |
| `Referrer-Policy` | Controls how much referrer (URL) info is sent when navigating away from your site. Limits data leakage. |
| `Permissions-Policy` | Controls which browser features (camera, microphone, geolocation) your site can use. |
| `Cross-Origin-Opener-Policy` | Isolates your browsing context from cross-origin windows. Prevents certain side-channel attacks. |
| `Cross-Origin-Resource-Policy` | Controls which origins can load your resources. Prevents unauthorized embedding. |

### Example — Setting a Header Manually in Express

```js
app.use((req, res, next) => {
  res.setHeader('X-Content-Type-Options', 'nosniff');
  next();
});
```

You *could* set each header manually, but that's tedious and error-prone.

## Helmet

**Helmet** is an Express middleware package that sets sensible security headers for you in one line:

```bash
npm install helmet
```

```js
const helmet = require('helmet');
app.use(helmet());
```

By default, `helmet()` sets most of the headers listed above with secure defaults. You can also configure individual headers:

```js
app.use(helmet({
  contentSecurityPolicy: {
    directives: {
      defaultSrc: ["'self'"],
      scriptSrc: ["'self'", "trusted-cdn.com"],
    },
  },
  frameguard: { action: 'deny' },
}));
```

Helmet is widely trusted, actively maintained, and is one of the first things you should add to any Express app going into production.
