# Node.js vs Browser JavaScript

## JavaScript Versions

### Node.js
- **Version Control**: Tied to Node.js version, not browser
- **ES Support**: Modern Node.js (14+) supports most ES2020+ features
- **Check Support**: Run `node --v8-options | grep harmony` to see available features
- **Upgrade**: Update Node.js version to get newer ES features

### Browser
- **Version Control**: Depends on user's browser version
- **ES Support**: Varies widely (IE11 vs Chrome vs Safari)
- **Check Support**: Use [caniuse.com](https://caniuse.com)
- **Solution**: Transpile with Babel for older browser support

## Key Differences

### Global Objects

**Node.js**:
```javascript
global          // Global namespace
process         // Process information
__dirname       // Current directory path
__filename      // Current file path
Buffer          // Binary data handling
```

**Browser**:
```javascript
window          // Global namespace
document        // DOM access
navigator       // Browser information
location        // URL information
localStorage    // Client-side storage
```

### APIs Available

| Feature | Node.js | Browser |
|---------|---------|---------|
| File System | ✅ `fs` module | ❌ (limited File API) |
| HTTP Server | ✅ `http` module | ❌ |
| DOM Manipulation | ❌ | ✅ `document` |
| Fetch API | ✅ (Node 18+) | ✅ |
| WebSockets | ✅ (via libraries) | ✅ Native |
| Crypto | ✅ `crypto` module | ✅ Web Crypto API |

### Module Systems

**Node.js**:
- CommonJS (default)
- ES Modules (with config)
- Can use both with proper setup

**Browser**:
- ES Modules only (native)
- CommonJS requires bundler (Webpack, Rollup)
- `<script type="module">` for ESM

### Environment Detection

```javascript
// Check if running in Node.js
if (typeof process !== 'undefined' && process.versions?.node) {
  console.log('Running in Node.js');
}

// Check if running in browser
if (typeof window !== 'undefined') {
  console.log('Running in browser');
}
```

### Asynchronous Patterns

**Node.js**:
- Callbacks (legacy)
- Promises
- async/await
- Event emitters
- Streams

**Browser**:
- Promises
- async/await
- Event listeners
- Web Workers

### Performance Considerations

**Node.js**:
- Single-threaded event loop
- Worker threads for CPU-intensive tasks
- No rendering/painting overhead
- Direct file system access

**Browser**:
- Single-threaded per tab
- Web Workers for parallel processing
- Rendering/painting affects performance
- Sandboxed environment (security restrictions)

## Best Practices

### For Node.js
- Use latest LTS version for production
- Use ES Modules for new projects
- Leverage built-in modules (fs, path, http)
- Handle errors with try/catch and error events

### For Browser
- Transpile for older browser support
- Use polyfills for missing features
- Bundle and minify code
- Consider browser compatibility matrix
- Test across different browsers

## Universal JavaScript (Isomorphic)

Code that runs in both environments:

**Works Everywhere**:
- Core JavaScript (variables, functions, classes)
- Promises and async/await
- Array/Object methods
- JSON operations
- Math operations

**Requires Abstraction**:
- HTTP requests (use fetch or axios)
- Storage (localStorage vs file system)
- Environment variables (process.env vs config)

## When to Use What

**Node.js**:
- Backend APIs
- Build tools
- CLI applications
- Server-side rendering
- Microservices

**Browser**:
- User interfaces
- Client-side interactions
- DOM manipulation
- Visual rendering
- User input handling
