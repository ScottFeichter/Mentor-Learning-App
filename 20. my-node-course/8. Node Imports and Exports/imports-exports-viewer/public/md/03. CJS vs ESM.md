# CommonJS vs ES Modules

## File Extensions

### CommonJS
- `.js` - Default in Node.js (when no `"type"` in package.json)
- `.cjs` - Explicitly CommonJS (always treated as CJS)

### ES Modules
- `.mjs` - Explicitly ES Module (always treated as ESM)
- `.js` - Treated as ESM when `"type": "module"` in package.json

## Syntax Differences

### CommonJS
```javascript
// Exporting
module.exports = { func1, func2 };
exports.func1 = func1;

// Importing
const module = require('./module');
```

### ES Modules
```javascript
// Exporting
export { func1, func2 };
export default func1;

// Importing
import module from './module.js';
import { func1, func2 } from './module.js';
```

## Key Differences

| Feature | CommonJS | ES Modules |
|---------|----------|------------|
| Syntax | `require()` / `module.exports` | `import` / `export` |
| Loading | Synchronous | Asynchronous |
| Default | Yes (without config) | Requires `.mjs` or package.json config |
| `__dirname` | Available | Not available (use `import.meta.url`) |
| Top-level await | No | Yes |
| File extension in imports | Optional | Required |

## Package.json Configuration

```json
{
  "type": "module"
}
```
With this setting, all `.js` files are treated as ES Modules.
