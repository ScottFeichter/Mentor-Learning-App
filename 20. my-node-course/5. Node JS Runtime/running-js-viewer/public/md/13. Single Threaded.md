# JavaScript Single Threaded Execution

## JavaScript Agent
An agent is an autonomous executor of JS that maintains:
- **Heap** (of objects)
- **Queue** (of jobs) (aka the event loop)
- **Stack** (of execution contexts)

## Function Definition vs Invocation

### Function Definition:
- Creates a binding (variable name) that points to a function object stored in the heap
- The function object contains the code, scope chain, and other metadata
- No execution context is created at this point

### Function Invocation:
- Creates a new execution context and pushes it onto the call stack
- The execution context contains:
  - Variable environment (local variables, parameters)
  - Lexical environment (scope chain)
  - "this" binding
  - Reference to the outer environment

## JavaScript Execution Flow

1. **Initial parsing**: JS reads top to bottom, executing synchronous code immediately
2. **Asynchronous operations**: When encountered, these don't execute immediately - instead, their callbacks/handlers get queued for later execution
3. **Job queue**: Receives jobs from completed async operations (timers, promises, I/O, etc.)
4. **Event loop**: Continuously checks if the call stack is empty, then moves jobs from queue to stack

### Key Points About Functions:
- Functions themselves don't automatically create execution contexts just by being defined
- Execution contexts are created only when functions are invoked/called
- Each function call pushes a new execution context onto the call stack
- When the function completes, its execution context is popped from the stack

## Stack vs Queue Distinction

- **Call stack**: LIFO (Last In, First Out) - stores execution contexts of currently running functions
- **Job queue**: FIFO (First In, First Out) - stores pending jobs waiting to be executed

**Flow**: Code parsing → Async operations queue jobs → Event loop moves jobs to call stack → Function calls create execution contexts on the stack

## Single-Threaded Nature

### JavaScript's Single-Threaded Execution:
- There is only **one call stack** per JavaScript thread
- Only **one execution context** can be actively running at any given moment
- The currently executing context is always at the **top of the stack**

### This Means:
- JavaScript cannot execute multiple functions simultaneously
- When a function is running, everything else waits
- Even if there are jobs in the queue, they must wait until the call stack is empty

### Example of Blocking:
```javascript
function slowFunction() {
  // This blocks everything else
  for (let i = 0; i < 1000000000; i++) {}
}

setTimeout(() => console.log('timer'), 0);
slowFunction(); // Blocks the timer callback
console.log('done');
```

The timer callback sits in the job queue but cannot execute until `slowFunction()` completes and its execution context is popped from the stack.

### Why This Matters:
- JavaScript needs the event loop for concurrency
- Async operations are handled by the browser/Node.js APIs (separate threads)
- Only the JavaScript execution itself is single-threaded

**Key Insight**: One call stack = single-threaded execution = only one thing runs at a time.

## CPU Threads vs JavaScript Single-Threading

### JavaScript's "Single-Threaded" Refers To:
- The JavaScript **execution engine** uses one thread for running JS code
- Only one call stack, one event loop per JS thread
- Your JS code cannot run in parallel with itself

### But the Overall System Uses Multiple CPU Threads:
- **Browser/Node.js APIs** run on separate threads (file I/O, network requests, timers)
- **Garbage collection** may use separate threads
- **JIT compilation** happens on background threads
- **Web Workers** create entirely separate JS threads

### Example:
```javascript
// This JS code runs on the main JS thread
console.log('start');

// setTimeout handler runs on a separate system thread
setTimeout(() => {
  console.log('timer'); // Callback executes back on main JS thread
}, 1000);

// File reading happens on I/O thread pool
fs.readFile('file.txt', (data) => {
  console.log(data); // Callback executes back on main JS thread
});

console.log('end');
```

### Summary:
- **JavaScript execution**: Single-threaded (one CPU thread for your JS code)
- **JavaScript runtime environment**: Multi-threaded (uses multiple CPU threads for system operations)

The "single-threaded" nature is about the **execution model** of your JavaScript code, not about the entire system using only one CPU thread.
