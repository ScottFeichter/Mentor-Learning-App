JS is executed linearly from top to bottom, line by line.

Therefore JS code is ran in a queue like manner;

However, order of the queue depends on branching logic.

Therefore it is rare that a program of any significant size would run as appears in a file, line by line, top to bottom.

Additionally, JS generally runs on a single thread;

This means each task must be processed and complete before moving to the next task.

There are ways to multithread with JS but this is very advanced and isn't necessary in most cases.

If a task stalls it will block the exectution of all tasks.

Since JS has clever solutions to keep execution flowing on a single thread it is not necessary to utilize multithreading with JS in most cases.

Furthermore, every function call creates its own execution context.

The execution context of functions behaves like a stack.
