# JavaScript Compilation and Interpretation

JavaScript goes through multiple compilation stages in modern engines:

## JavaScript Compilation Pipeline

### 1. **Parsing**
- Source code → Abstract Syntax Tree (AST)
- Syntax validation and structure analysis

### 2. **Bytecode Generation**
- AST → Intermediate bytecode (not machine code)
- Platform-independent instructions
- Example engines: V8 (Ignition), SpiderMonkey, JavaScriptCore

### 3. **Interpretation**
- Bytecode executed by virtual machine interpreter
- Slower but works immediately

### 4. **Just-In-Time (JIT) Compilation**
- Hot code paths → optimized machine code
- **Baseline compiler**: Quick compilation for frequently used code
- **Optimizing compiler**: Heavy optimization for very hot code (V8's TurboFan)

## Example Flow in V8:
```
JavaScript source
    ↓ (Parser)
Abstract Syntax Tree
    ↓ (Ignition)
Bytecode
    ↓ (Interpreter)
Execution
    ↓ (Profiler detects hot code)
Machine Code (TurboFan)
```

## Key Points:
- **Not transpiled** to other high-level languages
- **Compiled to bytecode** first, then optionally to machine code
- **JIT compilation** happens at runtime based on usage patterns
- **Deoptimization** can fall back to bytecode if assumptions break

Modern JS engines are sophisticated compilers, not simple interpreters. The "interpreted" label is outdated - today's JavaScript is compiled multiple times during execution for optimal performance.
