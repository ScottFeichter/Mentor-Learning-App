# Environments

**Environment** refers to the circumstances that the project runs in.

## Common Environments

- **Development** - your local machine where you write and test code
- **Testing** - where automated tests run to verify code works
- **Production** - live code that is up and running for end users

## Why It Matters

In a **development** environment, your project would look for all resources on your local machine. A resource could be a database.

In a **production** environment, the database would not be on your local machine - rather on a dedicated database machine.

## Example

Your `package.json` can have different dependencies for different environments:

- `dependencies` - needed in all environments (including production)
- `devDependencies` - needed only during development (testing tools, linters, etc.)
