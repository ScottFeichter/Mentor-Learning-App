# Connection Parameters

## URL Parameters Explained

The DATABASE_URL can include query parameters that configure connection behavior:

```bash
DATABASE_URL="postgresql://user:pass@host:5432/mydb?schema=public&sslmode=require&connection_limit=5"
```

## Common Parameters

### schema
```bash
?schema=public
```
- Specifies which PostgreSQL schema to use
- Default is `public`
- PostgreSQL databases can have multiple schemas (namespaces for tables)

### sslmode
```bash
?sslmode=require
```
- Controls SSL/TLS encryption for the connection
- **Required** for most cloud-hosted databases
- Values: `disable`, `prefer`, `require`, `verify-ca`, `verify-full`

### connection_limit
```bash
?connection_limit=5
```
- Maximum number of connections in the pool
- Default varies by environment
- Serverless environments often need lower limits (1-5)
- Traditional servers can use higher limits (10-20)

### pool_timeout
```bash
?pool_timeout=10
```
- Seconds to wait for a connection from the pool
- If no connection is available within this time, an error is thrown

### connect_timeout
```bash
?connect_timeout=10
```
- Seconds to wait when establishing a new connection
- Useful for remote databases with network latency

### pgbouncer
```bash
?pgbouncer=true
```
- Indicates the connection goes through PgBouncer (connection pooler)
- Disables features incompatible with PgBouncer (like prepared statements)
- Common with Supabase and other pooled connections

## Environment-Specific Configurations

### Development (Local)
```bash
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/myapp_dev"
```
- No SSL needed
- Higher connection limits fine
- Direct connection

### Testing
```bash
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/myapp_test"
```
- Separate database for tests
- Can be wiped between test runs

### Production (Cloud)
```bash
DATABASE_URL="postgresql://user:pass@host:5432/myapp?sslmode=require&connection_limit=10"
```
- SSL required
- Connection pooling recommended
- Appropriate connection limits

### Serverless (Neon, Vercel)
```bash
DATABASE_URL="postgresql://user:pass@host:5432/mydb?sslmode=require&pgbouncer=true&connection_limit=1"
DIRECT_URL="postgresql://user:pass@host:5432/mydb?sslmode=require"
```
- Very low connection limits
- Pooled URL for queries
- Direct URL for migrations

## Security Best Practices

- **Never** commit DATABASE_URL to version control
- Store in `.env` file (add `.env` to `.gitignore`)
- Use different credentials for dev/staging/production
- Rotate passwords periodically
- Use SSL in production (`sslmode=require`)
