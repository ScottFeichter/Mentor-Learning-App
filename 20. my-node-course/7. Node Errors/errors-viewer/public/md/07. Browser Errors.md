# Browser Errors

Standard JS errors like `TypeError`, `ReferenceError`, `SyntaxError`, etc. are defined by the ECMAScript spec and exist in any JS runtime.

The errors below only exist in the browser because they come from **Web APIs** that browsers implement.

---

## DOMException

- The most common browser-specific error.
- Thrown by DOM and Web API operations.
- It has
        - a `name` property that tells you what went wrong - and a numeric `code` for legacy compatibility.

```javascript
// Example: trying to manipulate an invalid DOM operation
try {
  document.querySelectorAll("///invalid");
} catch (e) {
  console.log(e instanceof DOMException); // true
  console.log(e.name);    // "SyntaxError" (but it's a DOMException, not a JS SyntaxError)
  console.log(e.message); // describes the DOM-specific issue
}
```

`DOMException` has many named variants. Some common ones:

| Name | When It's Thrown |
|------|-----------------|
| `NotFoundError` | A node was not found (e.g. removing a child that doesn't exist) |
| `HierarchyRequestError` | Trying to insert a node where it's not allowed |
| `InvalidStateError` | An object is in a state where the operation can't be performed |
| `NotAllowedError` | The user or browser denied permission (e.g. autoplay blocked, clipboard access denied) |
| `AbortError` | An operation was aborted (e.g. a fetch was cancelled via AbortController) |
| `SecurityError` | A security violation (e.g. accessing cross-origin iframe content) |
| `NetworkError` | A network operation failed at the browser level |
| `TimeoutError` | An operation timed out |
| `DataCloneError` | Data could not be cloned (e.g. trying to postMessage a function to a Web Worker) |
| `QuotaExceededError` | Storage quota exceeded (e.g. localStorage is full) |
| `ConstraintError` | An IndexedDB constraint was violated |
| `ReadOnlyError` | Attempted to write in a read-only IndexedDB transaction |
| `InvalidAccessError` | An invalid parameter was passed to a Web API method |
| `EncodingError` | Encoding/decoding failed (e.g. with TextDecoder) |

## SecurityError

Thrown when you violate the browser's same-origin policy or other security restrictions.

```javascript
// Trying to access a cross-origin iframe's content
try {
  let frame = document.getElementById("cross-origin-iframe");
  let doc = frame.contentDocument; // SecurityError
} catch (e) {
  console.log(e.name); // "SecurityError"
}
```

---

## NotAllowedError

Thrown when the browser blocks an action that requires user interaction or permission.

```javascript
// Trying to autoplay a video without user interaction
try {
  await video.play();
} catch (e) {
  console.log(e.name); // "NotAllowedError"
}

// Trying to access clipboard without permission
try {
  await navigator.clipboard.readText();
} catch (e) {
  console.log(e.name); // "NotAllowedError"
}
```

---

## QuotaExceededError

Thrown when browser storage is full.

```javascript
// localStorage has a ~5MB limit in most browsers
try {
  localStorage.setItem("key", hugeString);
} catch (e) {
  console.log(e.name); // "QuotaExceededError"
}
```

---

## AbortError

Thrown when an operation is explicitly cancelled.

```javascript
const controller = new AbortController();
controller.abort();

try {
  await fetch("/api/data", { signal: controller.signal });
} catch (e) {
  console.log(e.name); // "AbortError"
}
```

---

## Unhandled Promise Rejection (browser behavior)

Not an error type per se, but the browser fires an `unhandledrejection` event when a Promise rejects and nothing catches it. This is a **browser-level behavior**, not part of the JS spec.

```javascript
window.addEventListener("unhandledrejection", (event) => {
  console.log(event.reason); // the rejection value
  event.preventDefault();    // prevents the default console error
});
```

## Event-Based Errors (not thrown, but fired)

These don't use `throw` — they fire error **events** on elements. You can't catch them with try/catch.

```javascript
// Image fails to load
const img = new Image();
img.onerror = (e) => {
  console.log("Image failed to load");
};
img.src = "https://bad-url.com/nope.png";

// Script fails to load
const script = document.createElement("script");
script.onerror = (e) => {
  console.log("Script failed to load");
};
script.src = "https://bad-url.com/nope.js";
document.head.appendChild(script);
```

The global `window.onerror` handler catches uncaught runtime errors in the browser:

```javascript
window.onerror = (message, source, lineno, colno, error) => {
  console.log("Global error:", message);
};
```

---

## Key Takeaway

Standard JS errors (`TypeError`, `ReferenceError`, `SyntaxError`, `RangeError`, `URIError`, `EvalError`) come from the **language itself** and exist in every JS runtime.

Browser errors mostly come through `DOMException` and its named variants, and they originate from **Web APIs** — the DOM, Fetch, Storage, Media, Clipboard, IndexedDB, etc. These only exist in the browser because the browser is the one providing those APIs.

You won't see these errors in Node.js because Node doesn't have a DOM, localStorage, or the other browser Web APIs.
