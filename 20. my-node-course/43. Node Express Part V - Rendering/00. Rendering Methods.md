# Rendering Methods

There are 5 primary methods for rendering content to the browser:

## 1. SSG — Static Site Generation

Pages are pre-built at **build time** and served as static HTML files.

Fast and cheap to host, but content is fixed until the next build.

## 2. SSR — Server-Side Rendering

Pages are generated **per request** on the server.

The browser receives fully-formed HTML.

This is what Express does natively with template engines like EJS or Pug.

## 3. CSR — Client-Side Rendering

The server sends a minimal HTML shell and JavaScript builds the page **in the browser**.

This is the default behavior of React, Vue, and Angular SPAs.

## 4. ISR — Incremental Static Regeneration

A hybrid of SSG and SSR — static pages are served but **revalidate/rebuild in the background** after a set interval.

Popularized by Next.js.

## 5. Islands Architecture

The page is rendered as **static HTML**, with isolated interactive **"islands"** that hydrate independently.

Only the components that need interactivity ship JavaScript — the rest stays as zero-JS HTML.

Popularized by Astro. Also seen in Marko and Fresh (Deno).

---

## SSG Packages / Frameworks in the Node Ecosystem

- **Next.js** — supports all 4 methods, most popular React framework
- **Astro** — SSG-first, lets you use React/Vue/Svelte components with zero JS by default
- **Eleventy (11ty)** — lightweight, template-driven SSG, not tied to any frontend framework
- **Gatsby** — React-based SSG (less popular now but still around)
- **Nuxt** — Vue equivalent of Next.js, supports SSG and SSR
- **Hugo** — extremely fast, though written in Go, not Node

---

## Where Does Express Fit?

Express is inherently an **SSR** tool — it renders and serves pages per request.

Understanding these rendering methods helps contextualize where Express sits in the bigger picture.
