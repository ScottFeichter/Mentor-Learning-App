# Why JS?

## Why Not Use C/C++ to Access the DOM?

The key reason: **Security**.

## The Problem With C/C++

If websites could send C/C++ code to your browser:

```
Website sends C/C++ code → Your browser compiles it → Runs on your machine
```

**This would be catastrophic:**
- C/C++ has direct access to your entire computer
- Could delete files, steal data, install viruses
- Could crash your system
- No way to sandbox or restrict it safely

You'd be letting random websites run native code on your machine - like giving strangers the keys to your house!

## Why JavaScript Was Created

JavaScript was designed specifically to be:

1. **Sandboxed** - Can only access what the browser allows
2. **Interpreted** - Browser controls execution, can stop malicious code
3. **Limited** - No file system access, no system calls
4. **Safe** - Can't harm your computer even if malicious

```
Website sends JavaScript → Browser interprets it safely → Limited DOM access only
```

## The Architecture

```
Your Computer
  └── Browser (C/C++ application you trust)
      └── JavaScript Engine (safe sandbox)
          └── Website's JS code (untrusted, restricted)
```

The browser acts as a **gatekeeper** - it's written in C/C++ and has full system access, but it only exposes a safe, limited API to JavaScript.

## Who Writes The Code?

You (the user) don't write code that runs in the browser - **website owners** do. 

Would you trust every website you visit to run C/C++ code on your computer? Absolutely not!

JavaScript lets websites be interactive while keeping your computer safe.

## The Trade-off

- **C/C++**: Fast, powerful, but dangerous for untrusted code
- **JavaScript**: Slower, limited, but safe for untrusted code from the internet

JavaScript was the right choice for the web.
