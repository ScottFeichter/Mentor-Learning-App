# Rendering vs Loading

## The Original HTML File

- **Never changes** - it stays on the server exactly as written
- Browser downloads it once when you visit the page
- If you refresh the page, browser re-downloads the original HTML and starts over

## What Changes During Use

The **JavaScript objects in memory** (the DOM) change as you interact with the site:
- Click a button → JS changes object properties
- Type in a form → JS updates input object values
- Scroll → JS adds/removes classes

The **visual rendering** updates automatically when the DOM objects change.

## Re-rendering vs Reloading

### Re-rendering (Continuous & Automatic)
- Browser updates the visual display as DOM objects change
- Happens automatically, many times per second
- Only repaints what changed (efficient)
- DOM objects stay in memory
- **Example**: Clicking a button that changes text color

```javascript
button.style.color = 'red';  // Triggers re-render, not reload
```

### Reloading/Refreshing (Manual & Complete Reset)
- Browser throws away all DOM objects
- Re-downloads the original HTML from server
- Rebuilds entire DOM from scratch
- Loses all JavaScript state/changes
- **Example**: Pressing F5 or clicking refresh button

## The Flow

```
Initial Load:
HTML file (server) → Download → Parse → Create DOM objects → Render to screen

During Use:
User interaction → JS modifies DOM objects → Browser re-renders → Updated screen

Page Reload:
Discard everything → Start over at "Initial Load"
```

## Key Takeaway

The original HTML is **read-only**. All dynamic changes happen to the **in-memory JavaScript object representation** (the DOM), which the browser continuously re-renders to the screen.
