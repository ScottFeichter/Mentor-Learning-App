# WTF CSS?

## What Exactly Is CSS?

**CSS (Cascading Style Sheets)** is a text-based language that describes how HTML elements should be displayed on screen.

```css
button {
  color: blue;
  font-size: 16px;
  padding: 10px;
}
```

It's just text instructions that tell the browser: "Make buttons blue, 16px font, with 10px padding."

## How It Does What It Does

### The Process

```
1. Browser parses HTML → Creates DOM objects
2. Browser parses CSS → Creates CSSOM (CSS Object Model)
3. Browser combines DOM + CSSOM → Creates Render Tree
4. Layout engine calculates positions and sizes
5. Painting engine draws pixels to screen
```

### Under The Hood

The browser's **rendering engine** (written in C++):
- Reads CSS rules
- Matches them to DOM elements (selector matching)
- Calculates final styles (cascading, inheritance, specificity)
- Computes layout (box model, flexbox, grid)
- Paints pixels based on those calculations

CSS doesn't "do" anything - it's data. The browser's C++ rendering engine does all the work.

## Who's The Asshole That Invented It?

### The "Culprit": Håkon Wium Lie

- **1994**: Proposed CSS while working at CERN with Tim Berners-Lee
- **1996**: CSS 1 released
- **Intent**: Separate content (HTML) from presentation (CSS)

### Was He An Asshole?

**No - he solved a real problem:**

**Before CSS (early 1990s):**
```html
<font color="blue" size="5">
  <b>
    <center>
      This is terrible
    </center>
  </b>
</font>
```

Styling was mixed into HTML. Nightmare to maintain.

**After CSS:**
```html
<h1>This is better</h1>
```
```css
h1 { color: blue; font-size: 24px; text-align: center; }
```

Separation of concerns. Change all headings by editing one CSS rule.

### The Problem

CSS was designed for **documents** (academic papers, simple pages), not **applications** (complex UIs, responsive layouts, animations).

As the web evolved, CSS had to bolt on features it wasn't designed for:
- Flexbox (2009)
- Grid (2017)
- Variables (2015)
- Animations (2009)

Each addition made it more complex and inconsistent.

## Why We're Stuck With It For Life

### 1. Backwards Compatibility

Billions of websites use CSS. Browsers must support:
- CSS 1 (1996)
- CSS 2 (1998)
- CSS 3 (ongoing since 1999)
- All the quirks and bugs

Can't break existing sites.

### 2. No Alternative Gained Traction

Attempts to replace CSS:
- **XSL** (XML Styling Language) - too complex, died
- **SASS/LESS** - compile to CSS (not a replacement)
- **CSS-in-JS** - still generates CSS under the hood
- **Tailwind** - utility classes, still CSS

Nothing has succeeded in replacing it.

### 3. The Network Effect

- All browsers support CSS
- All developers know CSS (sort of)
- All tools work with CSS
- Massive ecosystem

Switching would require coordinating browsers, developers, tools, and billions of websites. Impossible.

### 4. It's "Good Enough"

Despite frustrations, CSS works. You can build anything with it (eventually, after fighting specificity and the cascade).

## What Native Apps Use Instead

Native apps don't use CSS. They use **programmatic layout systems** built into their frameworks:

### iOS (Swift/Objective-C)
```swift
button.backgroundColor = .blue
button.titleLabel?.font = UIFont.systemFont(ofSize: 16)
button.contentEdgeInsets = UIEdgeInsets(top: 10, left: 10, bottom: 10, right: 10)
```

Or **Auto Layout** (constraint-based):
```swift
button.widthAnchor.constraint(equalToConstant: 200).isActive = true
button.centerXAnchor.constraint(equalTo: view.centerXAnchor).isActive = true
```

Or **SwiftUI** (declarative):
```swift
Button("Click me") {
    // action
}
.foregroundColor(.blue)
.font(.system(size: 16))
.padding(10)
```

### Android (Kotlin/Java)
```kotlin
button.setBackgroundColor(Color.BLUE)
button.textSize = 16f
button.setPadding(10, 10, 10, 10)
```

Or **XML layouts**:
```xml
<Button
    android:background="@color/blue"
    android:textSize="16sp"
    android:padding="10dp" />
```

Or **Jetpack Compose** (declarative):
```kotlin
Button(
    onClick = { },
    colors = ButtonDefaults.buttonColors(backgroundColor = Color.Blue),
    contentPadding = PaddingValues(10.dp)
) {
    Text("Click me", fontSize = 16.sp)
}
```

### Desktop (Qt, WPF, etc.)

**Qt (C++):**
```cpp
button->setStyleSheet("background-color: blue; font-size: 16px; padding: 10px;");
```

**WPF (C#/XAML):**
```xml
<Button Background="Blue" FontSize="16" Padding="10">Click me</Button>
```

### React Native (JavaScript, but not CSS)
```javascript
<Button
  title="Click me"
  color="blue"
  style={{
    fontSize: 16,
    padding: 10
  }}
/>
```

Uses JavaScript objects, not CSS text. Compiles to native UI components.

## Key Differences: CSS vs Native

| Aspect | CSS | Native Apps |
|--------|-----|-------------|
| **Language** | Text-based stylesheet | Code (Swift, Kotlin, C++) |
| **Separation** | Separate file from structure | Integrated with code |
| **Cascade** | Global rules cascade down | Local, explicit styling |
| **Specificity** | Complex rules (id > class > tag) | Direct property setting |
| **Layout** | Box model, flexbox, grid | Constraint-based, programmatic |
| **Performance** | Browser parses and applies | Direct API calls to rendering engine |
| **Debugging** | Inspect element, computed styles | Debugger, view hierarchy |

## Why Native Doesn't Use CSS

**1. Performance**
- Native apps call rendering APIs directly
- No parsing CSS text
- No selector matching
- No cascade calculation

**2. Type Safety**
- Code is compiled, catches errors
- CSS is text, errors found at runtime

**3. Integration**
- Styling is part of the code
- Can use variables, functions, logic
- CSS is separate, limited logic

**4. Control**
- Direct access to platform capabilities
- CSS limited to what browsers expose

## The Irony

Modern web frameworks are trying to make CSS more like native:
- **CSS-in-JS**: Write styles in JavaScript
- **Tailwind**: Utility classes (like inline styles)
- **CSS Modules**: Scoped styles (no global cascade)

We're slowly moving away from CSS's original design (global cascading stylesheets) toward native-style local, programmatic styling... while still generating CSS under the hood.

## The Bottom Line

**CSS exists because:**
- Solved a real problem in 1994 (separating content from presentation)
- Designed for documents, not applications
- Backwards compatibility prevents replacement
- Network effects make switching impossible

**Native apps don't use CSS because:**
- They can call rendering APIs directly
- They prioritize performance and type safety
- They were designed for applications from the start

**We're stuck with CSS because:**
- Billions of websites depend on it
- No viable replacement has emerged
- It's "good enough" despite frustrations
- The web platform can't start over

Håkon Wium Lie wasn't an asshole - he solved the problem of his time. We're just living with a document styling language in an application world.
