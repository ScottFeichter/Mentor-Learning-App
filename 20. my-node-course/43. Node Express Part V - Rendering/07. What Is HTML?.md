# What Is HTML?

## What HTML Actually Is

HTML is just **plain text** - a text file with special syntax using angle brackets:

```html
<h1>Hello World</h1>
<p>This is a paragraph.</p>
```

That's it. It's text in a file, like a .txt file, but with a .html extension.

## What Are Tags?

Tags are **instructions written in text** that tell the browser how to structure and display content. They're not objects yet - they're just text characters: `<`, `>`, `h1`, `p`, etc.

Think of HTML like a recipe written on paper - it's just instructions, not the actual cake.

## The Transformation

```
1. HTML File (text)
   ↓
2. Browser reads the text
   ↓
3. Parser converts tags into JavaScript objects (DOM)
   ↓
4. Rendering engine converts objects into pixels
   ↓
5. Screen displays colored dots (what you see)
```

## What Is "Rendered HTML"?

Yes! Rendered HTML is literally **colored pixels/dots on your screen**. 

- `<h1>Hello</h1>` (text) → becomes large, bold pixels spelling "Hello"
- `<button>Click</button>` (text) → becomes a rectangular shape with text inside
- `<img src="cat.jpg">` (text) → becomes thousands of colored pixels forming a cat image

The browser's rendering engine calculates:
- Where each pixel goes (layout)
- What color each pixel is (styling)
- Then paints those pixels to your screen

So yes - you're seeing dots on a screen, arranged according to the instructions in the HTML text file!

## The DOM Has Always Existed

Step 3 (creating DOM objects) has **always** happened - even before JavaScript existed!

The DOM was created for the **browser itself** to work with, not for JavaScript. The browser needs an internal object representation to manage the page structure.

### Before JavaScript (early 1990s)

```
1. HTML File (text)
   ↓
2. Browser reads the text
   ↓
3. Parser converts tags into internal objects (DOM) ← Still happened!
   ↓
4. Rendering engine converts objects into pixels
   ↓
5. Screen displays colored dots
```

The difference: **You couldn't access or modify those objects** because there was no JavaScript.

### After JavaScript (1995+)

Same process, but now JavaScript can access and modify the DOM objects through the `document` object.

### Why The DOM Always Existed

The browser needs an internal data structure to:
- Track parent-child relationships between elements
- Calculate layout and positioning
- Handle user clicks (which element was clicked?)
- Manage memory efficiently

The DOM is that data structure. JavaScript just gave **you** (the developer) access to it.

## What Was The DOM Before JavaScript?

Before JavaScript, the DOM was an **internal data structure in C/C++** (the language browsers are written in).

Early browsers (like Netscape, Mosaic) were written in C/C++. When they parsed HTML, they created:
- **C/C++ structs or objects** representing each HTML element
- A tree structure in memory linking parent/child elements
- Internal properties for each element (tag name, attributes, text content)

### The Key Difference

**Before JavaScript (early 1990s)**
- DOM existed as C/C++ objects inside the browser's code
- Only the browser's internal code could access it
- Developers had no way to interact with it
- It was a "black box" - you sent HTML in, got pixels out

**After JavaScript (1995+)**
- Same C/C++ objects internally
- But now **exposed** to JavaScript through the `document` API
- Browser created JavaScript "wrapper" objects that let you access the internal C/C++ structures
- Developers could now read and modify the DOM

### Analogy

Think of a car engine:
- The engine always existed (DOM in C/C++)
- Before: Only mechanics inside the factory could touch it
- After: They added a steering wheel and pedals (JavaScript API) so you could control it

The DOM didn't change - JavaScript just gave you access to it!
