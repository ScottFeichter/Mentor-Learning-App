# Roles: Database vs Server vs Client

These terms don't always refer to physical computers.

They also describe **abstract roles** that software components play in a system.

## Client (Role)

Any software that **makes requests** to another service.

- A browser making HTTP requests
- A mobile app calling an API
- A server calling another server (the calling server is the "client" in that interaction)

## Server (Role)

Any software that **listens for and responds to requests**.

- An Express app handling HTTP requests
- A Node.js process running on port 3000
- Any program that waits for incoming connections

## Database (Role)

Any software that **stores, organizes, and retrieves data** on demand.

- MongoDB, PostgreSQL, MySQL (dedicated database software)
- SQLite (a file-based database)
- Even a JSON file could serve the "database role" in a simple app

## The Same Program Can Play Multiple Roles

```javascript
// This Express app is a SERVER to the browser
// AND a CLIENT to the database
app.get('/users', async (req, res) => {
  const users = await db.query('SELECT * FROM users'); // Client role
  res.json(users); // Server role
});
```

## Three-Tier Architecture

This separation of roles is known as **three-tier architecture** (or n-tier architecture):

```
Presentation Tier  →  Logic Tier  →  Data Tier
   (Client)           (Server)       (Database)
```

- **Presentation Tier** - handles what the user sees and interacts with
- **Logic Tier** - handles business rules, processing, and decision-making
- **Data Tier** - handles persistence and data management

## Why Separate Roles?

- **Separation of concerns** - each layer has one job
- **Scalability** - scale each tier independently
- **Maintainability** - change one layer without breaking others
- **Security** - isolate sensitive data behind layers
- **Reusability** - multiple clients can share the same server/database
