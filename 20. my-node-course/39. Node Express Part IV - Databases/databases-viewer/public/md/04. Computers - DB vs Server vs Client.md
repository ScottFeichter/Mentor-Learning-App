# Database vs Server vs Client

These are three types of physical computers in a networked system.

## Client

The computer the **user** interacts with directly.

- Laptops, desktops, phones, tablets
- Runs browsers, apps, or other user-facing software
- Sends requests to servers
- Displays data to the user
- Optimized for user experience (display, input, responsiveness)

## Server

The computer that **processes requests** and sends back responses.

- Sits between the client and the database
- Runs application logic (business rules, authentication, routing)
- Receives requests from clients
- Fetches or sends data to the database
- Returns responses to clients
- Optimized for handling many simultaneous connections

## Database

The computer that **stores and manages data**.

- Holds persistent data (user accounts, products, records)
- Receives queries from the server
- Returns requested data to the server
- Optimized for fast read/write operations and large storage capacity
- Rarely communicates directly with the client

## The Flow

```
Client  →  Server  →  Database
(request)  (logic)    (data)

Client  ←  Server  ←  Database
(response) (logic)    (data)
```

## Key Differences

| | Client | Server | Database |
|---|---|---|---|
| **Purpose** | User interaction | Process logic | Store data |
| **Talks to** | Server | Client & Database | Server |
| **Optimized for** | Display & input | Connections & logic | Storage & queries |
| **Who uses it** | End user | Application code | Server code |
| **Example** | Your laptop | AWS EC2 instance | AWS RDS instance |

## Important Note

These are **roles**, not always separate physical machines. A single computer can act as all three during development (your laptop runs the client, server, and database). In production, they are typically separate machines for performance, security, and scalability.
