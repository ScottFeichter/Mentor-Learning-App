# Loading

## What Is Loading?

In the context of databases and ORMs, "loading" refers to fetching related data.

When you query for a user, do you also fetch their posts, comments, and profile at the same time?


## Loading Strategies

- **Lazy loading** = fetch related data later, only if needed
- **Eager loading** = fetch related data now, all at once

Choose based on whether you know you'll need the related data. If yes, eager load. If maybe, lazy load.

## When to Use Each

| Scenario | Use |
|---|---|
| Displaying a user profile with their posts | Eager loading |
| Listing users in a table (no related data shown) | Lazy loading |
| API response that includes nested data | Eager loading |
| Data that is rarely accessed | Lazy loading |
| Looping through records and accessing relations | Eager loading |

## The N+1 Problem

The biggest reason to choose eager over lazy loading:

```javascript
// LAZY - BAD: 101 queries
const users = await User.findAll(); // 1 query
for (const user of users) {
  const posts = await user.getPosts(); // 100 queries (one per user)
}

// EAGER - GOOD: 1-2 queries
const users = await User.findAll({
  include: [{ model: Post }] // Fetches all posts with users
});
```
