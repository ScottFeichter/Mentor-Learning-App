# Base64URL Encoding in JWT

## JWT Structure

A JWT (JSON Web Token) has three **parts** (not objects):

1. **Header** - A JSON object (encoded as Base64URL string)
2. **Payload** - A JSON object (encoded as Base64URL string)
3. **Signature** - A cryptographic signature (raw bytes encoded as Base64URL string)

The complete JWT is a string with these three parts separated by dots:

```
header.payload.signature
```

Example:
```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
```

## Base64URL Encoding Process

### Example: Encoding JWT Header

**Input JSON:**
```json
{"alg":"HS256","typ":"JWT"}
```

**Output Base64URL:**
```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
```

### Steps:

1. **Start with the JSON string:**
   ```
   {"alg":"HS256","typ":"JWT"}
   ```

2. **Convert to bytes (UTF-8 encoding):**
   Each character becomes its byte representation in UTF-8

3. **Apply Base64 encoding:**
   The bytes are encoded using standard Base64, which converts binary data into ASCII characters using A-Z, a-z, 0-9, +, and /

4. **Convert to Base64URL:**
   - Replace `+` with `-`
   - Replace `/` with `_`
   - Remove any trailing `=` padding characters

5. **Result:**
   ```
   eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
   ```

## Base64 vs Base64URL

The key difference between Base64 and Base64URL is that Base64URL uses URL-safe characters (no `+` or `/`) and removes padding, making it safe to use in URLs and HTTP headers without encoding issues.

## Verification

You can verify this in JavaScript:
```javascript
btoa('{"alg":"HS256","typ":"JWT"}')
// Output: eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
```
