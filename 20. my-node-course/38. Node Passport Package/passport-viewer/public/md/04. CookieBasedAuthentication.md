# Cookie-Based Authentication

Cookie-based authentication is a method where the server creates a session after successful login and stores a session identifier in a cookie on the client's browser. The browser automatically sends this cookie with every subsequent request to maintain the authenticated state.

## How It Works

```
1. User submits login credentials (username/password)
2. Server verifies credentials
3. Server creates a session and stores user data
4. Server sends session ID to client in a cookie
5. Browser stores cookie and automatically sends it with every request
6. Server reads cookie, retrieves session, identifies user
7. User stays logged in until session expires or logout
```

## What is a Cookie?

A cookie is a small piece of data (max 4KB) that:
- Is stored in the browser
- Is automatically sent with every HTTP request to the same domain
- Has an expiration date
- Can be secured with various flags

## Basic Implementation

```javascript
const express = require('express');
const session = require('express-session');
const bcrypt = require('bcrypt');

const app = express();
app.use(express.json());

// Setup session middleware (creates and manages cookies)
app.use(session({
  secret: 'your-secret-key',
  resave: false,
  saveUninitialized: false,
  cookie: {
    secure: false,        // true in production with HTTPS
    httpOnly: true,       // prevents JavaScript access
    maxAge: 24 * 60 * 60 * 1000  // 24 hours
  }
}));

// Login - creates session and cookie
app.post('/login', async (req, res) => {
  const { username, password } = req.body;
  
  // Find user in database
  const user = await User.findOne({ username });
  if (!user) {
    return res.status(401).json({ message: 'Invalid credentials' });
  }
  
  // Verify password
  const isValid = await bcrypt.compare(password, user.password);
  if (!isValid) {
    return res.status(401).json({ message: 'Invalid credentials' });
  }
  
  // Create session (cookie automatically created)
  req.session.userId = user.id;
  req.session.username = user.username;
  
  res.json({ message: 'Logged in successfully' });
});

// Protected route - cookie automatically sent by browser
app.get('/profile', (req, res) => {
  // Check if session exists
  if (!req.session.userId) {
    return res.status(401).json({ message: 'Not authenticated' });
  }
  
  // User is authenticated, session data available
  res.json({
    userId: req.session.userId,
    username: req.session.username
  });
});

// Logout - destroys session and clears cookie
app.post('/logout', (req, res) => {
  req.session.destroy((err) => {
    if (err) {
      return res.status(500).json({ message: 'Logout failed' });
    }
    res.clearCookie('connect.sid');
    res.json({ message: 'Logged out successfully' });
  });
});
```

## Cookie Structure

When a session is created, the browser receives a cookie like this:

```
Set-Cookie: connect.sid=s%3Aj8fh2k3j4h5k6j7h8k9j0.signature; 
            Path=/; 
            HttpOnly; 
            Expires=Wed, 16 Jan 2025 10:00:00 GMT
```

The browser then automatically sends it with every request:

```
Cookie: connect.sid=s%3Aj8fh2k3j4h5k6j7h8k9j0.signature
```

## Cookie Flags (Security)

```javascript
cookie: {
  secure: true,        // Only send over HTTPS
  httpOnly: true,      // No JavaScript access (prevents XSS)
  sameSite: 'strict',  // Prevents CSRF attacks
  maxAge: 3600000,     // Expires in 1 hour (milliseconds)
  domain: '.example.com',  // Cookie valid for all subdomains
  path: '/'            // Cookie valid for entire site
}
```

### Flag Explanations

- **secure** - Cookie only sent over HTTPS, not HTTP
- **httpOnly** - Cookie cannot be accessed by JavaScript (document.cookie)
- **sameSite** - Controls cross-site cookie sending
  - `strict` - Never sent on cross-site requests
  - `lax` - Sent on top-level navigation (default)
  - `none` - Always sent (requires secure: true)
- **maxAge** - Cookie lifetime in milliseconds
- **expires** - Specific expiration date
- **domain** - Which domains can receive the cookie
- **path** - Which paths can receive the cookie

## Authentication Middleware

```javascript
// Middleware to check if user is authenticated
function isAuthenticated(req, res, next) {
  if (req.session && req.session.userId) {
    return next();
  }
  res.status(401).json({ message: 'Authentication required' });
}

// Use middleware on protected routes
app.get('/dashboard', isAuthenticated, (req, res) => {
  res.json({ message: 'Welcome to dashboard' });
});

app.post('/update-profile', isAuthenticated, (req, res) => {
  // User is authenticated, proceed with update
  res.json({ message: 'Profile updated' });
});
```

## Session Storage Options

### Memory Store (Default - Development Only)
```javascript
app.use(session({
  secret: 'secret',
  // Uses memory by default
}));
```

### MongoDB Store (Production)
```javascript
const MongoStore = require('connect-mongo');

app.use(session({
  secret: 'secret',
  store: MongoStore.create({
    mongoUrl: 'mongodb://localhost:27017/sessions'
  })
}));
```

### Redis Store (Production - Best Performance)
```javascript
const RedisStore = require('connect-redis').default;
const { createClient } = require('redis');

const redisClient = createClient();
redisClient.connect();

app.use(session({
  secret: 'secret',
  store: new RedisStore({ client: redisClient })
}));
```

## Advantages of Cookie-Based Authentication

✅ **Automatic** - Browser handles cookie storage and sending
✅ **Secure** - Session data stored on server, not client
✅ **Simple** - Easy to implement and understand
✅ **Built-in expiration** - Cookies can auto-expire
✅ **Server control** - Can invalidate sessions server-side

## Disadvantages

❌ **Stateful** - Requires server-side session storage
❌ **Scalability** - Need shared session store for multiple servers
❌ **CSRF vulnerable** - Requires additional protection
❌ **Not ideal for APIs** - Mobile apps and SPAs may prefer tokens
❌ **Cross-domain issues** - Cookies don't work across different domains

## Cookie-Based vs Token-Based Authentication

| Feature | Cookie-Based | Token-Based (JWT) |
|---------|--------------|-------------------|
| Storage | Server (session) | Client (localStorage/cookie) |
| State | Stateful | Stateless |
| Scalability | Harder | Easier |
| Security | More secure | Moderate |
| CSRF | Vulnerable | Not vulnerable |
| Cross-domain | Limited | Easy |
| Mobile apps | Harder | Easier |
| Best for | Traditional web apps | APIs, SPAs, mobile |

## Complete Example with Passport.js

```javascript
const passport = require('passport');
const LocalStrategy = require('passport-local').Strategy;

// Configure session
app.use(session({
  secret: 'secret',
  resave: false,
  saveUninitialized: false,
  cookie: { httpOnly: true, maxAge: 24 * 60 * 60 * 1000 }
}));

app.use(passport.initialize());
app.use(passport.session());

// Configure authentication strategy
passport.use(new LocalStrategy(async (username, password, done) => {
  const user = await User.findOne({ username });
  if (!user || !await bcrypt.compare(password, user.password)) {
    return done(null, false);
  }
  return done(null, user);
}));

// Serialize user to session (stores user.id in cookie)
passport.serializeUser((user, done) => {
  done(null, user.id);
});

// Deserialize user from session (retrieves user from cookie's id)
passport.deserializeUser(async (id, done) => {
  const user = await User.findById(id);
  done(null, user);
});

// Login route
app.post('/login', passport.authenticate('local'), (req, res) => {
  res.json({ message: 'Logged in', user: req.user });
});

// Protected route
app.get('/profile', (req, res) => {
  if (!req.isAuthenticated()) {
    return res.status(401).json({ message: 'Not authenticated' });
  }
  res.json({ user: req.user });
});

// Logout
app.post('/logout', (req, res) => {
  req.logout(() => {
    res.json({ message: 'Logged out' });
  });
});
```

## Security Best Practices

1. **Always use HTTPS in production** - Prevents cookie theft
2. **Set httpOnly flag** - Prevents XSS attacks
3. **Set sameSite flag** - Prevents CSRF attacks
4. **Use strong session secrets** - For signing cookies
5. **Implement CSRF tokens** - Additional CSRF protection
6. **Set reasonable expiration** - Don't keep sessions forever
7. **Regenerate session ID after login** - Prevents session fixation
8. **Use secure session storage** - Redis/database, not memory

## Key Takeaways

- Cookie-based authentication uses **sessions** stored on the server
- The **session ID** is stored in a cookie on the client
- Cookies are **automatically sent** with every request
- Best for **traditional web applications** with server-side rendering
- Requires **session storage** (memory, database, Redis)
- More **secure** than storing sensitive data on the client
- Needs **CSRF protection** since cookies are sent automatically
