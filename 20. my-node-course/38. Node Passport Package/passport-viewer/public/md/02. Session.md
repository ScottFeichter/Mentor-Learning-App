# Session in Web Development

A **session**  represents a series of interactions between a specific user's browser and a web server over a limited period.

Its primary purpose is to maintain state (remember user data and activity) across the inherently stateless HTTP protocol.

# What Sessions Are

It is a way to store user-specific data (on the server) across multiple HTTP requests.

It solves the problem that HTTP is stateless - each request is independent and doesn't remember previous requests.


## The Problem: HTTP is Stateless

```
Request 1: User logs in → Server verifies credentials
Request 2: User views profile → Server doesn't remember login
Request 3: User updates settings → Server doesn't remember login
```

Without sessions, users would need to log in with every single request.

## The Solution: Sessions

Sessions allow the server to remember information about a user across multiple requests.

```
Request 1: User logs in → Server creates session, stores user data
Request 2: User views profile → Server recognizes user from session
Request 3: User updates settings → Server still knows who the user is
```

## How Sessions Work

1. **User logs in** - Server validates credentials
2. **Server creates session** - Generates unique session ID and stores user data
3. **Session ID sent to client** - Stored in a cookie
4. **Client sends cookie with each request** - Browser automatically includes it
5. **Server reads session ID** - Retrieves stored user data
6. **User stays logged in** - Until session expires or logout

## Session Storage

Session data is stored on the **server**, not the client. Only the session ID is sent to the client.

**Common storage options:**
- **Memory** (default) - Fast but lost on server restart
- **Database** - Persistent (MongoDB, PostgreSQL, MySQL)
- **Redis** - Fast and persistent, ideal for production
- **File system** - Simple but slower

## Basic Example with express-session

```javascript
const express = require('express');
const session = require('express-session');

const app = express();

// Configure session middleware
app.use(session({
  secret: 'your-secret-key',           // Used to sign session ID cookie
  resave: false,                       // Don't save session if unmodified
  saveUninitialized: false,            // Don't create session until something stored
  cookie: {
    secure: false,                     // Set true in production with HTTPS
    httpOnly: true,                    // Prevents client-side JS from accessing cookie
    maxAge: 1000 * 60 * 60 * 24        // 24 hours
  }
}));

// Login - create session
app.post('/login', (req, res) => {
  const { username, password } = req.body;

  // Verify credentials (simplified)
  if (username === 'user' && password === 'pass') {
    // Store data in session
    req.session.userId = 123;
    req.session.username = username;
    req.session.isAuthenticated = true;

    res.send('Logged in');
  } else {
    res.status(401).send('Invalid credentials');
  }
});

// Protected route - read from session
app.get('/profile', (req, res) => {
  if (!req.session.isAuthenticated) {
    return res.status(401).send('Please log in');
  }

  res.json({
    userId: req.session.userId,
    username: req.session.username
  });
});

// Logout - destroy session
app.post('/logout', (req, res) => {
  req.session.destroy((err) => {
    if (err) {
      return res.status(500).send('Error logging out');
    }
    res.clearCookie('connect.sid'); // Clear session cookie
    res.send('Logged out');
  });
});
```

## Session with Database (MongoDB Store)

```javascript
const MongoStore = require('connect-mongo');

app.use(session({
  secret: 'your-secret-key',
  resave: false,
  saveUninitialized: false,
  store: MongoStore.create({
    mongoUrl: 'mongodb://localhost:27017/myapp',
    ttl: 24 * 60 * 60 // Session expires in 24 hours
  }),
  cookie: { maxAge: 1000 * 60 * 60 * 24 }
}));
```

## Session vs Cookie vs Token

| Feature | Session | Cookie | Token (JWT) |
|---------|---------|--------|-------------|
| Storage location | Server | Client | Client |
| Data size | Large | Small (4KB limit) | Medium |
| Stateful/Stateless | Stateful | Stateful | Stateless |
| Scalability | Harder (needs shared storage) | Harder | Easier |
| Security | More secure (data on server) | Less secure | Moderate |
| Use case | Traditional web apps | Small data storage | APIs, SPAs, mobile |

## Session Data Structure

When you create a session, it looks like this on the server:

```javascript
{
  "sessionId": "abc123xyz789",
  "userId": 123,
  "username": "john",
  "isAuthenticated": true,
  "createdAt": "2025-01-15T10:00:00Z",
  "expiresAt": "2025-01-16T10:00:00Z"
}
```

The client only receives:
```
Cookie: connect.sid=abc123xyz789
```

## Important Session Options

```javascript
app.use(session({
  secret: 'secret-key',              // Required: signs session ID
  resave: false,                     // Don't save unchanged sessions
  saveUninitialized: false,          // Don't save empty sessions
  name: 'sessionId',                 // Cookie name (default: connect.sid)
  cookie: {
    secure: true,                    // Only send over HTTPS
    httpOnly: true,                  // No client-side JS access
    maxAge: 1000 * 60 * 60 * 24,    // Expiration time
    sameSite: 'strict'               // CSRF protection
  },
  rolling: true,                     // Reset expiration on each request
  unset: 'destroy'                   // Destroy session when unset
}));
```

## Session Security Best Practices

1. **Use HTTPS** - Prevents session ID theft
2. **Set httpOnly** - Prevents XSS attacks from stealing session
3. **Set secure: true** - Only send cookie over HTTPS
4. **Use strong secret** - For signing session IDs
5. **Set reasonable expiration** - Don't keep sessions forever
6. **Regenerate session ID** - After login to prevent fixation attacks
7. **Use sameSite** - Prevents CSRF attacks

```javascript
// Regenerate session ID after login
app.post('/login', (req, res) => {
  // Verify credentials...

  req.session.regenerate((err) => {
    if (err) return res.status(500).send('Error');

    req.session.userId = user.id;
    req.session.isAuthenticated = true;
    res.send('Logged in');
  });
});
```

## Key Takeaways

- **Session** = Server-side storage of user data across requests
- **Session ID** = Unique identifier stored in cookie on client
- **Cookie** = Transport mechanism for session ID
- Sessions make HTTP stateful by remembering user information
- Essential for authentication and maintaining user state
