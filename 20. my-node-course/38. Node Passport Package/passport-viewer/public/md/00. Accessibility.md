# Accessibility (A11y)

Accessibility in web development means making websites and applications usable by everyone, including people with disabilities.

It ensures that all users, regardless of their abilities, can perceive, understand, navigate, and interact with your web content.

## What is A11y?

**A11y** is a numeronym (number-based abbreviation) for "Accessibility":
- **A** - First letter
- **11** - Number of letters between 'A' and 'y' (ccessibilit)
- **y** - Last letter

Similar numeronyms:
- **i18n** = Internationalization (18 letters between i and n)
- **l10n** = Localization (10 letters between l and n)

## Why Accessibility Matters

### Legal Requirements
- **ADA** (Americans with Disabilities Act) in the US
- **Section 508** for federal websites
- **WCAG** (Web Content Accessibility Guidelines) - international standard
- Legal liability for non-compliant sites

### Ethical Reasons
- 15% of world population has some form of disability
- Everyone deserves equal access to information
- Temporary disabilities (broken arm, eye surgery)
- Situational limitations (bright sunlight, noisy environment)

### Business Benefits
- Larger audience reach
- Better SEO (search engines use similar techniques)
- Improved usability for everyone
- Better mobile experience
- Reduced legal risk

## Types of Disabilities

### Visual
- Blindness
- Low vision
- Color blindness
- **Assistive tech:** Screen readers, magnifiers

### Auditory
- Deafness
- Hard of hearing
- **Assistive tech:** Captions, transcripts

### Motor/Physical
- Limited mobility
- Tremors
- Paralysis
- **Assistive tech:** Keyboard navigation, voice control

### Cognitive
- Learning disabilities
- Memory issues
- Attention disorders
- **Needs:** Clear language, consistent navigation

## WCAG Principles (POUR)

### 1. Perceivable
Information must be presentable to users in ways they can perceive.

```html
<!-- Bad: Image without alt text -->
<img src="logo.png">

<!-- Good: Image with descriptive alt text -->
<img src="logo.png" alt="Company Logo">
```

### 2. Operable
User interface components must be operable.

```html
<!-- Bad: Div acting as button -->
<div onclick="submit()">Submit</div>

<!-- Good: Semantic button -->
<button onclick="submit()">Submit</button>
```

### 3. Understandable
Information and operation must be understandable.

```html
<!-- Bad: Unclear error -->
<span class="error">Invalid</span>

<!-- Good: Clear error message -->
<span class="error" role="alert">
  Email address must include @ symbol
</span>
```

### 4. Robust
Content must be robust enough to work with assistive technologies.

```html
<!-- Bad: Custom element without ARIA -->
<div class="checkbox"></div>

<!-- Good: Proper ARIA attributes -->
<div role="checkbox" aria-checked="false" tabindex="0"></div>
```

## Common Accessibility Issues in Authentication

### 1. Form Labels
```html
<!-- Bad: No label -->
<input type="text" placeholder="Username">

<!-- Good: Proper label -->
<label for="username">Username</label>
<input type="text" id="username" name="username">
```

### 2. Error Messages
```html
<!-- Bad: Visual only -->
<input type="password" class="error">

<!-- Good: Accessible error -->
<label for="password">Password</label>
<input
  type="password"
  id="password"
  aria-describedby="password-error"
  aria-invalid="true"
>
<span id="password-error" role="alert">
  Password must be at least 8 characters
</span>
```

### 3. Focus Management
```javascript
// After login error, focus on error message
document.getElementById('error-message').focus();

// After successful login, announce to screen reader
const announcement = document.createElement('div');
announcement.setAttribute('role', 'status');
announcement.setAttribute('aria-live', 'polite');
announcement.textContent = 'Login successful. Redirecting...';
document.body.appendChild(announcement);
```

### 4. Keyboard Navigation
```html
<!-- Ensure all interactive elements are keyboard accessible -->
<button type="submit">Login</button>
<a href="/forgot-password">Forgot Password?</a>

<!-- Not keyboard accessible -->
<div onclick="login()">Login</div>
```

## Accessibility in Authentication Forms

### Complete Accessible Login Form
```html
<form method="post" action="/login" aria-labelledby="login-heading">
  <h1 id="login-heading">Login</h1>

  <!-- Username field -->
  <div>
    <label for="username">Username</label>
    <input
      type="text"
      id="username"
      name="username"
      autocomplete="username"
      required
      aria-required="true"
    >
  </div>

  <!-- Password field -->
  <div>
    <label for="password">Password</label>
    <input
      type="password"
      id="password"
      name="password"
      autocomplete="current-password"
      required
      aria-required="true"
    >
  </div>

  <!-- Error message -->
  <div
    id="login-error"
    role="alert"
    aria-live="assertive"
    style="display: none;"
  >
    <!-- Error text inserted here -->
  </div>

  <!-- Submit button -->
  <button type="submit">Login</button>

  <!-- Additional links -->
  <a href="/forgot-password">Forgot your password?</a>
  <a href="/register">Create an account</a>
</form>
```

## ARIA (Accessible Rich Internet Applications)

ARIA attributes provide additional context for assistive technologies.

### Common ARIA Attributes
```html
<!-- Roles -->
<div role="alert">Error message</div>
<div role="status">Loading...</div>
<nav role="navigation">...</nav>

<!-- States -->
<button aria-pressed="true">Bold</button>
<input aria-invalid="true">
<div aria-expanded="false">Menu</div>

<!-- Properties -->
<input aria-label="Search">
<button aria-describedby="help-text">Submit</button>
<div aria-live="polite">Updates appear here</div>
```

## Testing for Accessibility

### Manual Testing
1. **Keyboard only** - Navigate without mouse (Tab, Enter, Space, Arrow keys)
2. **Screen reader** - Use NVDA (Windows), JAWS (Windows), VoiceOver (Mac/iOS)
3. **Zoom** - Test at 200% zoom
4. **Color contrast** - Check text readability

### Automated Testing
```bash
# Install axe-core
npm install axe-core

# Or use browser extensions
# - axe DevTools
# - WAVE
# - Lighthouse (built into Chrome)
```

### Quick Checks
- Can you navigate with keyboard only?
- Do all images have alt text?
- Do form inputs have labels?
- Are error messages announced?
- Is color contrast sufficient?
- Does content make sense without CSS?

## Best Practices for Authentication

1. **Use semantic HTML**
   ```html
   <button> not <div onclick="">
   <label> for all inputs
   <form> for forms
   ```

2. **Provide clear labels**
   ```html
   <label for="email">Email Address</label>
   <input type="email" id="email">
   ```

3. **Show clear errors**
   ```html
   <span role="alert">Password is required</span>
   ```

4. **Support keyboard navigation**
   - Tab through all interactive elements
   - Enter to submit forms
   - Escape to close modals

5. **Use autocomplete**
   ```html
   <input type="email" autocomplete="email">
   <input type="password" autocomplete="current-password">
   ```

6. **Provide focus indicators**
   ```css
   button:focus {
     outline: 2px solid blue;
   }
   ```

7. **Announce dynamic changes**
   ```html
   <div aria-live="polite" role="status">
     Login successful
   </div>
   ```

## Common Mistakes

### ❌ Don't Do This
```html
<!-- No label -->
<input type="text" placeholder="Username">

<!-- Div as button -->
<div onclick="submit()">Submit</div>

<!-- Removing focus outline -->
<style>
  *:focus { outline: none; }
</style>

<!-- Color-only error indication -->
<input style="border: 1px solid red;">

<!-- CAPTCHA without alternative -->
<img src="captcha.png">
```

### ✅ Do This
```html
<!-- Proper label -->
<label for="username">Username</label>
<input type="text" id="username">

<!-- Semantic button -->
<button type="submit">Submit</button>

<!-- Visible focus indicator -->
<style>
  button:focus {
    outline: 2px solid blue;
    outline-offset: 2px;
  }
</style>

<!-- Error with text -->
<input aria-invalid="true" aria-describedby="error">
<span id="error" role="alert">Username is required</span>

<!-- CAPTCHA with audio alternative -->
<img src="captcha.png" alt="CAPTCHA">
<button>Play audio CAPTCHA</button>
```

## Key Takeaways

- **A11y** = Accessibility (A + 11 letters + y)
- Makes web accessible to people with disabilities
- Legal requirement in many jurisdictions
- Benefits everyone, not just disabled users
- Use semantic HTML and proper labels
- Support keyboard navigation
- Test with screen readers
- Provide clear error messages
- Don't rely on color alone
- Include ARIA attributes when needed
- Accessibility is not optional - it's essential
