# Application Layer Protocols

## DNS (Domain Name System)

- Translates hostnames to IP addresses
- A host requests from the DNS server the IP address of a hostname
- DNS server address is provided by ISP to your router, then via DHCP to devices

### URL Structure

- **Protocol/scheme** — HTTPS, FTP, SFTP, etc.
- **Hostname** — www.google.com
- **Path and file name** — /author/book.html
- **Fragment** — #page155

### nslookup

Discover IP addresses for any domain name:

```bash
nslookup www.google.com
```

## HTTP and HTML

1. Client sends request to DNS to get the IP of the URL
2. Uses the IP to send a request via HTTP on port 80
3. Server responds with web page using markup languages
4. Browser interprets HTML

- **HTTP** — not secure, can be intercepted
- **HTTPS** — secure HTTP using port 443 with secure transport protocols

## FTP (File Transfer Protocol)

- Transfers files from one computer to another
- Two ports: Control (21) for commands, Data (20) for transfers
- Can "get" or "put" files

Modes:
- **Active** — server approves data request (can have firewall issues)
- **Passive** — server merely "listens," user establishes both channels

Pros: multiple files, resume transfers, schedule transfers
Cons: lack of security, not encrypted

Alternatives: SFTP (port 22), HTTPS, FTPS, AS2

## Virtual Terminals

- **SSH** — secure remote login, encrypted
- **Telnet** — port 23, NOT secure (plaintext), now obsolete for most uses

## Email Protocols

| Protocol | Port | Description |
|----------|------|-------------|
| SMTP | 25 | Sends messages between servers |
| POP3 | 110 | Downloads messages, removes from server |
| IMAP4 | 143 | Downloads messages, keeps on server |

## VoIP (Voice over IP)

- Peer-to-peer technology
- Analog voice → digital data → encapsulated in IP packets
- Calls to regular phones require a gateway to PSTN
