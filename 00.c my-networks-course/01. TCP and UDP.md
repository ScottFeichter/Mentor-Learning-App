# TCP and UDP

## Transport Protocols

Transport protocols act as the "delivery person." IP is concerned with machine-to-machine communication, and HTTP is designed for application-to-application communication. Transport protocols bridge the gap between the network and software.

## TCP (Transmission Control Protocol)

- **Connection-oriented** — establishes a connection between two sockets
- **Reliable** — segments respect strict order and verify receipt
- Data can't be "lost" — missing segments are re-sent
- Relatively "heavy" — messages may take longer but arrive complete

### Common TCP Use Cases

- File transfer
- Web browsing (HTTP/HTTPS)
- CRUD operations
- Email

## UDP (User Datagram Protocol)

- **Connection-less** — no verification of receipt
- **Unreliable** — packets may be lost or arrive out of order
- Trades reliability for raw speed
- If order matters, the application must sort things out

### Common UDP Use Cases

- DNS
- Discovery requests
- Video game world state updates
- Video and audio streaming
- Voice-over-IP (VoIP)
- Continuous data broadcasts (smart home devices)

## Key Differences

| Feature | TCP | UDP |
|---------|-----|-----|
| Connection | Connection-oriented | Connection-less |
| Reliability | Guaranteed delivery | No guarantee |
| Ordering | Sequenced | Unordered |
| Speed | Slower | Faster |
| Use case | Data integrity critical | Speed critical |
