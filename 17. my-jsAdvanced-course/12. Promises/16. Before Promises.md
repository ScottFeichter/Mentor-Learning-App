# Before Promises: Callbacks

**Callbacks** were the primary way to handle asynchronous operations before Promises were introduced in ES6 (2015).

## Callback Pattern

```javascript
function fetchUser(id, callback) {
  setTimeout(() => {
    const user = { id: id, name: "John" };
    callback(null, user); // (error, result)
  }, 1000);
}

fetchUser(1, function(error, user) {
  if (error) {
    console.error(error);
  } else {
    console.log(user);
  }
});
```

## The Problem: Callback Hell

When you needed multiple async operations, callbacks created deeply nested code:

```javascript
fetchUser(1, function(error, user) {
  if (error) throw error;
  
  fetchPosts(user.id, function(error, posts) {
    if (error) throw error;
    
    fetchComments(posts[0].id, function(error, comments) {
      if (error) throw error;
      
      console.log(comments);
    });
  });
});
```

## Other Pre-Promise Solutions

**1. Named Functions**
- Avoided nesting by using named callback functions
- Still difficult to follow execution flow

**2. Libraries**
- **Async.js** - provided utilities like `async.waterfall()`, `async.parallel()`
- **jQuery Deferred** - early promise-like implementation
- **Q.js** - promise library before native support

**3. Event Emitters**
- Used for handling multiple async events
- Still common in Node.js streams

Promises solved callback hell by providing chainable `.then()` methods and better error handling, making asynchronous code much more readable and maintainable.
