# The Reject Function

## Overview

The reject function is one of the two callback functions provided to the executor function. It is used to signal that the asynchronous operation has failed.

## Basic Usage

```javascript
let myPromise = new Promise(function executor(resolve, reject) {
  // Simulate an operation that might fail
  let operationFailed = true;
  
  if (operationFailed) {
    reject("Something went wrong!"); // Calls reject with error message
  } else {
    resolve("Success!");
  }
});
```

## What Reject Does

When called, the reject function:

1. **Changes state** from `pending` to `rejected`
2. **Stores the error reason** in the Promise's internal value property
3. **Executes queued `.catch()` handlers** immediately
4. **Prevents future state changes** (Promise can only be settled once)

## Handling Rejected Promises

```javascript
myPromise
  .then(function(value) {
    console.log("Success:", value);
  })
  .catch(function(error) {
    console.log("Error:", error); // This will run if reject() was called
  });
```

## Error Objects

You can pass any type of value to reject, but Error objects are common:

```javascript
new Promise(function(resolve, reject) {
  try {
    // Some risky operation
    throw new Error("Something broke!");
  } catch (error) {
    reject(error); // Pass the Error object
  }
});
```

## Automatic Rejection

If the executor function throws an error, the Promise is automatically rejected:

```javascript
new Promise(function(resolve, reject) {
  throw new Error("Oops!"); // Automatically calls reject(error)
});
```

The reject function is the Promise's way of handling failure cases in asynchronous operations.
