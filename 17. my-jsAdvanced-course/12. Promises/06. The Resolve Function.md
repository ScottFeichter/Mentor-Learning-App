# The Resolve Function

## Where Resolve Stores Data

The resolve function stores the success data in the Promise object's internal value property.

```javascript
let myPromise = new Promise(function executor(resolve, reject) {
  resolve("success data");
});

// Internally, the Promise object now looks something like:
// {
//   state: "fulfilled",
//   value: "success data",        ← stored here
//   handlers: [...]
// }
```

## Accessing the Value

You can't directly access this internal value - you have to use `.then()`:

```javascript
myPromise.then(function(value) {
  console.log(value); // "success data" - comes from internal value property
});
```

Similarly, `reject("error reason")` would store the error in an internal property (often called the "reason").

## Promise Object Structure

So the Promise object acts like a container that holds:

- **State**: `pending`, `fulfilled`, or `rejected`
- **Value**: The success data (when fulfilled) or error reason (when rejected)
- **Handlers**: Queue of `.then()`/`.catch()` callbacks waiting to run

The resolve/reject functions populate these internal properties.

## How Resolve Works Internally

The resolve function is created internally by the JavaScript engine. A simplified version might look like this:

```javascript
function resolve(value) {
  if (this.state !== "pending") return; // Can only resolve once

  this.state = "fulfilled";
  this.value = value;

  // Execute all queued .then() handlers
  this.handlers.forEach(handler => {
    if (handler.onFulfilled) {
      handler.onFulfilled(value);
    }
  });
}
```

## Key Points

- It's bound to the specific Promise instance (`this`)
- It can only be called once (state check)
- It stores the value and changes state
- It immediately executes any waiting `.then()` handlers
- It's created fresh for each new Promise

The actual implementation is more complex (handles edge cases, microtasks, etc.), but this captures the core behavior: change state, store value, trigger handlers.

The reject function would be similar but set `state = "rejected"` and execute `.catch()` handlers instead.

These functions are essentially the Promise's internal API that the executor gets access to.
