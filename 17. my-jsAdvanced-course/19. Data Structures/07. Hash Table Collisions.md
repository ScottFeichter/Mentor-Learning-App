# Hash Table Collisions

Two keys hash to the same bucket.

## Reducing Collisions

- Increase the underlying array size (probability of collision = 1 / buckets.length)
- You can never completely avoid them

## Resolving Collisions

A clever solution is to use a **linked list** in a bucket having a collision.

- Requires adding a `next` pointer to each key:value pair
- Since this requires list traversal it is O(n)
- But `n` refers to the number of collisions in a given bucket, not the total values in the hash table
- With an appropriately sized array, collisions remain low

## Load Factor

**Load Factor** = number of key:value pairs / number of buckets

- Used to trigger a resize
- Different languages resize at different load factors, but generally **0.7**
- This means a hash table always wastes between 35-70% of allocated memory
- Still has a space complexity of O(n)

## Other Collision Resolution Methods

- **Double-hashing**
- **Open addressing**
