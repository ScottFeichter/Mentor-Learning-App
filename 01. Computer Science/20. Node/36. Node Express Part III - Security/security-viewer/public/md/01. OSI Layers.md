# OSI Layers

The OSI (Open Systems Interconnection) model has 7 layers. Here's how they map to the security concerns covered in this course:

| OSI Layer | # | Security Relevance to Web Dev |
|---|---|---|
| Physical | 1 | Not covered — hardware/cables, outside web dev scope |
| Data Link | 2 | Not covered — MAC addresses/switches, outside web dev scope |
| Network | 3 | Partially relevant — IP-level routing, firewalls |
| Transport | 4 | TLS/HTTPS — encrypts data in transit |
| Session | 5 | Session management, cookies, authentication |
| Presentation | 6 | Encoding, payload encryption, sanitization |
| Application | 7 | HTTP, XSS, CSRF, injection, browser security |

## Where Web Developers Live

Layers **4–7** are where web developers spend most of their time. Layers 1–3 are typically handled by network engineers, cloud providers, or managed infrastructure (e.g. AWS VPCs, security groups).

## Notes

- The **Server/Infrastructure** and **Database** security concerns from `00. Security Levels.md` don't map cleanly to a single OSI layer — they span multiple layers and fall more under operational security.
- The OSI model is a conceptual framework. Real-world protocols (like TCP/IP) don't always align perfectly with it, but it's useful for understanding where different security concerns live.
