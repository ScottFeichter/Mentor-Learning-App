# Database Keys

## What Is a Key?

A **key** is a column (or set of columns) in a table that uniquely identifies a row or establishes a relationship between tables.

Keys are how databases keep data organized and connected.

## Types of Keys

### Primary Key

A column that **uniquely identifies each row** in a table. Every table should have one.

- Must be unique (no two rows can have the same value)
- Cannot be null
- Typically an auto-incrementing integer or UUID

```sql
CREATE TABLE users (
  id INTEGER PRIMARY KEY,  -- Primary key
  name TEXT,
  email TEXT
);
```

### Foreign Key

A column that **references the primary key of another table**. This is how relationships are created.

```sql
CREATE TABLE orders (
  id INTEGER PRIMARY KEY,
  user_id INTEGER,         -- Foreign key
  product TEXT,
  FOREIGN KEY (user_id) REFERENCES users(id)
);
```

The `user_id` in the orders table points back to the `id` in the users table.

### Composite Key

A primary key made up of **two or more columns** together.

```sql
CREATE TABLE enrollments (
  student_id INTEGER,
  course_id INTEGER,
  PRIMARY KEY (student_id, course_id)  -- Composite key
);
```

Neither column is unique alone, but the combination is.

### Unique Key

A column that must have **unique values** but is not the primary key.

```sql
CREATE TABLE users (
  id INTEGER PRIMARY KEY,
  email TEXT UNIQUE  -- Unique key
);
```

## Why Keys Matter

- **Identify rows** - primary keys give each row a unique address
- **Connect tables** - foreign keys create relationships between tables
- **Enforce integrity** - prevent duplicate or orphaned data
- **Improve performance** - keys are automatically indexed for fast lookups
