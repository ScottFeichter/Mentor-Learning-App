# Prisma Migrate

## What Is Prisma Migrate?

Prisma Migrate is a database migration tool that translates changes in your Prisma schema into SQL migration files. It keeps your database schema in sync with your application code.

## Migration Commands

| Command | Purpose |
|---------|---------|
| `npx prisma migrate dev` | Create and apply migration (development) |
| `npx prisma migrate deploy` | Apply pending migrations (production) |
| `npx prisma migrate reset` | Drop database, reapply all migrations, run seed |
| `npx prisma migrate status` | Check migration status |
| `npx prisma db push` | Push schema changes without creating migration files |

## Development Workflow

### 1. Modify the Schema

```prisma
model User {
  id    Int     @id @default(autoincrement())
  email String  @unique
  name  String?
  age   Int?    // ← new field added
}
```

### 2. Create and Apply Migration

```bash
npx prisma migrate dev --name add_age_to_user
```

This does three things:
1. Generates a SQL migration file
2. Applies the migration to your database
3. Regenerates Prisma Client

### 3. Generated Migration File

```
prisma/migrations/
  └── 20240115120000_add_age_to_user/
      └── migration.sql
```

```sql
-- migration.sql
ALTER TABLE "User" ADD COLUMN "age" INTEGER;
```

## Migration File Structure

```
prisma/
├── schema.prisma
└── migrations/
    ├── 20240101000000_init/
    │   └── migration.sql
    ├── 20240115120000_add_age_to_user/
    │   └── migration.sql
    └── migration_lock.toml
```

- Each migration is a timestamped folder
- Contains the SQL that was applied
- `migration_lock.toml` tracks the database provider
- Migrations are applied in chronological order

## Common Scenarios

### Initial Migration (New Project)

```bash
npx prisma migrate dev --name init
```

### Adding a Field

```prisma
model User {
  id    Int     @id @default(autoincrement())
  email String  @unique
  name  String?
  phone String? // ← add this
}
```

```bash
npx prisma migrate dev --name add_phone_to_user
```

### Adding a New Model

```prisma
model Task {
  id        Int     @id @default(autoincrement())
  title     String
  userId    Int
  user      User    @relation(fields: [userId], references: [id])
}
```

```bash
npx prisma migrate dev --name add_task_model
```

### Making a Field Required

```prisma
// Before
name String?

// After
name String @default("Unknown")
```

```bash
npx prisma migrate dev --name make_name_required
```

## Production Deployment

In production, use `migrate deploy` (not `migrate dev`):

```bash
npx prisma migrate deploy
```

Differences from `migrate dev`:
- Does NOT create new migrations
- Only applies pending migrations
- Does NOT regenerate the client
- Does NOT reset the database
- Safe for production use

## Resetting the Database

```bash
npx prisma migrate reset
```

This will:
1. Drop the database
2. Recreate it
3. Apply all migrations
4. Run the seed script (if configured)

**Warning:** This destroys all data. Only use in development.

## db push (No Migration Files)

```bash
npx prisma db push
```

- Pushes schema changes directly to the database
- Does NOT create migration files
- Useful for prototyping
- Not recommended for production or team projects

## Best Practices

- Always name migrations descriptively: `--name add_email_verification`
- Commit migration files to version control
- Never edit migration files after they've been applied
- Use `migrate deploy` in CI/CD pipelines
- Test migrations on a staging database before production
