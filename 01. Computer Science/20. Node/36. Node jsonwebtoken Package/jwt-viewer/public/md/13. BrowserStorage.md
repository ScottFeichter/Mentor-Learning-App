# Browser Storage

## Types of Browser Storage

### 1. Local Storage

**Capacity**: ~5-10 MB per domain

**Persistence**: Permanent (until manually cleared)

**Scope**: Same origin (protocol + domain + port)

**What to store**:
- User preferences (theme, language)
- Shopping cart data
- Form data for recovery
- Cached application state

```javascript
// Store data
localStorage.setItem('theme', 'dark');

// Retrieve data
const theme = localStorage.getItem('theme');

// Remove data
localStorage.removeItem('theme');

// Clear all
localStorage.clear();
```

### 2. Session Storage

**Capacity**: ~5-10 MB per domain

**Persistence**: Until tab/window closes

**Scope**: Same tab/window only

**What to store**:
- Temporary form data
- Single-session user state
- Wizard/multi-step form progress
- Temporary authentication tokens

```javascript
// Store data
sessionStorage.setItem('step', '3');

// Retrieve data
const step = sessionStorage.getItem('step');
```

### 3. Cookies

**Capacity**: ~4 KB per cookie, ~180 cookies per domain

**Persistence**: Configurable (session or expiration date)

**Scope**: Can be sent to server with every HTTP request

**What to store**:
- Session IDs
- Authentication tokens
- Tracking/analytics data
- User preferences needed server-side

```javascript
// Set cookie
document.cookie = "user=John; expires=Fri, 31 Dec 2024 23:59:59 GMT; path=/";

// Read cookies
console.log(document.cookie);

// Cookie attributes
// - Secure: HTTPS only
// - HttpOnly: Not accessible via JavaScript (set server-side)
// - SameSite: CSRF protection
```

### 4. IndexedDB

**Capacity**: ~50 MB to unlimited (browser-dependent, user can grant more)

**Persistence**: Permanent (until manually cleared)

**Scope**: Same origin

**What to store**:
- Large datasets
- Offline application data
- Files and blobs
- Complex structured data

```javascript
// Open database
const request = indexedDB.open('MyDatabase', 1);

request.onsuccess = (event) => {
  const db = event.target.result;
  // Use database
};
```

### 5. Cache API (Service Workers)

**Capacity**: Varies by browser, typically large (hundreds of MB)

**Persistence**: Permanent (until manually cleared)

**Scope**: Same origin

**What to store**:
- Static assets (CSS, JS, images)
- API responses for offline use
- PWA resources

```javascript
// Cache resources
caches.open('v1').then(cache => {
  cache.add('/styles.css');
});

// Retrieve from cache
caches.match('/styles.css').then(response => {
  // Use cached response
});
```

## Comparison Table

| Storage Type | Capacity | Persistence | Server Access | Use Case |
|--------------|----------|-------------|---------------|----------|
| **Local Storage** | ~5-10 MB | Permanent | No | User preferences, app state |
| **Session Storage** | ~5-10 MB | Tab session | No | Temporary session data |
| **Cookies** | ~4 KB | Configurable | Yes (auto-sent) | Auth tokens, tracking |
| **IndexedDB** | ~50 MB+ | Permanent | No | Large datasets, offline apps |
| **Cache API** | Large | Permanent | No | Static assets, PWA |

## Key Differences

### Local Storage vs Session Storage
- Local Storage persists forever
- Session Storage clears when tab closes

### Cookies vs Local Storage
- Cookies sent with every HTTP request (adds overhead)
- Local Storage stays client-side only
- Cookies can be HttpOnly (more secure for auth)

### IndexedDB vs Local Storage
- IndexedDB handles large, complex data
- Local Storage limited to strings only
- IndexedDB supports transactions and indexes

## Security Considerations

- **Never store sensitive data unencrypted** (passwords, credit cards)
- **XSS attacks** can access Local/Session Storage
- **Use HttpOnly cookies** for authentication tokens
- **Set SameSite attribute** on cookies to prevent CSRF
- **Use Secure flag** for cookies on HTTPS sites

## Browser Support

All modern browsers support these storage mechanisms. Check [caniuse.com](https://caniuse.com) for specific version support.
