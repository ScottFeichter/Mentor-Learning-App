# Authentication Security

## Password Storage
- Passwords stored as cryptographic hashes, not plain text
- Protects against database breaches
- Prevents internal access to user passwords

## JWT Tokens
- Issued upon login, server-signed to identify users
- Included in subsequent requests
- Should not contain sensitive data
- Stored in browser storage (vulnerable to XSS attacks)
- XSS: Attackers inject malicious scripts to compromise user data/sessions

## Secure Storage
- Use HTTP-only cookies (not accessible via JavaScript)
- Reduces XSS attack risk
- Protect against CSRF with packages like host-csrf
- CSRF: Ensures requests are intentional from authenticated users, not attackers

## Route Protection
- Use authentication middleware to validate JWT
- Stores user details in req.user for route handlers
- Public routes (login, registration) remain accessible without authentication

## Error Handling
- Use express-async-errors for async error management
- StatusError class for structured errors with HTTP status codes
- Error middleware returns descriptive messages for expected errors (validation)
- Generic messages for unexpected errors (crashes, null references, edge cases)

## Security Testing
- Regular testing crucial for Node.js applications
- Focus on: input validation, authentication, data security, error handling
- Use appropriate security tools
