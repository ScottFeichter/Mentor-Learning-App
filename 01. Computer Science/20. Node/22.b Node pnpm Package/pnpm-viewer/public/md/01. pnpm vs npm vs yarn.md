# pnpm vs npm vs yarn

## Speed Comparison

| Operation | npm | yarn | pnpm |
|-----------|-----|------|------|
| Clean install | Slowest | Fast | Fastest |
| With lockfile | Moderate | Fast | Fastest |
| With cache | Fast | Fast | Fastest |

## Disk Usage

- **npm** — Each project gets its own full copy of every package
- **yarn** — Same as npm (flat node_modules with copies)
- **pnpm** — Single global store, projects use hard links (saves 50-80% disk space)

## Lockfile Format

| Manager | Lockfile |
|---------|----------|
| npm | `package-lock.json` |
| yarn | `yarn.lock` |
| pnpm | `pnpm-lock.yaml` |

## node_modules Structure

### npm / yarn (flat)
```
node_modules/
  express/
  body-parser/      (hoisted, even if not in your package.json)
  accepts/          (hoisted transitive dep)
```

### pnpm (strict)
```
node_modules/
  .pnpm/
    express@4.18.2/
      node_modules/
        express/
        body-parser/  (only accessible to express)
  express -> .pnpm/express@4.18.2/node_modules/express
```

## Phantom Dependencies

A phantom dependency is a package you can `require()` even though you never added it to your `package.json`. This happens because npm/yarn hoist transitive dependencies.

```javascript
// This works with npm/yarn but SHOULDN'T
const accepts = require('accepts'); // transitive dep of express

// With pnpm, this correctly throws an error
// unless you explicitly add 'accepts' to your package.json
```

## Monorepo Support

### pnpm workspaces (pnpm-workspace.yaml)
```yaml
packages:
  - 'packages/*'
  - 'apps/*'
```

### npm workspaces (package.json)
```json
{
  "workspaces": ["packages/*", "apps/*"]
}
```

### yarn workspaces (package.json)
```json
{
  "workspaces": ["packages/*", "apps/*"]
}
```

## When to Use Which

| Use Case | Recommendation |
|----------|---------------|
| Default/simple projects | npm (comes with Node) |
| Monorepos | pnpm or yarn |
| Disk space concerns | pnpm |
| Maximum speed | pnpm |
| Legacy projects | npm or yarn (whatever lockfile exists) |
| CI/CD pipelines | pnpm (fastest, reproducible) |

## Summary

- All three use the same npm registry
- pnpm is fastest and most disk-efficient
- pnpm prevents phantom dependency bugs
- npm is the default and most widely supported
- yarn pioneered lockfiles and workspaces
- Choose based on your team's needs and existing lockfile
