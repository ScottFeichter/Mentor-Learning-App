# 24. What Is The Use Of JWT?

## Why Use JWTs Despite The Risk?

Every authentication mechanism carries theft risk — session IDs, API keys, and cookies can all be stolen too. JWTs aren't uniquely vulnerable; they simply make different trade-offs that offer significant advantages in modern architectures.

## Key Benefits

### Stateless Authentication
The server doesn't need to store session data or query a database on every request. The token itself contains everything needed to verify the user's identity and permissions. This eliminates a major bottleneck.

### Scalability
Because no server-side session store is required, any instance behind a load balancer can validate the token independently. Horizontal scaling becomes trivial — no sticky sessions, no shared session cache.

### Cross-Service Communication (Microservices)
A single JWT can be passed between services without each service needing to call back to an auth server. Service B trusts the token signed by the auth server just as Service A does.

### Cross-Domain / Cross-Origin Friendly
Unlike cookies, JWTs can be sent in an `Authorization` header to any domain. This makes them ideal for SPAs calling APIs on different origins.

### Decoupled Auth Server
The service that issues tokens can be completely separate from the services that consume them. Consumers only need the public key to verify signatures.

### Embedded Claims
Permissions, roles, and user metadata travel with the token. Services can make authorization decisions without additional lookups.

### Mobile & IoT Friendly
Stateless tokens work naturally on platforms where cookie-based sessions are awkward or unavailable.

## The Trade-Off In Perspective

| Concern | Session-Based | JWT-Based |
|---------|--------------|-----------|
| Server memory | Grows with users | None |
| Database lookup per request | Yes | No |
| Revocation | Immediate (delete session) | Requires extra mechanism |
| Horizontal scaling | Needs shared store | Built-in |
| Cross-service auth | Difficult | Natural |

## Bottom Line

JWTs are useful because they trade **immediate revocability** for **statelessness, scalability, and portability**. When combined with short expiration times and refresh token rotation, the theft risk becomes manageable — and the architectural benefits are substantial.
