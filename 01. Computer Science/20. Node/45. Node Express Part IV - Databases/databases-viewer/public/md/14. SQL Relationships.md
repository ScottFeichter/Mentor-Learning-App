# Relationships

## What Are Relationships?

A **relationship** is a connection between two tables established through keys. Relationships allow you to split data across multiple tables while keeping it connected.

## Types of Relationships

### One-to-One

One row in Table A relates to exactly one row in Table B.

```
Users Table:              Profiles Table:
| id | name  |           | id | user_id | bio          |
|----|-------|           |----|---------|--------------|
| 1  | John  |           | 1  | 1       | "Developer"  |
| 2  | Sarah |           | 2  | 2       | "Designer"   |
```

Each user has exactly one profile. Each profile belongs to exactly one user.

**Use case:** Splitting a table with many columns into two for organization.

### One-to-Many

One row in Table A relates to many rows in Table B.

```
Users Table:              Orders Table:
| id | name  |           | id | user_id | product  |
|----|-------|           |----|---------|----------|
| 1  | John  |           | 1  | 1       | Widget   |
| 2  | Sarah |           | 2  | 1       | Gadget   |
                          | 3  | 2       | Widget   |
```

One user can have many orders. Each order belongs to one user.

**Use case:** The most common relationship type. Users → posts, authors → books, customers → orders.

### Many-to-Many

Many rows in Table A relate to many rows in Table B. Requires a **junction table** (also called a join table).

```
Students Table:       Enrollments (Junction):     Courses Table:
| id | name  |       | student_id | course_id |   | id | title    |
|----|-------|       |------------|-----------|   |----|----------|
| 1  | John  |       | 1          | 1         |   | 1  | Math     |
| 2  | Sarah |       | 1          | 2         |   | 2  | Science  |
                      | 2          | 1         |
```

John takes Math and Science. Both John and Sarah take Math.

**Use case:** Students ↔ courses, products ↔ categories, users ↔ roles.

## RDBMS vs Non-Relational (NoSQL)

- **RDBMS** - structured tables, strict schemas, SQL, relationships (PostgreSQL, MySQL)
- **NoSQL** - flexible documents, dynamic schemas, no SQL required (MongoDB, Redis)

In NoSQL databases, relationships are often handled by embedding data within documents rather than using separate tables and keys.
