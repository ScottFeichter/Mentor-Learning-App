# Thenables in Mongoose

## What are Thenables?

Thenables are objects that have a `then()` method, making them promise-like. Mongoose queries return thenables, not actual Promises.

## Mongoose Query Thenables

Mongoose queries are lazy and only execute when you call `then()`, `catch()`, `exec()`, or use `await`.

```javascript
// This doesn't execute yet - it's a thenable
const query = User.findOne({ name: 'John' });

// Now it executes
query.then(user => console.log(user));
```

## Using Thenables

### With .then()
```javascript
User.findById(id)
  .then(user => {
    console.log(user);
    return user.save();
  })
  .then(savedUser => console.log('Saved:', savedUser))
  .catch(err => console.error(err));
```

### With async/await
```javascript
async function getUser(id) {
  try {
    const user = await User.findById(id);
    return user;
  } catch (error) {
    console.error(error);
  }
}
```

### With .exec()
```javascript
// Converts thenable to actual Promise
const user = await User.findById(id).exec();
```

## Key Differences from Promises

### Mongoose Thenable:
- Lazy execution (only runs when consumed)
- Can be chained with query methods
- Has additional Mongoose-specific methods

```javascript
User.findOne({ name: 'John' })
  .select('name email')  // Mongoose method
  .populate('posts')     // Mongoose method
  .then(user => console.log(user));
```

### Actual Promise:
- Executes immediately
- Standard Promise methods only

```javascript
User.findById(id).exec()  // Returns actual Promise
  .then(user => console.log(user));
```

## Best Practices

1. **Use async/await** for cleaner code:
```javascript
const user = await User.findById(id);
```

2. **Use .exec()** when you need actual Promises:
```javascript
const userPromise = User.findById(id).exec();
```

3. **Chain query methods** before consuming:
```javascript
const user = await User.findOne({ email })
  .select('name email')
  .populate('profile');
```

## Differences: then vs catch vs exec vs await

### .then()
- Executes the query and handles success
- Returns a new thenable/promise
- Chainable

```javascript
User.findById(id)
  .then(user => console.log(user))
  .then(() => console.log('Done'));
```

### .catch()
- Handles errors in the promise chain
- Must be used with `.then()` or after other promise methods
- Returns a new thenable/promise

```javascript
User.findById(id)
  .then(user => console.log(user))
  .catch(err => console.error(err));
```

### .exec()
- Converts Mongoose thenable to actual Promise
- Executes the query immediately
- Returns a real Promise (not thenable)

```javascript
const promise = User.findById(id).exec(); // Real Promise
promise.then(user => console.log(user));
```

### await
- Pauses function execution until promise resolves
- Must be used inside async function
- Cleaner syntax, handles both success and error with try/catch

```javascript
async function getUser(id) {
  try {
    const user = await User.findById(id); // Executes query
    return user;
  } catch (error) {
    console.error(error);
  }
}
```

### When to Use Each:

- **await**: Modern, clean syntax - preferred approach
- **.then()/.catch()**: Legacy promise chains, callback-style
- **.exec()**: When you need actual Promises for libraries that require them
- **Direct thenable**: When chaining multiple Mongoose query methods

## Summary

- Mongoose queries return thenables (promise-like objects)
- Thenables are lazy - they don't execute until consumed
- Use `await`, `.then()`, or `.exec()` to execute queries
- Thenables allow chaining Mongoose query methods before execution
