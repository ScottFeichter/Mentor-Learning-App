# Data Validation and Sanitization

## Data Validation

**Data validation** ensures that input data meets specific criteria and business rules before processing or storage.

### Purpose
- **Prevent invalid data** from entering the system
- **Enforce business rules** and constraints
- **Improve data quality** and consistency
- **Provide user feedback** on input errors

### Types of Validation

#### Client-Side Validation
```javascript
// Form validation example
function validateEmail(email) {
  const regex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
  return regex.test(email);
}

function validateAge(age) {
  return age >= 0 && age <= 120;
}
```

#### Server-Side Validation
```javascript
// Express.js with validation middleware
const { body, validationResult } = require('express-validator');

app.post('/users', [
  body('email').isEmail().normalizeEmail(),
  body('age').isInt({ min: 0, max: 120 }),
  body('name').isLength({ min: 1, max: 50 }).trim()
], (req, res) => {
  const errors = validationResult(req);
  if (!errors.isEmpty()) {
    return res.status(400).json({ errors: errors.array() });
  }
  // Process valid data
});
```

#### Database-Side Validation
```sql
-- Constraints enforced at the database level
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  name VARCHAR(50) NOT NULL,
  email VARCHAR(255) UNIQUE NOT NULL,
  age INTEGER CHECK (age >= 0 AND age <= 120),
  role VARCHAR(20) DEFAULT 'user',
  created_at TIMESTAMP DEFAULT NOW()
);
```

```javascript
// Mongoose schema-level validation (maps to DB constraints)
const userSchema = new mongoose.Schema({
  name: { type: String, required: true, maxlength: 50 },
  email: { type: String, required: true, unique: true },
  age: { type: Number, min: 0, max: 120 }
});
```

#### Common Database-Side Mechanisms
- **NOT NULL** — prevents null values
- **UNIQUE** — prevents duplicate entries
- **CHECK constraints** — e.g. `CHECK (age >= 0)`
- **Data types** — a column defined as `INTEGER` rejects strings
- **Foreign key constraints** — ensures referential integrity
- **Triggers** — custom logic that runs before/after inserts or updates
- **Stored procedures** — encapsulate validation logic inside the database

### Common Validation Rules
- **Required fields**: Must be present
- **Data types**: String, number, boolean, date
- **Format**: Email, phone, URL patterns
- **Range**: Min/max values, length limits
- **Custom rules**: Business-specific logic
