## Two Main Categories

- **Relational (SQL)** - data in tables with rows and columns (PostgreSQL, MySQL)
- **Non-Relational (NoSQL)** - data in documents, key-value pairs, graphs, etc. (MongoDB, Redis)

## NoSQL Subtypes

| Type | How It Stores Data | Example | Use Case |
|---|---|---|---|
| **Document** | JSON-like documents | MongoDB, CouchDB | Flexible content, user profiles |
| **Key-Value** | Simple key → value pairs | Redis, DynamoDB | Caching, sessions, fast lookups |
| **Graph** | Nodes and edges (relationships) | Neo4j, Amazon Neptune | Social networks, recommendations |
| **Column-Family** | Columns grouped into families | Cassandra, HBase | Large-scale analytics, time-series data |

## How to Choose?

- **Need strict structure and relationships?** → Relational (SQL)
- **Need flexibility and speed with changing data?** → Document (NoSQL)
- **Need extremely fast simple lookups?** → Key-Value (NoSQL)
- **Need to model complex relationships?** → Graph (NoSQL)
- **Need to handle massive amounts of data?** → Column-Family (NoSQL)
