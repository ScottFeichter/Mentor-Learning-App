# JWT Header

## What is it?

The JWT Header is the first part of a JSON Web Token.

It's a JSON object that describes the cryptographic operations applied to the JWT and optionally contains additional metadata about the token type.

## Structure

The header is Base64URL-encoded and typically contains two fields:

```json
{
  "alg": "HS256",
  "typ": "JWT"
}
```

## Common Fields

### `alg` (Algorithm) - Required
Specifies the cryptographic algorithm used to sign the token.

**Common options:**
- `HS256` - HMAC with SHA-256 (symmetric)
- `HS384` - HMAC with SHA-384 (symmetric)
- `HS512` - HMAC with SHA-512 (symmetric)
- `RS256` - RSA with SHA-256 (asymmetric)
- `RS384` - RSA with SHA-384 (asymmetric)
- `RS512` - RSA with SHA-512 (asymmetric)
- `ES256` - ECDSA with SHA-256 (asymmetric)
- `ES384` - ECDSA with SHA-384 (asymmetric)
- `ES512` - ECDSA with SHA-512 (asymmetric)
- `PS256` - RSA-PSS with SHA-256 (asymmetric)
- `none` - No signature (not recommended for production)

### `typ` (Type) - Optional
Declares the media type of the JWT. Usually set to `"JWT"`.

### `kid` (Key ID) - Optional
Identifies which key was used to sign the token. Useful when multiple keys are available.

```json
{
  "alg": "RS256",
  "typ": "JWT",
  "kid": "key-2024-01"
}
```

### `cty` (Content Type) - Optional
Used when the JWT payload is another JWT (nested JWT).

## Example Headers

**Basic HMAC:**
```json
{
  "alg": "HS256",
  "typ": "JWT"
}
```

**RSA with Key ID:**
```json
{
  "alg": "RS256",
  "typ": "JWT",
  "kid": "prod-key-001"
}
```

**ECDSA:**
```json
{
  "alg": "ES256",
  "typ": "JWT"
}
```

## Security Considerations

- Never use `"alg": "none"` in production
- Choose algorithm based on your security requirements:
  - Symmetric (HS*): Faster, but same key for signing and verification
  - Asymmetric (RS*, ES*, PS*): More secure for distributed systems, different keys for signing and verification
