# Security Checklist

A comprehensive checklist for securing your authentication system in production.

## Password Security

### ✅ Password Hashing
- [ ] Use bcrypt (not MD5, SHA1, or SHA256)
- [ ] Salt rounds set to 10 or higher
- [ ] Use async methods (hash, compare)
- [ ] Never store plain-text passwords
- [ ] Hash on server side only

### ✅ Password Requirements
- [ ] Minimum 8 characters
- [ ] Require mix of uppercase, lowercase, numbers
- [ ] Require special characters
- [ ] Check against common password lists
- [ ] Implement password strength meter

### ✅ Password Reset
- [ ] Use cryptographically secure tokens
- [ ] Set token expiration (15-60 minutes)
- [ ] Invalidate token after use
- [ ] Don't reveal if email exists
- [ ] Rate limit reset requests

## Session Security

### ✅ Session Configuration
- [ ] Use strong, random session secret
- [ ] Set httpOnly: true on cookies
- [ ] Set secure: true in production (HTTPS)
- [ ] Set sameSite: 'strict' or 'lax'
- [ ] Set appropriate maxAge
- [ ] Use persistent session store (not memory)

```javascript
app.use(session({
  secret: process.env.SESSION_SECRET, // Strong random string
  resave: false,
  saveUninitialized: false,
  store: MongoStore.create({ mongoUrl: process.env.MONGODB_URI }),
  cookie: {
    httpOnly: true,
    secure: process.env.NODE_ENV === 'production',
    sameSite: 'strict',
    maxAge: 24 * 60 * 60 * 1000
  }
}));
```

### ✅ Session Management
- [ ] Regenerate session ID after login
- [ ] Destroy session on logout
- [ ] Implement session timeout
- [ ] Clear expired sessions regularly
- [ ] Limit concurrent sessions per user

## Authentication Security

### ✅ Login Protection
- [ ] Rate limit login attempts
- [ ] Implement account lockout after failed attempts
- [ ] Use same error message for invalid username/password
- [ ] Log failed login attempts
- [ ] Implement CAPTCHA after multiple failures

```javascript
const rateLimit = require('express-rate-limit');

const loginLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,
  max: 5,
  message: 'Too many login attempts'
});

app.post('/login', loginLimiter, ...);
```

### ✅ Registration Protection
- [ ] Validate all input fields
- [ ] Check for existing username/email
- [ ] Implement email verification
- [ ] Rate limit registration
- [ ] Use CAPTCHA to prevent bots

### ✅ Error Messages
- [ ] Don't reveal if username exists
- [ ] Use generic error messages
- [ ] Log detailed errors server-side only
- [ ] Don't expose stack traces to users

## HTTPS and Transport Security

### ✅ HTTPS
- [ ] Use HTTPS in production
- [ ] Redirect HTTP to HTTPS
- [ ] Use valid SSL certificate
- [ ] Enable HSTS (HTTP Strict Transport Security)

```javascript
// Redirect HTTP to HTTPS
app.use((req, res, next) => {
  if (req.header('x-forwarded-proto') !== 'https' && process.env.NODE_ENV === 'production') {
    res.redirect(`https://${req.header('host')}${req.url}`);
  } else {
    next();
  }
});

// HSTS
app.use((req, res, next) => {
  res.setHeader('Strict-Transport-Security', 'max-age=31536000; includeSubDomains');
  next();
});
```

## Cross-Site Attack Prevention

### ✅ CSRF Protection
- [ ] Implement CSRF tokens
- [ ] Use sameSite cookie attribute
- [ ] Verify Origin/Referer headers
- [ ] Use double-submit cookie pattern

```javascript
const csrf = require('csurf');
const csrfProtection = csrf({ cookie: true });

app.use(csrfProtection);

app.get('/form', (req, res) => {
  res.render('form', { csrfToken: req.csrfToken() });
});
```

### ✅ XSS Protection
- [ ] Set httpOnly on cookies
- [ ] Sanitize all user input
- [ ] Use Content Security Policy (CSP)
- [ ] Escape output in templates
- [ ] Don't use eval() or innerHTML

```javascript
const helmet = require('helmet');

app.use(helmet.contentSecurityPolicy({
  directives: {
    defaultSrc: ["'self'"],
    scriptSrc: ["'self'"],
    styleSrc: ["'self'", "'unsafe-inline'"]
  }
}));
```

### ✅ CORS Configuration
- [ ] Whitelist specific origins
- [ ] Set credentials: true only when needed
- [ ] Don't use wildcard (*) with credentials
- [ ] Validate Origin header

```javascript
const cors = require('cors');

app.use(cors({
  origin: ['https://yourdomain.com'],
  credentials: true,
  optionsSuccessStatus: 200
}));
```

### ✅ MongoDB Security
- [ ] Use authentication
- [ ] Create database user with minimal permissions
- [ ] Don't expose MongoDB port publicly
- [ ] Use connection string with credentials
- [ ] Enable encryption at rest

### ✅ Query Security
- [ ] Use parameterized queries
- [ ] Validate and sanitize input
- [ ] Implement proper error handling
- [ ] Don't expose database errors to users
- [ ] Use indexes for performance

## Environment and Configuration

### ✅ Environment Variables
- [ ] Store secrets in environment variables
- [ ] Never commit .env to version control
- [ ] Use different secrets for dev/prod
- [ ] Rotate secrets regularly
- [ ] Use strong, random values

```javascript
// .env
SESSION_SECRET=<strong-random-string>
MONGODB_URI=mongodb://user:pass@host:port/db
JWT_SECRET=<another-strong-random-string>
```

### ✅ Dependencies
- [ ] Keep dependencies updated
- [ ] Run npm audit regularly
- [ ] Remove unused dependencies
- [ ] Use package-lock.json
- [ ] Review dependency security advisories

## Monitoring and Logging

### ✅ Logging
- [ ] Log authentication attempts
- [ ] Log failed logins
- [ ] Log account lockouts
- [ ] Log password resets
- [ ] Don't log sensitive data (passwords, tokens)

```javascript
const winston = require('winston');

const logger = winston.createLogger({
  level: 'info',
  format: winston.format.json(),
  transports: [
    new winston.transports.File({ filename: 'error.log', level: 'error' }),
    new winston.transports.File({ filename: 'combined.log' })
  ]
});

// Log failed login
logger.warn('Failed login attempt', { 
  username, 
  ip: req.ip,
  timestamp: new Date()
});
```

### ✅ Monitoring
- [ ] Monitor failed login attempts
- [ ] Alert on unusual activity
- [ ] Track session creation rate
- [ ] Monitor API rate limits
- [ ] Set up uptime monitoring

## Quick Security Audit

Run through this checklist before deploying:

1. **Passwords**: Hashed with bcrypt? ✓
2. **Sessions**: httpOnly, secure, sameSite set? ✓
3. **HTTPS**: Enabled in production? ✓
4. **Rate Limiting**: Implemented on auth routes? ✓
5. **CSRF**: Protection enabled? ✓
6. **XSS**: Input sanitized, CSP configured? ✓
7. **Secrets**: In environment variables? ✓
8. **Dependencies**: Updated and audited? ✓
9. **Logging**: Authentication events logged? ✓
10. **Monitoring**: Alerts configured? ✓
