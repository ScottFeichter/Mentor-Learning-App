# Programming Languages

## Heirarchy

## Definitions

### Bytes
A byte is a unit of digital information consisting of 8 bits. It's the smallest addressable unit of memory in most computer architectures. Programs, data, and instructions are all stored and measured in bytes.

### Runtime
The runtime is the environment in which a program executes. It includes:
- The execution engine (interpreter, virtual machine, or direct CPU execution)
- Memory management systems
- Standard libraries and APIs
- Garbage collectors (if applicable)
- Just-in-time compilers (if applicable)

### Bytecode
Bytecode is an intermediate representation of code that sits between high-level source code and machine code. It's platform-independent instructions designed to be executed by a virtual machine or interpreter. Examples include Java bytecode (executed by JVM), Python bytecode (executed by Python VM), and JavaScript bytecode (executed by JS engines like V8).

## Level 0: Machine Code
**Binary instructions executed directly by CPU**
- `01001000 01100101 01101100 01101100 01101111` (Hello in x86-64)
- Platform-specific (Intel x86, ARM, RISC-V)
- Fastest execution, hardest to write/read
- **Cost per byte**: ~$0.000001 (most efficient)

**Hello Example:**
```assembly
; x86-64 machine code (hexadecimal representation)
48 65 6C 6C 6F 20 57 6F 72 6C 64 21
```

## Level 1: Assembly Language
**Human-readable mnemonics for machine instructions**
- `MOV AX, 1234h` → moves value to register
- One-to-one mapping with machine code
- Platform-specific but readable
- **Examples**: x86 Assembly, ARM Assembly, MIPS Assembly
- **Cost per byte**: ~$0.000002

**Hello Example (x86-64 NASM):**
```assembly
section .data
    hello db 'Hello World!', 0

section .text
    global _start
_start:
    mov rax, 1      ; sys_write
    mov rdi, 1      ; stdout
    mov rsi, hello  ; message
    mov rdx, 12     ; length
    syscall
```

## Level 2: Systems Programming Languages
**Compiled directly to machine code, minimal runtime**

### C (1972)
- Direct memory management
- No garbage collection
- Minimal abstraction over hardware
- **Compilation**: C source → Machine code
- **Cost per byte**: ~$0.000005

**Hello Example:**
```c
#include <stdio.h>
int main() {
    printf("Hello World!\n");
    return 0;
}
```

### C++ (1985)
- C with object-oriented features
- Manual memory management
- Zero-cost abstractions
- **Compilation**: C++ source → Machine code
- **Cost per byte**: ~$0.000008

**Hello Example:**
```cpp
#include <iostream>
int main() {
    std::cout << "Hello World!" << std::endl;
    return 0;
}
```

### Rust (2010)
- Memory safety without garbage collection
- Zero-cost abstractions
- Modern systems programming
- **Compilation**: Rust source → Machine code
- **Cost per byte**: ~$0.000010

**Hello Example:**
```rust
fn main() {
    println!("Hello World!");
}
```

## Level 3: Managed/Runtime Languages
**Compiled to intermediate code, executed by runtime**

### Java (1995)
- **Compilation**: Java source → Java bytecode → JVM execution
- Platform-independent bytecode
- Garbage collected
- JIT compilation to machine code
- **Cost per byte**: ~$0.000020

**Hello Example:**
```java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello World!");
    }
}
```

### C# (2000)
- **Compilation**: C# source → IL bytecode → CLR execution
- Similar to Java but Microsoft ecosystem
- Garbage collected
- JIT compilation to machine code
- **Cost per byte**: ~$0.000025

**Hello Example:**
```csharp
using System;
class Hello {
    static void Main() {
        Console.WriteLine("Hello World!");
    }
}
```

## Level 4: Dynamic/Interpreted Languages
**Executed by interpreters or VMs at runtime**

### JavaScript (1995)
- **Modern execution**: Source → AST → Bytecode → JIT to machine code
- Dynamic typing
- JIT compilation in modern engines (V8, SpiderMonkey)
- **Cost per byte**: ~$0.000030

**Hello Example:**
```javascript
console.log("Hello World!");
```

### Python (1991)
- **Execution**: Source → Python bytecode → Python VM
- Dynamic typing
- Interpreted with some JIT options (PyPy)
- **Cost per byte**: ~$0.000050

**Hello Example:**
```python
print("Hello World!")
```

### Ruby (1995)
- **Execution**: Source → Ruby bytecode → Ruby VM
- Dynamic typing
- Primarily interpreted
- **Cost per byte**: ~$0.000060

**Hello Example:**
```ruby
puts "Hello World!"
```

### PHP (1995)
- **Execution**: Source → Opcodes → Zend Engine
- Dynamic typing
- Primarily interpreted, some JIT in PHP 8+
- **Cost per byte**: ~$0.000040

**Hello Example:**
```php
<?php
echo "Hello World!";
?>
```

## Level 5: Domain-Specific Languages
**Higher-level abstractions for specific domains**

### SQL
- Database query language
- Compiled to execution plans
- **Cost per byte**: ~$0.000100

**Hello Example:**
```sql
SELECT 'Hello World!' AS greeting;
```

### HTML/CSS
- Markup and styling languages
- Parsed and rendered by browsers
- **Cost per byte**: ~$0.000200

**Hello Example:**
```html
<!DOCTYPE html>
<html>
<body>
    <h1>Hello World!</h1>
</body>
</html>
```

### Shell Scripts (Bash, PowerShell)
- Command automation
- Interpreted by shell
- **Cost per byte**: ~$0.000080

**Hello Example (Bash):**
```bash
#!/bin/bash
echo "Hello World!"
```

## Execution Speed Hierarchy (Fastest to Slowest)
1. **Machine Code** (Assembly, C, C++, Rust)
2. **JIT-Compiled** (Modern JavaScript, Java, C#)
3. **Bytecode Interpreted** (Python, Ruby, PHP)
4. **Script Interpreted** (Shell scripts)

## Development Speed Hierarchy (Fastest to Slowest)
1. **High-level Dynamic** (Python, Ruby, JavaScript)
2. **Managed Static** (Java, C#)
3. **Systems** (C++, Rust)
4. **Low-level** (C, Assembly)

## Memory Management
- **Manual**: C, C++, Assembly
- **Ownership**: Rust
- **Garbage Collected**: Java, C#, JavaScript, Python, Ruby, PHP

## Key Insight
Modern languages often blur these boundaries:
- JavaScript JIT compiles to machine code
- Java bytecode gets JIT compiled
- Python can compile to C extensions
- WebAssembly brings near-native performance to browsers

The hierarchy represents abstraction levels, not strict performance tiers.
