# Authentication

## What Is It?

Authentication (AuthN) is the process of verifying **who a user is**. It answers the question: *"Are you really who you claim to be?"*

The most common example: a user submits an email and password, and the server checks if those credentials are valid.

---

## Authentication vs. Authorization

| | Authentication (AuthN) | Authorization (AuthZ) |
|---|---|---|
| **Question** | *Who are you?* | *What can you do?* |
| **When** | Happens first | Happens after authentication |
| **Example** | Logging in with email/password | Checking if the user has admin privileges |
| **Failure response** | `401 Unauthorized` | `403 Forbidden` |

Authentication always comes before authorization. You can't check what someone is allowed to do until you know who they are.

## Common Strategies

### Session-Based Authentication
1. User logs in with credentials
2. Server creates a **session** and stores it (in memory, a DB, or Redis)
3. Server sends a **session ID** back in a cookie
4. Browser sends the cookie with every subsequent request
5. Server looks up the session to identify the user

### Token-Based Authentication (JWT)
1. User logs in with credentials
2. Server generates a **JSON Web Token** containing user info and signs it
3. Token is sent back to the client (stored in localStorage, cookie, etc.)
4. Client sends the token in the `Authorization` header on future requests
5. Server verifies the token's signature — no server-side session storage needed

### OAuth / Third-Party Authentication
User authenticates through an external provider (Google, GitHub, etc.) instead of managing credentials directly. The provider sends back a token your app can use to identify the user.

### API Key Authentication
A unique key is issued to a client (usually for server-to-server communication). Simple but less secure for user-facing apps — keys don't expire by default and aren't tied to a session.

### Multi-Factor Authentication (MFA)
Requires **two or more** verification methods:
- Something you **know** (password)
- Something you **have** (phone, authenticator app)
- Something you **are** (fingerprint, face ID)

## Tools & Libraries

| Tool | Description |
|---|---|
| **bcrypt** / **bcryptjs** | Hash and compare passwords — never store plaintext |
| **jsonwebtoken** | Create and verify JWTs in Node |
| **Passport.js** | Authentication middleware for Express with 500+ strategies (local, Google, GitHub, etc.) |
| **express-session** | Session management middleware for Express |
| **connect-redis** / **connect-mongo** | Session stores for production (don't use in-memory sessions in prod) |
| **OAuth2 / OpenID Connect** | Protocols for third-party auth — implemented via Passport strategies or libraries like `openid-client` |
| **Auth0** / **Firebase Auth** / **AWS Cognito** | Managed authentication services — handle signup, login, MFA, and token management for you |

## Basic Flow in Express

```js
const bcrypt = require('bcryptjs');
const jwt = require('jsonwebtoken');

// Register — hash the password before storing
app.post('/register', async (req, res) => {
  const hashedPassword = await bcrypt.hash(req.body.password, 12);
  // save user with hashedPassword to DB
});

// Login — compare password, issue token
app.post('/login', async (req, res) => {
  const user = await findUserByEmail(req.body.email);
  const match = await bcrypt.compare(req.body.password, user.hashedPassword);

  if (!match) return res.status(401).json({ error: 'Invalid credentials' });

  const token = jwt.sign({ id: user.id }, process.env.JWT_SECRET, { expiresIn: '1h' });
  res.json({ token });
});

// Protected route — verify token
function authenticate(req, res, next) {
  const token = req.headers.authorization?.split(' ')[1];
  if (!token) return res.status(401).json({ error: 'No token provided' });

  try {
    req.user = jwt.verify(token, process.env.JWT_SECRET);
    next();
  } catch {
    res.status(401).json({ error: 'Invalid token' });
  }
}

app.get('/profile', authenticate, (req, res) => {
  res.json({ userId: req.user.id });
});
```

## Key Takeaway

Authentication is the gatekeeper — it establishes identity. Once identity is confirmed, authorization takes over to determine access. Both are essential, and they should always be treated as separate concerns.
