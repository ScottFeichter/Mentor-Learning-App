# Security Terminology

## General Security

- **Whitelist** — by default nobody is allowed in; entities are explicitly added to gain access
- **Blacklist** — by default everyone is allowed in; entities are explicitly added to be denied access
- **Encryption** — converting data into an unreadable format that can be reversed with a key
- **Decryption** — converting encrypted data back to its original readable form
- **Hashing** — one-way transformation of data into a fixed-length string; cannot be reversed (used for passwords)
- **Salting** — adding random data to input before hashing to prevent attacks using precomputed tables
- **Plaintext** — unencrypted, readable data (storing passwords in plaintext = very bad)
- **Cipher** — an algorithm used to perform encryption/decryption
- **Vulnerability** — a weakness in a system that can be exploited
- **Exploit** — a method or tool that takes advantage of a vulnerability
- **Attack Vector** — the path or method an attacker uses to gain access
- **Principle of Least Privilege** — users/processes should only have the minimum access they need

## Web Dev Security

- **TLS (Transport Layer Security)** — protocol that encrypts data in transit between client and server; the "S" in HTTPS
- **SSL (Secure Sockets Layer)** — predecessor to TLS, now deprecated but the term is still used loosely
- **HTTPS** — HTTP over TLS; encrypted communication between browser and server
- **XSS (Cross-Site Scripting)** — injecting malicious scripts into web pages viewed by other users
- **CSRF (Cross-Site Request Forgery)** — tricking a user's browser into making an unintended request to a site they're authenticated on
- **SQL Injection** — inserting malicious SQL into input fields to manipulate database queries
- **DDoS (Distributed Denial of Service)** — flooding a server with traffic to make it unavailable
- **CORS (Cross-Origin Resource Sharing)** — a mechanism that controls which domains can make requests to your server
- **CSP (Content Security Policy)** — a security header that restricts where scripts/resources can be loaded from
- **SRI (Subresource Integrity)** — verifying that files fetched from CDNs haven't been tampered with

## Authentication & Authorization

- **Authentication (AuthN)** — verifying *who* someone is (login)
- **Authorization (AuthZ)** — verifying *what* someone is allowed to do (permissions)
- **Session** — server-side record of a user's authenticated state
- **Token** — a piece of data (like a JWT) used to prove identity without re-sending credentials
- **JWT (JSON Web Token)** — a compact, self-contained token for securely transmitting information between parties
- **OAuth** — a protocol that lets users grant third-party apps limited access without sharing passwords
- **MFA (Multi-Factor Authentication)** — requiring more than one form of verification (password + phone code, etc.)

## Data Protection

- **Sanitization** — cleaning user input to remove dangerous or unwanted content
- **Validation** — checking that input meets expected rules before processing it
- **Escaping** — converting special characters so they're treated as text, not code
- **Parameterized Queries** — using placeholders in database queries to prevent injection attacks
- **Encryption at Rest** — encrypting stored data (in a database or on disk)
- **Encryption in Transit** — encrypting data as it moves across the network (TLS)
