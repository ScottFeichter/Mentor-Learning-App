# Node Errors

These are errors that come from the **Node.js runtime**, not from the JavaScript language specification (ECMAScript). Standard JS errors like `TypeError`, `ReferenceError`, `SyntaxError`, etc. exist in every JS runtime. The errors below only exist in Node because they come from **Node's core modules and system-level operations** — things like the file system, networking, child processes, and the operating system.

---

## System Errors

Node wraps operating system errors into JS Error objects. These come from failed system calls (file I/O, networking, etc.) and have extra properties that standard JS errors don't have.

### Extra Properties on Node System Errors

| Property | What It Is |
|----------|-----------|
| `error.code` | A string like `ENOENT`, `ECONNREFUSED`, `EACCES` — the system error code |
| `error.errno` | The numeric OS-level error number |
| `error.syscall` | The system call that failed (e.g. `open`, `read`, `connect`) |
| `error.path` | The file path involved (if applicable) |
| `error.address` | The network address involved (if applicable) |
| `error.port` | The network port involved (if applicable) |

### Common System Error Codes

| Code | Meaning |
|------|---------|
| `ENOENT` | No such file or directory |
| `EACCES` | Permission denied |
| `EEXIST` | File already exists |
| `EISDIR` | Expected a file but got a directory |
| `ENOTDIR` | Expected a directory but got a file |
| `ENOTEMPTY` | Directory is not empty |
| `EMFILE` | Too many open files (system limit) |
| `ECONNREFUSED` | Connection refused by the remote server |
| `ECONNRESET` | Connection reset by the remote server |
| `ETIMEDOUT` | Connection timed out |
| `EADDRINUSE` | Address/port already in use (e.g. another server is on that port) |
| `EADDRNOTAVAIL` | Address not available |
| `EPIPE` | Broken pipe — writing to a connection that was closed |
| `EPERM` | Operation not permitted |

```javascript
const fs = require("fs");

try {
  fs.readFileSync("/does/not/exist.txt");
} catch (e) {
  console.log(e.code);    // "ENOENT"
  console.log(e.syscall);  // "open"
  console.log(e.path);     // "/does/not/exist.txt"
  console.log(e.message);  // "ENOENT: no such file or directory, open '/does/not/exist.txt'"
}
```

```javascript
const http = require("http");

const server = http.createServer((req, res) => res.end("hi"));

server.listen(3000);
server.on("error", (e) => {
  if (e.code === "EADDRINUSE") {
    console.log("Port 3000 is already in use");
  }
});
```

## Node-Specific Error Classes

### AssertionError

Thrown by the `assert` module when an assertion fails. Not a standard JS error.

```javascript
const assert = require("assert");

try {
  assert.strictEqual(1, 2);
} catch (e) {
  console.log(e.code);     // "ERR_ASSERTION"
  console.log(e.actual);   // 1
  console.log(e.expected);  // 2
  console.log(e.operator);  // "strictEqual"
}
```

### AbortError

Thrown when an operation is cancelled via an `AbortController`. Similar concept to the browser's AbortError but Node has its own implementation.

```javascript
const controller = new AbortController();
controller.abort();

try {
  await fetch("http://example.com", { signal: controller.signal });
} catch (e) {
  console.log(e.name); // "AbortError"
}
```

## Node Internal Error Codes (ERR_*)

Node has a large set of errors with codes prefixed by `ERR_`. These are thrown by Node's core modules. Some common ones:

| Code | When It's Thrown |
|------|-----------------|
| `ERR_INVALID_ARG_TYPE` | Wrong argument type passed to a Node API |
| `ERR_INVALID_ARG_VALUE` | Invalid argument value passed to a Node API |
| `ERR_MISSING_ARGS` | Required argument not provided to a Node API |
| `ERR_MODULE_NOT_FOUND` | An ES module could not be found |
| `ERR_REQUIRE_ESM` | Tried to `require()` an ES module |
| `ERR_PACKAGE_PATH_NOT_EXPORTED` | A package.json `exports` field doesn't expose the requested path |
| `ERR_HTTP_HEADERS_SENT` | Tried to set headers after they were already sent |
| `ERR_HTTP_INVALID_STATUS_CODE` | Invalid HTTP status code |
| `ERR_INVALID_URL` | An invalid URL was provided |
| `ERR_STREAM_DESTROYED` | Tried to write to a destroyed stream |
| `ERR_STREAM_PREMATURE_CLOSE` | A stream closed before it was expected to |
| `ERR_SOCKET_CLOSED` | Tried to use a socket that was already closed |
| `ERR_SERVER_NOT_RUNNING` | Tried to close a server that isn't running |
| `ERR_UNHANDLED_REJECTION` | A Promise rejected and nothing handled it |
| `ERR_WORKER_OUT_OF_MEMORY` | A Worker thread ran out of memory |

```javascript
// ERR_HTTP_HEADERS_SENT — very common Express mistake
app.get("/", (req, res) => {
  res.send("first response");
  res.send("second response"); // Error [ERR_HTTP_HEADERS_SENT]: Cannot set headers after they are sent
});
```

```javascript
// ERR_REQUIRE_ESM
try {
  require("some-esm-only-package");
} catch (e) {
  console.log(e.code); // "ERR_REQUIRE_ESM"
}
```

## Error-First Callbacks (Node Convention)

This isn't an error type, but it's a **Node-specific pattern** for handling errors. Many Node APIs use callbacks where the first argument is always the error (or `null` if no error).

```javascript
const fs = require("fs");

fs.readFile("/some/file.txt", "utf8", (err, data) => {
  if (err) {
    console.log(err.code); // "ENOENT", "EACCES", etc.
    return;
  }
  console.log(data);
});
```

This pattern predates Promises and async/await. You'll still see it in older Node code and some core APIs.

## Process-Level Error Events

Node emits error events on the `process` object that you can listen for. These are Node-specific — they don't exist in the browser.

```javascript
// Uncaught exception — an error was thrown and nothing caught it
process.on("uncaughtException", (err) => {
  console.log("Uncaught:", err.message);
  process.exit(1); // recommended to exit after this
});

// Unhandled promise rejection — a Promise rejected and nothing handled it
process.on("unhandledRejection", (reason, promise) => {
  console.log("Unhandled rejection:", reason);
});

// Warning — Node emitting a warning (e.g. too many event listeners)
process.on("warning", (warning) => {
  console.log(warning.name);    // e.g. "MaxListenersExceededWarning"
  console.log(warning.message);
});
```

---

## Key Takeaway

Standard JS errors (`TypeError`, `ReferenceError`, `SyntaxError`, `RangeError`, `URIError`, `EvalError`) come from the **language itself** and exist in every JS runtime.

Node errors come from **system calls and Node's core modules** — file system, networking, streams, HTTP, child processes, etc. They carry extra properties like `code`, `syscall`, `path`, and `port` that standard JS errors don't have.

You won't see `ENOENT`, `EADDRINUSE`, or `ERR_HTTP_HEADERS_SENT` in the browser because the browser doesn't give you direct access to the file system, raw TCP ports, or Node's HTTP module.
