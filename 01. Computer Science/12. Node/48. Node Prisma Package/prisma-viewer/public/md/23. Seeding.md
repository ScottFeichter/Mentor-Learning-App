# Seeding

## What Is Seeding?

Seeding is the process of populating your database with initial data. This is useful for development, testing, and setting up default records that your application needs to function.

## Setting Up a Seed Script

### 1. Create the Seed File

```javascript
// prisma/seed.js
const { PrismaClient } = require('@prisma/client');
const prisma = new PrismaClient();

async function main() {
  // Create users
  const john = await prisma.user.upsert({
    where: { email: 'john@example.com' },
    update: {},
    create: {
      name: 'John',
      email: 'john@example.com',
      hashedPassword: 'hashed_password_here'
    }
  });

  const jane = await prisma.user.upsert({
    where: { email: 'jane@example.com' },
    update: {},
    create: {
      name: 'Jane',
      email: 'jane@example.com',
      hashedPassword: 'hashed_password_here'
    }
  });

  // Create tasks for users
  await prisma.task.createMany({
    data: [
      { title: 'Learn Prisma', userId: john.id, priority: 'high' },
      { title: 'Build an API', userId: john.id, priority: 'medium' },
      { title: 'Write tests', userId: jane.id, priority: 'high' },
    ],
    skipDuplicates: true
  });

  console.log('Seed data created successfully');
}

main()
  .catch((e) => {
    console.error(e);
    process.exit(1);
  })
  .finally(async () => {
    await prisma.$disconnect();
  });
```

### 2. Configure package.json

```json
{
  "prisma": {
    "seed": "node prisma/seed.js"
  }
}
```

### 3. Run the Seed

```bash
npx prisma db seed
```

## When Seeding Runs Automatically

Seeding runs automatically when you use:

```bash
npx prisma migrate reset
```

This drops the database, reapplies all migrations, then runs the seed script.

## Using upsert for Idempotent Seeds

`upsert` ensures the seed can run multiple times without creating duplicates:

```javascript
const user = await prisma.user.upsert({
  where: { email: 'admin@example.com' },  // Check if exists
  update: {},                               // Do nothing if exists
  create: {                                 // Create if doesn't exist
    name: 'Admin',
    email: 'admin@example.com',
    role: 'admin'
  }
});
```

## Seed with Relations

```javascript
// Create user with tasks in one operation
const user = await prisma.user.create({
  data: {
    name: 'John',
    email: 'john@example.com',
    hashedPassword: 'hashed',
    tasks: {
      create: [
        { title: 'Task 1', priority: 'high' },
        { title: 'Task 2', priority: 'low' }
      ]
    }
  },
  include: { tasks: true }
});
```

## Seed with Faker (Realistic Test Data)

```javascript
const { faker } = require('@faker-js/faker');

async function main() {
  // Create 20 users with random data
  for (let i = 0; i < 20; i++) {
    await prisma.user.create({
      data: {
        name: faker.person.fullName(),
        email: faker.internet.email(),
        hashedPassword: 'hashed_placeholder',
        tasks: {
          create: Array.from({ length: faker.number.int({ min: 1, max: 5 }) }, () => ({
            title: faker.lorem.sentence(),
            priority: faker.helpers.arrayElement(['low', 'medium', 'high']),
            isCompleted: faker.datatype.boolean()
          }))
        }
      }
    });
  }
}
```

## Best Practices

- Use `upsert` to make seeds idempotent (safe to run multiple times)
- Keep seed data minimal and focused
- Use environment checks if seed data differs between dev/staging
- Don't seed production databases with test data
- Commit your seed file to version control
