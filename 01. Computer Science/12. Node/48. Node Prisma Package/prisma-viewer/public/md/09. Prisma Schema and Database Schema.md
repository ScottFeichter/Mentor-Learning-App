# Prisma Schema and Database Schema

## The Relationship

The Prisma schema describes the database schema. There are two cases to consider:

## Case 1: Introspection

There is an existing database schema. For the Prisma client to be able to operate on the database, a Prisma schema must be created to match.

Prisma provides a means to read the database schema and to create a Prisma schema from it. All of the existing data is preserved.

```bash
npx prisma db pull
```

### Benefits of Introspection

- **No Data Loss** - your existing data remains intact
- **Accurate Mapping** - automatically detects table structures
- **Time Saving** - no need to manually write the schema
- **Error Prevention** - eliminates manual mapping mistakes

### Downsides of Introspection

- **Schema Management is in SQL** - changes must be made directly in the database
- **Schema Evolution is difficult for a team project** - no version-controlled migration history
- **Schema Management is difficult in production** - harder to track and deploy changes

## Case 2: Migration

If there is no existing database schema, Prisma schema definitions can be created by hand. Then, those schema definitions are used to create tables with corresponding columns, constraints, and indexes. This process is called migration. If there is existing data, it can be preserved.

```bash
npx prisma migrate dev --name init
```

## Modifying the Schema

Once the Prisma and database schemas have been created by one of the processes above, it may be necessary to modify the schema — perhaps to add tables or to add or remove columns from tables.

The process:

1. Change the Prisma schema file
2. Run migration again: `npx prisma migrate dev --name description_of_change`
3. Prisma generates SQL and applies it to the database

**Every change to the Prisma schema requires that you run migration again.**

## Team Collaboration

As the Prisma schema is just a file, it can be:

- Shared within a development team via GitHub
- Propagated from GitHub to the production deployment
- Version-controlled alongside your application code
