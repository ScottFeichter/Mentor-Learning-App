# Web Architecture

A common pattern in communication scenarios - here we are focusing on the web.

## Clients and Servers

### The Request / Response Cycle

- Connection to the web allows a world of information available to us.

- It is much more and varied information than any one computer could store locally.

- To facilitate access is a system of client requests and server responses.

### The Protocol

- Communication over the internet occurs via Hyper Text Transfer Protocol.

- You don't invoke functions in your code to gather the information locally.

- Instead you send an HTTP request to a server and get a response back.

- The server is responsible for calling the necessary functions to gather requested data.

## What Makes It An API?

It's still just an interface to call pre-written code.

The difference is the code lives on a <span class="subheading-highlight">remote server</span>, not in your local project.

### How It Works

- You send an <span class="olive-bold">HTTP request</span> to a URL
- The server runs some code
- The server sends back an <span class="olive-bold">HTTP response</span> <span class="muted">(usually JSON)</span>

### Example

```javascript
fetch('https://api.github.com/users/octocat')
```

#### In This Example:

- The URL is the interface — the shared boundary
- The response is the output
- ```fetch()``` is a browser function that sends the request


#### About fetch()

```fetch()``` is an API, but NOT a **Web API**

- Is a Browser API — a function the browser provides to your JavaScript code.
- It runs <span class="olive-bold">locally</span> in your browser, not on a remote server.
- You call it like any other local function — no HTTP request is needed to access it.
- It performs many tasks so you don't have to.
    - Opens a TCP/IP connection to the server
    - Performs the TLS/SSL handshake for HTTPS
    - Formats the raw HTTP request message (method, headers, body, protocol version)
    - Sends the request bytes over the network
    - Listens for and receives the raw response bytes
    - Parses the HTTP response (status line, headers, body)
    - Handles redirects automatically
    - Manages the connection lifecycle (keep-alive, closing)
    - Returns a Promise so you don't have to deal with callbacks at the network level

It is the tool you use to call a Web API, not a Web API itself.
