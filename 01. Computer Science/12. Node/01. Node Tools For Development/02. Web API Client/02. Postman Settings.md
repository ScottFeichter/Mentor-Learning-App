# Postman Settings

&nbsp;

These settings are recommended to optimize your workflow in **Postman**.

## General Settings

<div class="indent">

### Theme

Set the theme to Dark or Light based on your preference.

Dark theme reduces eye strain during long development sessions.

### Default Protocol On Send

Set this to `HTTPS` so requests default to secure connections.

This avoids accidentally sending sensitive data over plain HTTP.

### Request Timeout

Set a timeout value in milliseconds to prevent requests from hanging indefinitely.

A value of `30000` (30 seconds) is a reasonable default for most APIs.

### Automatically Follow Redirects

Keep this enabled so **Postman** follows `3xx` redirect responses automatically.

Disable it only when you need to inspect the redirect response itself.

### Send No-Cache Header

Keep this enabled to ensure you always receive a fresh response from the server.

This prevents stale cached responses from masking bugs.

</div>

## Editor Settings

<div class="indent">

### Font Size

Increase the editor font size if you find the default hard to read.

### Auto-Close Brackets

Keep this enabled to speed up writing JSON request bodies.

### Trim Keys And Values

Enable this to automatically strip whitespace from header keys and values.

Accidental whitespace in headers is a common source of hard-to-find bugs.

</div>

## Data Settings

<div class="indent">

### Working Directory

Set a working directory so **Postman** knows where to look for files used in requests.

This is important when sending file uploads or using data files in collection runs.

### Save Cookies

Keep this enabled so **Postman** persists cookies between requests in a session.

This is essential for testing authenticated flows that rely on session cookies.

</div>

## Privacy Settings

<div class="indent">

### Usage Data

Disable sending anonymous usage data to **Postman**.

This is found under Settings → Privacy.

</div>

## Proxy Settings

<div class="indent">

### Use System Proxy

Enable this if your network requires a proxy to reach external APIs.

This tells **Postman** to use the same proxy configuration as your operating system.

### Proxy For HTTPS

To inspect HTTPS traffic through a proxy tool like Charles or Fiddler.

You need to configure the proxy host and port here.

</div>

## Certificates

<div class="indent">

### SSL Certificate Verification

This is enabled by default and should stay enabled in production testing.

Disable it temporarily only when testing against a local server with a self-signed certificate.

### Client Certificates

Add client certificates here when an API requires mutual TLS authentication.

Map each certificate to the specific host it applies to.

</div>
