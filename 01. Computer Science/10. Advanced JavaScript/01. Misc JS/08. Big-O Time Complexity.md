# Big-O and Time Complexity

## What is Big-O?

Determines the rate of growth through complexity analysis. The "O" stands for "order" — it describes the growth curve.

## Complexity Classes

- **O(1)** — Constant
- **O(n)** — Linear
- **O(n²)** — Quadratic
- **O(n³)** — Cubic (polynomial)

## Rules

- Constants **do not** matter
- Smaller terms **do not** matter
- Always answer: **what is n?**

## Large n's

Big-O is only concerned with very large values. If n is small, efficiency is usually a non-factor. As n grows, inefficiencies are magnified. The steeper the curve, the faster performance degrades.

## Ignoring Coefficients

Using y = mx + b as an analogy:
- We ignore m and b
- All constant coefficients are treated as 1
- Only the dominant term matters

For quadratic: y = ax² + bx + c → simplifies to O(n²)

## Growth Types

**Constant growth** — O(1)
- Runtime is constant regardless of input size
- Most arithmetic and logic operations

**Linear growth** — O(n)
- Operations increase proportionally with n
- Generally a for-loop iterating through n elements

**Quadratic growth** — O(n²)
- A function does n things n times
- A loop calling a helper function
- Nested loops (exponent increases with each nest)

**Cubic growth** — O(n³)
- Three nested loops running n times (polynomial)

## Loop Analysis

- **Nested loops** — often quadratic; exponent increases with each nest
- **Constant loops** — doesn't matter what n is
- **Adjacent loops** — each may or may not depend on n, but they're independent of each other

## Best, Worst, Average Case

- **Big-Ω (Omega)** — best case
- **Big-Θ (Theta)** — average case
- **Big-O** — worst case

Example (searching):
- Best case: element at index 0
- Worst case: element not in array
- Average case: element at median index
