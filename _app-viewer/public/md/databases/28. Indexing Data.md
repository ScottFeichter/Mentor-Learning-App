# Indexing Data

## What Is an Index?

An index is a separate data structure that the database maintains alongside your data to speed up lookups. Think of it like the index in the back of a textbook - instead of reading every page to find a topic, you look it up in the index and go directly to the right page.

## Without an Index

The database performs a **full table scan** - it checks every single row to find what you're looking for:

```
Query: Find user with email "john@example.com"

Row 1: "sarah@example.com" - no
Row 2: "mike@example.com" - no
Row 3: "john@example.com" - found!
...still checks remaining rows
```

With millions of rows, this is slow.

## With an Index

The database uses the index to jump directly to the matching row(s):

```
Index on email:
"john@example.com" → Row 3  ← goes here directly
```

## Why Index (Pros)

- **Faster reads** - queries that search, filter, or sort on indexed columns are significantly faster
- **Efficient sorting** - data is already organized in the index
- **Faster joins** - joining tables on indexed columns is much quicker
- **Unique constraints** - unique indexes enforce data integrity (no duplicate emails, etc.)

## Why NOT Index (Cons)

- **Slower writes** - every INSERT, UPDATE, or DELETE must also update the index
- **Storage cost** - indexes take up additional disk space
- **Maintenance overhead** - the database must keep indexes in sync with the data
- **Diminishing returns** - indexing a column with few unique values (like a boolean) provides little benefit
- **Over-indexing** - too many indexes on a table can make writes significantly slower

## When to Index

- Columns frequently used in WHERE clauses
- Columns used in JOIN conditions
- Columns used in ORDER BY or GROUP BY
- Columns with high cardinality (many unique values)

## When NOT to Index

- Small tables (full scan is fast enough)
- Columns rarely used in queries
- Columns with low cardinality (few unique values like true/false)
- Tables with heavy write operations and few reads
- Columns that are frequently updated

## Example

```sql
-- Create an index on the email column
CREATE INDEX idx_users_email ON users(email);

-- This query now uses the index instead of scanning every row
SELECT * FROM users WHERE email = 'john@example.com';
```

## Key Takeaway

Indexing is a **trade-off**: you sacrifice write speed and storage space to gain read speed. Index strategically based on how your data is actually queried.
